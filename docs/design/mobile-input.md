# 모바일 입력 UX 원칙

- 결정일: 2026-11-21
- 티켓: [모바일 입력 UX 원칙: 금액 입력·최근 항목·바텀시트·종목 검색](https://github.com/Gn0lee/oat/issues/529)

- 전제: ADR 0010(Expo, 직접 그린 키패드), ADR 0011(얇은 클라이언트), [통계 화면 구성](stats-screens.md)(하단 탭 4개, 숫자 색·크기), [브랜드](brand.md)(Pine, 다크 모드)
- PoC·조사: [모바일 입력 UX PoC](../research/2026-11-21-mobile-input-poc.md), [모바일 입력 UX 사례 조사](../research/2026-11-21-mobile-input-cases.md), [금액 입력과 RN 입력 손맛](../research/2026-11-15-amount-input-and-rn-input-feel.md)

원칙과 흐름을 정한다. 최종 시안(크기·간격·색·문구 다듬기)은 디자인 스펙에서 한다.

## 0. 한 장 요약

| 항목 | 결정 |
|---|---|
| 추가 버튼 | 홈·기록 탭 오른쪽 아래 떠 있는 `+`. 분석·자산 탭에는 없다. 탭 바 가운데 `+`는 만들지 않는다 |
| 입력 구조 | **퍼널**: 무엇을(장부·종류) → 얼마 → 모르는 칸만 → 확인. 한 화면에 질문 하나 |
| 장부 | 퍼널 첫 단계에서 고르고, 그 뒤 저절로 바뀌지 않는다 (ADR 0027) |
| 금액 키패드 | `00`, 만 단위 힌트, 외화면 `.`, 길게 눌러 붙여넣기, `⌫` 길게 전체 지우기, 햅틱. 빠른 금액 버튼·계산기 없음 |
| 최근 항목 | 그 장부의 최근 가맹점을 고르면 카테고리·결제수단까지 채우고 확인으로. 결제수단은 추측하지 않고 묻는다 |
| 줄 나누기 | 처음 고른 카테고리 줄이 차액을 맞춘다. 직접 친 금액은 바꾸지 않는다 |
| 매매 | 투자 화면에서 시작. 계좌 → 종목 → 수량 → 단가 → 확인. 종목 검색은 서버 메모리, 초성·한글 미국명 |
| 통계 귀속 | 기록 상세 맨 아래 "통계" 묶음(고정비·쓴 사람·통계에서 빼기). 입력에서는 접힌 "더 보기" |
| 시트·키보드 | 퍼널은 화면 이동, 시트는 한 칸 고칠 때만, 시트는 한 겹. 키패드와 키보드는 한 번에 하나 |
| 저장 실패 | 새 기록만 폰 대기열에 넣고 자동으로 다시 보낸다("보내는 중"). 수정·삭제는 온라인에서만 (ADR 0028) |
| 접근성 | 출시 조건으로 App Store 접근성 라벨 4개: VoiceOver·더 큰 텍스트·다크 인터페이스·색에만 의존하지 않음 |
| 콜드 스타트 | iPhone SE 2세대 Release 빌드에서 홈 숫자 보임·빠른 동작 키패드 p75 1.5초 이하, 첫 프레임 400ms대 |

## 1. 입력 진입

- **떠 있는 `+` 버튼**을 홈과 기록 탭의 오른쪽 아래(탭 바 위)에 둔다. 앱을 열면 홈이 먼저 뜨므로 한 번 탭으로 입력을 시작한다.
  - 분석·자산 탭에는 두지 않는다. 자산 탭에는 "지갑 추가"가 따로 있어서 `+`가 둘이면 헷갈린다.
  - 탭 바 가운데 `+`는 만들지 않는다. Apple HIG가 "탭 바는 이동용이지 동작용이 아니다"라고 하고, expo-router 네이티브 탭에는 탭을 버튼처럼 쓰는 기능이 없다.
- 입력은 아래에서 올라오는 **모달**이다. 닫으면 보던 탭으로 돌아간다.
- **앱 아이콘 빠른 동작**: 길게 누르면 `공용 지출`·`내 지출`. 퍼널 1단계를 건너뛰고 금액 단계로 바로 연다. 쓸 수 있는 장부 이름으로 만든다.
- 다른 입구: 매매는 투자 화면(7절), 돌려받은 돈은 원 기록 상세(2.2), 예정 확정은 홈 "확인할 것"(2.2).

## 2. 입력 퍼널

토스 제품 원칙 "One Thing"(한 화면에서 판단 하나)을 따른다. 송금과 달리 가계부는 하루 여러 번 같은 모양으로 적으므로, **답을 아는 단계는 건너뛰어** 탭 수를 줄인다.

### 2.1 지출

1. **무엇을 기록?** — `+`를 누르면 그 자리에 뜨는 메뉴: `🏠 공용 지출` · `🔒 내 지출` · `수입` · `이체`. 장부가 셋 이상이면 지출 항목은 장부마다 하나씩 보이고, 많으면 `다른 장부…`로 접는다.
2. **얼마?** — 키패드만 있는 화면(3절). 위에 "공용 지출"처럼 고른 것을 표시만 한다. 바꾸려면 뒤로 간다. 금액만 `다음` 버튼이 있다.
3. **모르는 칸만** — 차례로 가맹점 → 카테고리 → 결제수단. 값을 아는 단계는 건너뛴다(5절).
4. **확인** — 모든 칸(장부, 금액, 가맹점, 카테고리, 결제수단, 날짜, 메모)과 접힌 `더 보기`(8절). 칸을 누르면 그 칸만 시트로 열고 다시 확인으로 돌아온다. 버튼은 `저장`과 `저장하고 하나 더`.

- 고르는 단계는 고르는 순간 다음으로 넘어간다(`다음` 버튼 없음).
- 뒤로 가기를 해도 앞에서 넣은 값은 남는다.
- 날짜 기본값은 오늘·지금 시각이고 확인 화면에서 고친다. 해외 카드 이용은 현지 날짜 규칙(ADR 0014)이다.
- 저장하면 화면이 닫히고 "저장했어요 · 되돌리기" 토스트가 뜬다. 되돌리기는 방금 만든 기록을 지운다(온라인일 때. 보내는 중이면 대기열에서 뺀다).
- `저장하고 하나 더`는 퍼널을 금액 단계부터 다시 열고 장부·날짜·결제수단을 이어받는다.
- 구현 후보: 토스 `use-funnel`(React Navigation 지원 여부는 구현 때 확인). 단계 정의와 건너뛰기 조건을 선언적으로 두는 구조면 된다.

### 2.2 다른 종류

| 종류 | 퍼널 |
|---|---|
| 수입 | 어느 장부?(쓸 수 있는 장부가 하나면 건너뜀) → 금액 → 보낸 곳(가맹점 단계) → 카테고리 → 받은 지갑 → 확인 |
| 이체 | 어느 장부? → 금액 → 보내는 지갑 → 받는 지갑 → 확인. 카드대금도 이체다(받는 지갑 = 신용카드 지갑) |
| 매매 | 7절 |
| 돌려받은 돈 | 원 기록 상세의 `돌려받은 돈 기록` → 종류(환불·혜택·정산) → 금액 → 받은 지갑 → 확인. 원 기록·장부는 정해져 있다(같은 장부 규칙). 카테고리가 여럿이면 기본 배분(ADR 0007)을 확인 화면에서 고친다 |
| 예정 확정 | 홈 "확인할 것"·곧 나갈 돈에서 `확정` 한 번 탭. 금액이 다르면 `고쳐서 확정` → 확인 화면 |

## 3. 금액 키패드

| 기능 | 결정 | 이유 |
|---|---|---|
| `00` 키 | 넣는다 | 0이 많은 금액을 빨리 친다 |
| 만 단위 힌트 | 금액 아래 "125만원", "1만 2천원" | 0 개수를 잘못 세는 실수를 막는다 |
| 외화 | 통화가 USD 등이면 `00` 자리가 `.`. 아래에 기준환율 원화 환산을 작게 | 해외 결제·미국 주식 |
| 붙여넣기 | 금액을 길게 누르면 `붙여넣기` 메뉴. 숫자만 골라 넣는다 | iOS는 코드가 클립보드를 읽으면 허락 알림이 떠서, 사용자가 고를 때만 읽는다 |
| `⌫` 길게 누르기 | 전체 지우기 | |
| 햅틱 | 키마다 약한 선택 햅틱, 시스템 설정을 따름 | |
| 빠른 금액(+1만·+5만) | **넣지 않는다** | 가계부 금액은 12,800원처럼 딱 떨어지지 않는다 |
| 계산기(+ − × ÷) | **넣지 않는다** | 나누기는 줄(6절), 더치페이는 정산이 맡는다. 필요하면 나중에 더한다 |

- 금액 표시는 `TextInput`이 아니라 `Text`이고, 키는 `onPressIn`에서 처리한다(앱 스택 PoC 구성).
- 0원으로는 `다음`이 열리지 않는다(다리 금액 ≠ 0). 줄의 0원(무료 품목)은 6절.
- 큰 금액 표시의 넘침은 11.2.

## 4. 장부

장부(공용/개인)는 "우리 돈인가, 내 돈인가"라는 판단이라 결제수단·가맹점에서 맞히지 않는다. 내 카드로 장을 보면 공용이다. 그래서 퍼널 첫 단계에서 사람이 고른다(ADR 0027).

- 지출은 첫 메뉴에서 장부와 종류를 한 번에 고르므로 탭이 늘지 않는다.
- 고른 뒤에는 **저절로 바뀌지 않는다.** 가맹점·결제수단을 골라도 그대로다. 바꾸려면 퍼널 앞으로 가거나 확인 화면의 장부 칸을 누른다.
- 개인 장부는 자물쇠 표시와 다른 색으로 확인 화면 맨 위(금액 옆)에서 바로 구분된다. 색 값은 디자인 스펙에서 정한다.
- 장부를 바꾸면 그 장부에서 못 쓰는 카테고리(장부 전용 카테고리)는 비우고 다시 묻는다.
- 기록 탭에서 특정 장부를 걸러 보던 중에 `+`를 누르면 메뉴의 그 장부 항목을 맨 위에 둔다(그래도 고르는 건 사람).
- 결제수단·지갑에 기본 장부 칸을 더하는 안은 택하지 않았다. 몰래 바뀌는 장부가 개인 지출을 공용으로 새게 한다.

## 5. 최근 항목

- **③-1 가맹점 "어디서 썼어요?"**: 그 장부의 최근 가맹점 목록(자주 + 최근 순), 검색칸, `건너뛰기`. 키보드는 검색칸을 누를 때만 올라온다.
  - **최근 가맹점을 고르면** 그 장부에서 그 가맹점으로 마지막에 적은 기록의 카테고리·결제수단을 채우고 바로 확인으로 간다. 단골 지출은 `+` → 공용 지출 → 금액 → 다음 → 가맹점 → 저장, 탭 다섯 번이다.
  - 가맹점 이름은 공백·대소문자를 무시하고 같은 것으로 본다.
- **③-2 카테고리, ③-3 결제수단**: 가맹점을 건너뛰었거나 처음 보는 가맹점일 때만 나온다. 결제수단은 추측해서 건너뛰지 않는다(틀린 카드는 청구서까지 틀리게 한다). 내가 최근에 쓴 것을 맨 앞에 둔다.
- **기록 복제**: 기록 상세의 `다시 기록` → 날짜만 오늘로 바꿔 퍼널을 금액 단계부터 연다.
- **지키는 선**
  - 제안은 **고른 장부의 기록에서만** 만든다. 개인 장부의 가맹점이 공용 입력에 뜨지 않는다.
  - 결제수단은 **내가 쓸 수 있는 것만** 제안한다(내 결제수단, 함께 쓰는 지갑). 배우자가 공용 장부에 적은 배우자 카드는 제안하지 않는다.
  - 위치 기반 제안은 넣지 않는다. 위치 권한을 달라고 할 이유가 약하다.
  - 제안은 따로 저장하지 않고 서버가 기록에서 계산해 내려준다(얇은 클라이언트).

## 6. 줄 나누기

- 확인 화면의 카테고리 칸 옆 `나누기`에서 들어간다. 퍼널 단계에는 넣지 않는다.
- 줄은 **나란하다**. 처음 고른 카테고리 줄 안에 다른 줄이 들어가는 게 아니다. 세 줄을 같은 들여쓰기·같은 모양으로 그리고, 합계는 맨 위에 따로 둔다.
- **규칙: 직접 친 금액은 그대로, 안 친 줄이 맞춘다.**
  - 처음 고른 카테고리 줄은 아직 직접 친 적이 없어서 결제 금액 전체를 들고 있다. `+ 줄 추가`로 다른 줄 금액(같은 키패드)과 카테고리를 넣으면 그만큼 이 줄에서 빠진다. 합이 늘 맞는다.
  - 이 줄은 금액이 회색이다(자동으로 맞춰지는 중). 꼬리표("나머지")는 붙이지 않고, 회색 줄이 있을 때만 "떼어낸 만큼 장보기에서 빠져요"처럼 카테고리 이름을 넣은 안내 한 줄을 둔다.
  - 모든 줄을 고칠 수 있다. 회색 줄을 직접 고치면 맞춰 줄 줄이 없으므로, 합이 안 맞을 때 "3,000원이 남았어요 [간식에 더하기]"를 보여주고 합이 맞을 때까지 `완료`를 막는다. 버튼은 마지막으로 고친 줄이 아닌 줄을 제안한다.
  - 직접 친 금액은 앱이 바꾸지 않는다.
  - 다른 줄 합이 결제 금액을 넘으면 `완료`를 막고 "나눈 금액이 합계보다 3,000원 많아요"라고 쓴다.
  - 회색 줄이 0원이 되면 저장할 때 지운다. 직접 친 0원 줄(무료 품목)은 남긴다.
- 품목 이름·정가는 줄을 눌러 펼치는 선택 칸이다. 결제 할인은 정가와 줄 금액의 차이로 안다(ADR 0007). 영수증 품목을 하나하나 넣는 건 AI 연결의 몫으로 둔다.

## 7. 매매와 종목 검색

- **입구**: `+` 메뉴에 넣지 않는다. 투자 화면 `매매 기록` → 사기/팔기, 종목 상세 `더 사기`·`팔기`(계좌·종목을 건너뛰고 수량부터).
- **퍼널**
  1. **어느 계좌?** 증권 계좌가 하나면 건너뛴다. 장부는 계좌가 정해서 묻지 않는다(ADR 0009).
  2. **어떤 종목?** 보유 종목이 맨 위, 팔기면 그 계좌의 보유 종목만. 이름·코드·초성(`ㅅㅅㅈㅈ`)·한글 미국명(`애플`)·영문명으로 찾는다. 폐지(`listed = false`) 종목은 숨기고, 보유 중이면 보인다([시세 데이터 공급원](market-data.md) 7절).
  3. **몇 주?** 미국 종목만 소수점 키. 팔기는 `전부 12주` 칩. 가진 수량보다 많이 팔면 막는다.
  4. **얼마에?** 1주 단가. `11/20 종가 71,200` 칩(보유 종목은 최근 현재가, 아니면 마스터의 전일 종가 `base_price`)을 누르면 채우지만 **자동으로 넣지 않는다**(실제 체결가와 다르다). `총액으로 입력`으로 바꾸면 총액 ÷ 수량으로 단가를 계산한다(반올림은 물리 DB 스키마 4.2).
  5. **확인**: 체결일, 금액, 매매 비용(규칙·요율 추정, "추정" 표시, 고칠 수 있음), USD면 기준환율(증권사 환율로 고칠 수 있음), 메모.
- **체결일 기본값**: 국내는 오늘(한국), **미국은 지금의 미 동부 날짜**다. 한국 아침에 어젯밤 매수를 적으면 미국 날짜(어제)가 된다(ADR 0014).
- **검색 방식**: API 메모리의 마스터 사본을 전부 훑는다. 1.7만 종목에 평균 1ms, p99 1.7ms라 색인이 필요 없다([PoC](../research/2026-11-21-mobile-input-poc.md)). 앱은 글자마다 약 150ms 늦춰 서버에 묻는다. 순서는 코드 일치 > 코드 앞부분 > 이름·초성 앞부분 > 영문명 앞부분 > 포함, 보유 종목이 먼저, 같으면 짧은 이름 먼저.

## 8. 기록 상세의 "통계" 묶음

통계 질문 목록이 넘긴 "고정비"·"쓴 사람" 토글의 자리다.

```
통계
 고정비            [켬]
 쓴 사람         민지 ▾     ← 공용 장부 기록만
 통계에서 빼기      [끔]
```

- 기록 상세 맨 아래에 둔다. 가끔 고치는 값이다.
- 쓴 사람은 공용 장부 기록에만 보인다(쓴 사람 통계가 공용 장부만 센다). 고를 수 있는 값은 가구원들과 "함께"다.
- 자동값을 고치면 옆에 "직접 바꿈"을 붙이고 `자동으로 되돌리기`를 둔다(쓴 사람은 `spender_member_id`를 비움, 고정비는 저장 때 규칙으로 다시 계산한 값).
- 입력 퍼널은 이 값들을 묻지 않는다. 확인 화면의 접힌 `더 보기`에 같은 세 칸이 있다.

## 9. 바텀시트·키보드

- **화면 단위**: 퍼널 단계는 입력 모달 안의 화면 이동(push)이다. 시트는 확인 화면에서 한 칸을 고칠 때(카테고리·결제수단·날짜·금액 키패드)와, 다른 화면의 고르기(장부 필터 등)에만 쓴다.
- **시트는 한 겹**이다. 시트 위에 시트를 올리지 않고, 더 들어가야 하면 시트 안에서 화면을 넘긴다.
- **높이**: 짧은 목록은 내용만큼, 검색이 있는 긴 목록(카테고리·가맹점·종목)은 처음부터 크게 열고 검색칸을 맨 위에 둔다.
- **닫기**: 시트를 끌어 닫으면 취소다. 고르는 순간 반영하고 닫힌다. 입력 모달 전체를 끌어 닫을 때 입력한 게 있으면 "작성 중인 기록을 버릴까요?"를 묻는다.
- **키패드와 키보드는 한 번에 하나**다. 메모·검색칸을 누르면 키패드가 내려가고 시스템 키보드가 올라온다. 저장·다음 버튼은 키보드 바로 위에 붙어 가려지지 않는다(react-native-keyboard-controller).
- **라이브러리**: 시트는 react-native-true-sheet(iOS 순정 시트라 다크 모드·iOS 26 유리 효과·키보드 비켜 주기가 기본). 문제가 생기면 @gorhom/bottom-sheet. 앱 스택 PoC에서 둘의 손맛 차이는 없었다. 메모 입력칸(RN `TextInput` / `@expo/ui`)은 둘 다 한글 조합을 통과해서 구현 때 고른다.

## 10. 저장 실패와 "보내는 중"

서버는 집의 미니 PC라 잠깐 멈출 수 있고, 지하 매장처럼 신호가 약한 곳에서 적는 일이 흔하다. 쓰기마다 중복 방지 키를 붙이므로(서버 아키텍처 11번) 같은 요청을 다시 보내도 기록은 한 번만 생긴다(ADR 0028).

- **새 기록만 폰 대기열에 넣는다.** 저장을 누르면 화면은 바로 닫히고, 보내지 못했으면 토스트가 "연결되면 보낼게요"로 바뀐다. 연결되면 자동으로 보내고, 앱을 껐다 켜도 이어간다.
- 기록 탭 맨 위에 `보내는 중 N건` 줄이 생긴다. 그 기록은 목록에 "보내는 중" 표시를 달고 보인다(흐리게 하지 않는다).
- 홈 숫자·잔액은 서버가 받은 뒤에 반영된다(계산은 서버 몫). 그 사이 홈 맨 위 숫자 아래에 "보내는 중 N건 빠짐"을 붙인다.
- 서버가 거절하면(그사이 지갑이 보관됨, 검증 실패) `보내지 못한 기록`으로 옮긴다. 눌러서 고쳐 다시 보내거나 버린다.
- **수정·삭제는 온라인에서만** 된다. 버전 충돌(둘이 같은 기록을 고침)을 폰에서 풀 수 없다.
- 세션이 끝났으면(60일 미사용 등) 다시 로그인한 뒤 같은 사람의 대기열만 보낸다. 로그아웃하면 대기열을 지울지 묻는다.
- 구현: TanStack Query의 멈춘 쓰기 이어하기(`setMutationDefaults` + persist + `resumePausedMutations`). 중복 방지 키는 초안을 만들 때 정해 대기열에 함께 저장한다.

## 11. 접근성

출시 조건으로 App Store 접근성 라벨 **VoiceOver · 더 큰 텍스트 · 다크 인터페이스 · 색에만 의존하지 않음**을 표시할 수 있게 만든다. 라벨은 로그인·온보딩·입력·조회·설정의 공통 작업을 그 기능만으로 끝낼 수 있어야 붙일 수 있다.

### 11.1 VoiceOver

- **키패드**: 키마다 "키보드 키" 역할(`accessibilityRole="keyboardkey"`)과 이름("영영", "지우기"). 누를 때마다 금액을 한국어 단위로 읽는다("1만 2천 원", 순서 대기 알림). 금액 표시 자체도 같은 문장을 값으로 갖는다.
- **퍼널**: 다음 단계로 넘어가면 포커스를 그 화면의 질문("얼마 썼어요?")으로 옮긴다.
- **줄 나누기**: 회색 줄은 "자동 계산" 상태를 함께 읽는다.
- **홈 편집**: 끌기 손잡이와 함께 커스텀 액션 `위로 이동`·`아래로 이동`·`숨기기`(App Store 기준: 끌어 옮기기는 다른 방법도 줘야 한다).
- **차트**: 한 문장 요약을 읽는다("평소 이맘때보다 12만 원 덜"). 차트를 소리로 훑는 기능은 넣지 않는다.
- 색으로만 알리지 않는다(통계 화면 구성 9절의 부호 필수, 개인 장부의 자물쇠).

### 11.2 Dynamic Type

- **맨 위 큰 숫자**(홈 숫자, 입력 금액, 자산 탭 묶음 합계): 글자 크기를 따라 커지되 **늘 한 줄**이다. 넘치면 폭에 맞게 줄인다(`adjustsFontSizeToFit`, 최소 배율은 디자인 스펙). "1,284만"처럼 줄여 쓰지 않는다(금액이 바뀐다).
- **키패드 글자**: 상한을 둔다(`maxFontSizeMultiplier`). 키 크기가 고정이고 이미 크다.
- **목록 줄**(이름 ··· 금액): 접근성 크기(AX1~)에서는 금액을 이름 아래로 내린다.
- 금액은 13pt 이상이다(통계 화면 구성 9절). 라벨 기준인 200%까지 잘리지 않는지 실기기로 확인한다.

### 11.3 홈 편집

- 홈 맨 아래 `홈 편집` → 목록 화면. 맨 위 숫자 고르기가 맨 위에 따로 있고, 아래 카드 줄마다 켜기/끄기 스위치와 오른쪽 끌기 손잡이가 있다. 손잡이는 길게 누르지 않아도 바로 끌린다.
- 저장은 `household_members.home_layout`(통계 화면 구성 4절)이다.

## 12. 콜드 스타트

| 지점 | 목표(iPhone SE 2세대, Release 빌드) |
|---|---|
| 첫 프레임(스플래시 다음 첫 화면) | 400ms대. Apple WWDC19 기준. 재서 기록한다 |
| 홈 숫자 보임 | **p75 1.5초 이하** |
| 빠른 동작 → 키패드 누를 수 있음 | **1.5초 이하** |

- 기준 기기를 가장 느린 테스트 폰으로 잡는다. Expo가 제시한 콜드 1.5초와 같다(Shopify는 p75 2초).
- **마지막으로 본 홈 숫자를 폰에 두고 먼저 보여준다.** 네트워크를 기다리지 않는다. 새 숫자가 오면 바꾸고, 오래된 값이면 "11/21 14:20 기준"을 붙인다. 폰의 금융 데이터라 iOS 데이터 보호(잠금 해제 전 읽기 불가)를 쓰고, 로그아웃·계정 삭제 때 지운다.
- 분석·자산 탭 화면과 차트는 처음 누를 때 불러온다.
- 측정: 개발 중 Xcode Instruments(App Launch), 출시 뒤 Xcode Organizer·MetricKit의 실제 사용자 p75. 목표를 넘으면 출시를 막는다.

## 13. 나중에 정할 것: 여러 건 한 번에

여러 건을 몰아 적는 일(장본 영수증 여러 장, 밀린 기록)이 종종 있다. 지금은 지침만 둔다.

- `저장하고 하나 더`가 장부·날짜·결제수단을 이어받아 반복 입력의 탭을 줄인다(2.1).
- 영수증·카드 문자 묶음은 AI 연결(MCP)이 맡는 것이 기본이다. 앱은 "AI가 바꾼 기록"에서 확인·되돌리기를 한다.
- 일괄 입력 화면(표 모양, 여러 줄 한 번에 저장)은 실제로 몰아 적는 상황을 모은 뒤 따로 검토한다. 만들게 되면 각 건이 같은 퍼널 기본값 규칙(장부는 사람이 고름, 결제수단은 추측하지 않음)을 지키고, 건마다 중복 방지 키를 가진다.

## 14. 다른 티켓에 넘기는 것

- **디자인 스펙(디자인 그릴링)**: 퍼널 각 화면·확인 화면·나누기 화면의 최종 시안, 떠 있는 `+`의 크기와 탭 바와의 간격, 개인 장부 색과 자물쇠, 회색 자동 줄, 작은 폰(SE)에서 확인 화면 배치, 큰 숫자 최소 배율, 빈 상태 문구.
- **알림**: 예정·청구서 알림을 누르면 확인 화면(예정 확정)으로 바로 연다. `보내지 못한 기록`이 생기면 로컬 알림을 보낼지 정한다.
- **구현**: 가맹점 제안·종목 검색 엔드포인트(얇은 클라이언트 원칙대로 서버 계산), `use-funnel`의 React Navigation 지원 확인, true-sheet 채택, 빠른 동작(expo-quick-actions 류), 콜드 스타트 측정 자동화.
- **정식 출시 준비**: App Store 접근성 라벨 4개 표시와 그 전 점검(로그인·온보딩 포함 VoiceOver 완주, 200% 글자), 콜드 스타트 목표 확인을 출시 조건 목록에 넣는다.
