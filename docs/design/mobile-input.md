# 모바일 입력 UX 원칙

- 결정일: 2026-11-21
- 티켓: [모바일 입력 UX 원칙: 금액 입력·최근 항목·바텀시트·종목 검색](https://github.com/Gn0lee/oat/issues/529)
- 관련 ADR: 0027(기록 입력은 퍼널이고 장부는 첫 단계에서 고른다), 0028(보내지 못한 새 기록은 폰 대기열에서 자동으로 다시 보낸다), 0017(쓴 사람 "함께" 칸 추가), 0014(미국 체결일 기본값)
- 전제: ADR 0010(Expo, 직접 그린 키패드), ADR 0011(얇은 클라이언트), [통계 화면 구성](stats-screens.md)(하단 탭 4개, 숫자 색·크기), [브랜드](brand.md)(Pine, 다크 모드)
- PoC·조사: [모바일 입력 UX PoC](../research/2026-11-21-mobile-input-poc.md), [모바일 입력 UX 사례 조사](../research/2026-11-21-mobile-input-cases.md), [금액 입력과 RN 입력 손맛](../research/2026-11-15-amount-input-and-rn-input-feel.md)
- 리뷰: 다른 모델(Fable)의 독립 리뷰를 반영했다(대기열 수명, 결제수단 제안 범위, 퍼널이 담는 결제, 쓴 사람 "함께", 종목 검색의 개인 장부 노출 등).

원칙과 흐름을 정한다. 최종 시안(크기·간격·색·문구 다듬기)은 디자인 스펙에서 한다. "퍼널", "콜드 스타트", "p75" 같은 말은 설계 용어이고 화면 문구가 아니다.

## 0. 한 장 요약

| 항목 | 결정 |
|---|---|
| 추가 버튼 | 홈·기록 탭 오른쪽 아래 떠 있는 `+`. 분석·자산 탭에는 없다. 탭 바 가운데 `+`는 만들지 않는다 |
| 입력 구조 | **퍼널**: 무엇을(장부·종류) → 얼마 → 모르는 칸만 → 확인. 한 화면에 질문 하나 |
| 장부 | 퍼널 첫 단계에서 사람이 고르고, 그 뒤 저절로 바뀌지 않는다 (ADR 0027) |
| 금액 키패드 | `00`, 만 단위 힌트, 외화면 `.`, 길게 눌러 붙여넣기, `⌫` 길게 전체 지우기, 햅틱. 빠른 금액 버튼·계산기 없음 |
| 최근 항목 | 그 장부의 최근 가맹점을 고르면 카테고리와, **내가 쓸 수 있는 결제수단으로 적힌** 마지막 기록의 결제수단을 채우고 확인으로. 채운 결제수단에 "지난번과 같음" 표시 |
| 드문 결제 | 페이는 연결 대상을 한 단계 더 묻고, 할부·해외 결제·나눠 내기는 확인 화면의 조건부 칸 |
| 줄 나누기 | 직접 친 금액은 그대로, 안 친 줄이 맞춘다 |
| 매매 | 투자 화면에서 시작. 계좌 → 종목 → 수량 → 단가 → 확인. 종목 검색은 서버 메모리, 초성·한글 미국명. "보유 종목"은 내가 볼 수 있는 계좌 기준 |
| 통계 귀속 | 기록 상세 맨 아래 "통계" 묶음(고정비·쓴 사람·통계 제외). 쓴 사람 "함께"를 고를 수 있게 칸을 더한다 |
| 시트·키보드 | 퍼널은 화면 이동, 시트는 한 칸 고칠 때만, 시트는 한 겹. 키패드와 키보드는 한 번에 하나 |
| 저장 실패 | 새 기록만 폰 대기열에서 자동으로 다시 보낸다("보내는 중"). **새 기록 id는 앱이 정한다**. 수정·삭제는 온라인에서만 (ADR 0028) |
| 접근성 | 출시 조건으로 App Store 접근성 라벨 4개: VoiceOver·더 큰 텍스트·다크 인터페이스·색에만 의존하지 않음 |
| 콜드 스타트 | iPhone SE 2세대 Release 빌드, 콜드 실행 10회 중간값으로 홈 숫자 보임·빠른 동작 키패드 1.5초 이하 |

## 1. 입력 진입

- **떠 있는 `+` 버튼**을 홈과 기록 탭의 오른쪽 아래(탭 바 위)에 둔다. 앱을 열면 홈이 먼저 뜨므로 한 번 탭으로 입력을 시작한다.
  - 분석·자산 탭에는 두지 않는다. 자산 탭에는 "지갑 추가"가 따로 있어서 `+`가 둘이면 헷갈린다.
  - 탭 바 가운데 `+`는 만들지 않는다. Apple HIG가 "탭 바는 이동용이지 동작용이 아니다"라고 하고, expo-router 네이티브 탭에는 탭을 버튼처럼 쓰는 기능이 없다.
- 입력은 아래에서 올라오는 **모달**이다. 닫으면 보던 탭으로 돌아간다.
- **앱 아이콘 빠른 동작**: 길게 누르면 지출 항목 둘. 최근에 지출을 적은 장부 두 개(보관한 장부 제외)이고, 아직 없으면 공용 장부 하나와 내 개인 장부 하나다. 이름은 장부 이름을 그대로 쓴다. 퍼널 1단계를 건너뛰고 금액 단계로 바로 연다.
- 다른 입구: 매매는 투자 화면(7절), 돌려받은 돈은 원 기록 상세(2.3), 예정 확정은 홈 "확인할 것"(2.3).

## 2. 입력 퍼널

토스 제품 원칙 **"One Thing"**(한 화면에서 판단 하나)을 따른다([토스 제품 원칙](https://toss.im/tossfeed/article/tossproductprinciples)). 다만 가계부에서 단계식이 더 빠르다는 사례는 찾지 못했다(YNAB·Copilot은 한 화면 폼, [사례 조사](../research/2026-11-21-mobile-input-cases.md) 3절). 송금과 달리 가계부는 하루 여러 번 같은 모양으로 적으므로, **답을 아는 단계는 건너뛰어** 탭 수를 줄인다.

### 2.1 지출

1. **무엇을 기록?** — `+`를 누르면 그 자리에 뜨는 메뉴: `🏠 공용 지출` · `🔒 내 지출` · `수입` · `이체`. 장부가 셋 이상이면 지출 항목은 장부마다 하나씩 보이고, 많으면 `다른 장부…`로 접는다.
2. **얼마?** — 키패드만 있는 화면(3절). 위에 "공용 지출"처럼 고른 것을 표시만 한다. 바꾸려면 뒤로 간다. 금액만 `다음` 버튼이 있다.
3. **모르는 칸만** — 차례로 아래 단계. 값을 아는 단계는 건너뛴다(5절).
   - ③-1 **어디서 썼어요?**(가맹점)
   - ③-2 **어떤 카테고리?**
   - ③-3 **어디서 냈어요?** — 결제수단(카드·페이)과 내가 쓸 수 있는 지갑(현금·통장·포인트·상품권)을 한 목록에. 화면 문구는 "결제수단"이라는 말을 쓰지 않는다(지갑까지 들어 있어서).
   - ③-4 **어떤 걸로 냈어요?** — ③-3에서 페이를 골랐을 때만. 그 페이의 연결 대상(카드, 페이머니)이고, 마지막에 쓴 것(`payment_method_targets.last_used_at`)을 맨 앞에 둔다.
4. **확인** — 모든 칸(장부, 금액, 가맹점, 카테고리, 낸 곳, 날짜, 메모)과 조건부 칸, 접힌 `더 보기`. 칸을 누르면 그 칸만 시트로 열고 다시 확인으로 돌아온다. 버튼은 `저장`과 `저장하고 하나 더`.
   - 신용카드면 `일시불 ▾` 칸이 생긴다. 할부 개월을 고른다.
   - `더 보기`: `해외 결제`, `나눠 냈어요`, 통계 묶음(8절).
   - 앱이 채운 칸(최근 가맹점, 이어받은 값)에는 "지난번과 같음"을 작게 붙인다.

- 고르는 단계는 고르는 순간 다음으로 넘어간다(`다음` 버튼 없음).
- 뒤로 가기를 해도 앞에서 넣은 값은 남는다.
- **날짜·시각**: 기본은 오늘·지금 시각이고 확인 화면에서 고친다. 날짜를 고치면 시각은 비운다(그날 맨 뒤, 물리 DB 스키마 4.1). 해외 결제는 현지 날짜로 바뀐다(ADR 0014).
- **저장 뒤**: 화면이 닫히고 "저장했어요 · 되돌리기" 토스트가 뜬다.
  - 서버가 받은 기록이면 되돌리기는 그 기록을 지운다.
  - 아직 보내는 중이면 대기열에서 빼고, 이미 날아가는 중이면 "취소 표시"를 해 두었다가 서버 응답이 오면 지운다. 기록 id를 앱이 정해서(10절) 응답을 잃어도 지울 대상을 안다.
  - 지워도 감사 기록에는 만들었다가 지운 흔적과 내용이 남는다(물리 DB 스키마 5.4). 공용 장부의 감사 기록은 가구원이 볼 수 있으므로, 개인 지출을 공용 장부에 잘못 넣으면 되돌리기로 완전히 감출 수 없다. 그래서 장부는 첫 단계에서 고른다(ADR 0027).
- `저장하고 하나 더`는 퍼널을 금액 단계부터 다시 열고 장부·날짜·낸 곳을 이어받는다. 날짜가 오늘이면 시각은 새 지금 시각, 다른 날이면 비운다.
- 구현 후보: 토스 오픈소스 `use-funnel`(React Navigation 지원 여부는 구현 때 확인). 단계 정의와 건너뛰기 조건을 선언적으로 두는 구조면 된다.

### 2.2 조건부 칸

| 경우 | 입력 |
|---|---|
| 할부 | 신용카드를 고르면 확인 화면 `일시불 ▾`. 할부수수료는 청구서 확정 때(ADR 0005) |
| 해외 결제 | `더 보기`의 `해외 결제`를 켜면 외화 금액·통화를 친다(이때 키패드에 `.`). 카드 다리의 원화는 그날 기준환율로 추정하고 "추정" 표시(`legs.is_estimated`)를 붙여 청구서에서 확정한다. 날짜는 현지 날짜다. 금액 단계에서 원화로 친 값이 있으면 외화를 치는 순간 버리고 추정값으로 바꾼다 |
| 나눠 내기 | `더 보기`의 `나눠 냈어요` → 두 번째 낸 곳과 금액. 줄 나누기와 같은 규칙으로 첫 낸 곳의 금액이 자동으로 맞춰진다(6절). 네이버페이로 카드와 페이머니를 나눠 낸 것도 같다(다리 둘, 물리 DB 스키마 5.2) |
| 현금·계좌이체 | ③-3 목록의 지갑을 고른다. 결제수단 없이 지갑 다리만 생긴다 |
| 포인트·상품권으로 냄 | ③-3 목록의 포인트·상품권 지갑. 할인이 아니라 그 지갑에서 나간 돈이다(GLOSSARY **포인트**) |

### 2.3 다른 종류

| 종류 | 퍼널 |
|---|---|
| 수입 | 어느 장부?(쓸 수 있는 장부가 하나면 건너뜀) → 금액 → **누가 보냈어요?**(가맹점 단계, 회사·집주인) → 카테고리 → 받은 지갑 → 확인 |
| 이체 | 어느 장부?(하나면 건너뜀) → 금액 → 보내는 지갑 → 받는 지갑 → 확인. 카드대금도 이체다(받는 지갑 = 신용카드 지갑) |
| 매매 | 7절 |
| 돌려받은 돈 | 원 기록 상세의 `돌려받은 돈 기록` → 종류(환불·혜택·정산) → **받았어요 / 받을 거예요** → 정산이면 **누구에게서?**(상대) → 금액 → 받았으면 받은 지갑 → 확인. 원 기록·장부는 정해져 있다(같은 장부 규칙). "받을 거예요"는 예상 상태(다리 없음)로 "받을 돈"에 보인다. 카테고리가 여럿이면 기본 배분(ADR 0007)을 확인 화면에서 고친다 |
| 예정 확정 | 홈 "확인할 것"·곧 나갈 돈에서 `확정` 한 번 탭. 금액이 다르면 `고쳐서 확정` → 확인 화면 |

### 2.4 앱 입력 퍼널에서 다루지 않는 것

기록 상세에서 고치거나, 필요해지면 따로 화면을 만든다.

- 매입일, 다음 청구서로 넘기기: 기록 상세에서 고친다.
- 환전(금액 둘), 수수료가 붙는 이체.
- 원 기록 여러 개를 나눠 가리키는 묶음 정산, 원 기록 없이 먼저 받은 선지급 정산, 원 기록 없는 혜택 수입.
- 잔액 맞춤·청구서 확정은 지갑·청구서 화면의 몫이다(입력 퍼널이 아니다).

## 3. 금액 키패드

| 기능 | 결정 | 이유 |
|---|---|---|
| `00` 키 | 넣는다 | 0이 많은 금액을 빨리 친다 |
| 만 단위 힌트 | 금액 아래 "125만원", "1만 2천원" | 0 개수를 잘못 세는 실수를 막는다 |
| 소수점 | 통화가 외화일 때(해외 결제, USD 지갑·계좌)와 주식 수량에서 `00` 자리가 `.`. 외화 금액 아래에 기준환율 원화 환산을 작게 | 해외 결제·외화 계좌·소수점 매매 |
| 붙여넣기 | 금액을 길게 누르면 `붙여넣기` 메뉴. 숫자만 골라 넣는다 | iOS는 코드가 클립보드를 읽으면 허락 알림이 떠서, 사용자가 고를 때만 읽는다 |
| `⌫` 길게 누르기 | 전체 지우기 | |
| 햅틱 | 키마다 약한 선택 햅틱, 시스템 설정을 따름 | |
| 빠른 금액(+1만·+5만) | **넣지 않는다** | 가계부 금액은 12,800원처럼 딱 떨어지지 않는다 |
| 계산기(+ − × ÷) | **넣지 않는다** | 나누기는 줄(6절), 더치페이는 정산이 맡는다. 필요하면 나중에 더한다 |

- 금액 단계는 낸 곳보다 먼저라서 기본 통화는 원화다. USD 지갑에서 시작하는 입력(그 지갑 화면에서 연 기록)만 처음부터 그 통화다.
- 금액 표시는 `TextInput`이 아니라 `Text`이고, 키는 `onPressIn`에서 처리한다(앱 스택 PoC 구성).
- 0원으로는 `다음`이 열리지 않는다(다리 금액 ≠ 0). 줄의 0원(무료 품목)은 6절.
- 큰 금액 표시의 넘침은 11.2.

## 4. 장부

장부(공용/개인)는 "우리 돈인가, 내 돈인가"라는 판단이라 결제수단·가맹점에서 맞히지 않는다. 내 카드로 장을 보면 공용이다. 그래서 퍼널 첫 단계에서 사람이 고른다(ADR 0027).

- 지출은 첫 메뉴에서 장부와 종류를 한 번에 고르므로 탭이 늘지 않는다.
- 고른 뒤에는 **저절로 바뀌지 않는다.** 가맹점·결제수단을 골라도 그대로다. 바꾸려면 퍼널 앞으로 가거나 확인 화면의 장부 칸을 누른다.
- 개인 장부는 자물쇠 표시와 다른 색으로 확인 화면 맨 위(금액 옆)에서 바로 구분된다. 색 값은 디자인 스펙에서 정한다.
- 장부를 바꾸면 그 장부에서 못 쓰는 카테고리(장부 전용 카테고리)는 비우고 다시 묻는다. 줄을 나눈 기록이면 그 줄들의 카테고리만 비운다.
- 기록 탭에서 특정 장부를 걸러 보던 중에 `+`를 누르면 메뉴의 그 장부 항목을 맨 위에 둔다(그래도 고르는 건 사람).
- 결제수단·지갑에 기본 장부 칸을 더하는 안은 택하지 않았다. 몰래 바뀌는 장부가 개인 지출을 공용으로 새게 한다.

## 5. 최근 항목

- **③-1 가맹점 "어디서 썼어요?"**: 그 장부의 최근 가맹점 목록(자주 + 최근 순), 검색칸, `건너뛰기`. 키보드는 검색칸을 누를 때만 올라온다.
  - 목록은 그 장부의 지출·수입 기록의 가맹점(`records.title`)에서 만든다. 이체·카드대금·잔액 맞춤의 이름은 넣지 않는다. 공백·대소문자를 무시하고 같은 것으로 본다.
  - **최근 가맹점을 고르면** 칸을 채우고 바로 확인으로 간다. 단골 지출은 `+` → 공용 지출 → 금액 → 다음 → 가맹점 → 저장, 탭 다섯 번이다.
    - 카테고리: 그 장부에서 그 가맹점으로 적은 마지막 기록의 카테고리. 줄이 여럿이면 금액이 가장 큰 줄의 카테고리다. 줄 나누기는 가져오지 않는다.
    - 결제수단: 그 가맹점으로 적은 기록 중 **내가 쓸 수 있는 결제수단·지갑으로 적힌** 마지막 기록의 것. 배우자가 배우자 카드로 적은 기록은 건너뛴다. 없으면 ③-3을 묻는다.
    - 보관한 카테고리·결제수단·지갑이면 그 칸은 채우지 않고 묻는다. 할부·해외 결제·나눠 내기는 가져오지 않는다(일시불 원화 한 곳).
    - `저장하고 하나 더`로 이어받은 낸 곳이 있으면 가맹점 제안은 그 칸을 덮지 않는다(비어 있는 칸만 채운다).
    - 채운 칸에는 확인 화면에서 "지난번과 같음"을 붙여, 오늘 다른 카드로 냈다면 바로 보이게 한다.
- **③-2 카테고리, ③-3 낸 곳**: 가맹점을 건너뛰었거나 채우지 못한 칸만 나온다. 낸 곳은 추측해서 건너뛰지 않는다(틀린 카드는 청구서까지 틀리게 한다). 내가 최근에 쓴 것을 맨 앞에 둔다.
- **기록 복제**: 기록 상세의 `다시 기록` → 날짜만 오늘로 바꿔 퍼널을 금액 단계부터 연다. 낸 곳이 내가 쓸 수 없는 것이면 비운다.
- **지키는 선**
  - 제안은 **고른 장부의 기록에서만** 만든다. 개인 장부의 가맹점이 공용 입력에 뜨지 않는다.
  - 결제수단은 **내가 쓸 수 있는 것만** 제안한다(내 결제수단, 함께 쓰는 지갑).
  - 위치 기반 제안은 넣지 않는다. 위치 권한을 달라고 할 이유가 약하다.
  - 제안은 따로 저장하지 않고 서버가 기록에서 계산해 내려준다(얇은 클라이언트). 성능은 구현 때 재고, 느리면 `records (household_id, ledger_id, title)` 인덱스를 검토한다.
  - 서버에 닿지 못하면 마지막으로 받은 제안과 뼈대(장부·지갑·결제수단·카테고리)를 폰 캐시에서 쓴다(10.3).

## 6. 줄 나누기

- 확인 화면의 카테고리 칸 옆 `나누기`에서 들어간다. 퍼널 단계에는 넣지 않는다.
- 줄은 **나란하다**. 처음 고른 카테고리 줄 안에 다른 줄이 들어가는 게 아니다. 줄을 같은 들여쓰기·같은 모양으로 그리고, 합계는 맨 위에 따로 둔다.
- **규칙: 직접 친 금액은 그대로, 안 친 줄이 맞춘다.**
  - 처음 고른 카테고리 줄은 아직 직접 친 적이 없어서 결제 금액 전체를 들고 있다(**자동 줄**). `+ 줄 추가`로 다른 줄 금액(같은 키패드)과 카테고리를 넣으면 그만큼 자동 줄에서 빠진다. 합이 늘 맞는다.
  - 자동 줄은 금액 옆에 자동 아이콘을 두고 회색으로 그린다(색만으로 알리지 않는다). "나머지" 같은 꼬리표는 붙이지 않고, 자동 줄이 있을 때만 "떼어낸 만큼 장보기에서 빠져요"처럼 카테고리 이름을 넣은 안내 한 줄을 둔다.
  - 모든 줄을 고칠 수 있다. 자동 줄을 직접 고치면 자동 줄이 없어진다. 그 뒤로 합이 안 맞으면 "3,000원이 남았어요 [간식에 더하기]"를 보여주고 합이 맞을 때까지 `완료`를 막는다. 버튼은 마지막으로 고친 줄을 뺀 줄 중 금액이 가장 큰 줄을 제안한다.
  - 줄을 길게 눌러 `자동으로 맞추기`를 고르면 그 줄이 자동 줄이 된다(자동 줄은 늘 하나 이하).
  - 직접 친 금액은 앱이 바꾸지 않는다.
  - 다른 줄 합이 결제 금액을 넘으면 `완료`를 막고 "나눈 금액이 합계보다 3,000원 많아요"라고 쓴다.
  - 자동 줄이 0원이 되면 저장할 때 지운다. 직접 친 0원 줄(무료 품목)은 남긴다.
- **결제 금액을 나중에 바꾸면**: 자동 줄이 있으면 자동 줄이 맞춘다(0 아래로 가면 위 넘침 문장). 없으면 확인 화면에 "줄 합이 금액과 3,000원 달라요 [나누기 열기]"를 띄우고 저장을 막는다.
- **저장된 기록을 다시 열면** 모든 줄이 직접 친 줄이다(자동 여부는 저장하지 않는다). 금액을 고치면 위 차이 안내로 맞춘다.
- 품목 이름·정가는 줄을 눌러 펼치는 선택 칸이다. 결제 할인은 정가와 줄 금액의 차이로 안다(ADR 0007). 영수증 품목을 하나하나 넣는 건 AI 연결의 몫으로 둔다.

## 7. 매매와 종목 검색

- **입구**: `+` 메뉴에 넣지 않는다. 투자 화면 `매매 기록` → 사기/팔기, 종목 상세 `더 사기`·`팔기`(계좌·종목을 건너뛰고 수량부터).
- **퍼널**
  1. **어느 계좌?** 내가 기록을 쓸 수 있는 장부에 묶인 증권 계좌만 보인다. 하나면 건너뛴다. 장부는 계좌가 정해서 묻지 않는다(ADR 0009).
  2. **어떤 종목?** 이 계좌와 내가 볼 수 있는 장부의 계좌가 보유한 종목을 올린다(다른 가구원의 개인 장부에 묶인 계좌의 종목은 순서·폐지 종목 노출·현재가 칩 어디에도 쓰지 않는다, ADR 0025). 팔기면 이 계좌의 보유 종목만. 이름·코드·초성(`ㅅㅅㅈㅈ`)·한글 미국명(`애플`)·미국 종목 영문명으로 찾는다. 폐지(`listed = false`) 종목은 숨기고, 내가 볼 수 있는 계좌가 보유 중이면 보인다([시세 데이터 공급원](market-data.md) 7절).
  3. **몇 주?** 수량 키패드는 늘 `.`이 있다(국내·미국 소수점 매매). 팔기는 `전부 12주` 칩. 가진 수량보다 많이 팔면 막는다.
  4. **얼마에?** 1주 단가. `11/20 종가 71,200` 칩(보유 종목은 최근 현재가, 아니면 마스터의 전일 종가 `base_price`)을 누르면 채우지만 **자동으로 넣지 않는다**(실제 체결가와 다르다).
     - `총액으로 입력`으로 바꾸면 현금 다리는 친 총액 그대로이고, 단가는 총액 ÷ 수량으로 계산해 보여준다. 반올림된 금액을 수량으로 나누면 증권사 평단과 어긋날 수 있어서(물리 DB 스키마 3.2), 소수점 수량이면 계산한 단가를 증권사 화면과 맞춰 보라고 안내하고 고칠 수 있게 한다. 단가 자릿수는 구현 때 물리 DB 스키마 4.2와 함께 정한다.
  5. **확인**: 체결일, 금액, 매매 비용(규칙·요율 추정, "추정" 표시, 고칠 수 있음), USD면 기준환율(증권사 환율로 고칠 수 있음), 메모.
- **체결일 기본값**: 국내는 오늘(한국). **미국은 지금의 미 동부 날짜**이고, 그날이 토·일이면 직전 금요일이다(휴장일 달력은 두지 않는다, 사용자가 고친다). 한국 아침에 어젯밤 매수를 적으면 미국 날짜(어제)가 된다. ADR 0014에 반영했다. 국내 증권사 주간거래(미국 낮 시간) 체결분의 현지 날짜는 구현 전에 확인한다.
- **검색 방식**: API 메모리의 마스터 사본을 전부 훑는다. 1.7만 종목에 평균 1ms, p99 1.7ms(맥북, 요청 하나)라 색인이 필요 없다([PoC](../research/2026-11-21-mobile-input-poc.md)). 미니 PC에서도 수 ms 안일 것으로 본다(추론, 구현 때 확인). 앱은 글자마다 약 150ms 늦춰 서버에 묻는다. 순서는 코드 정확 일치 > 보유 종목 > 코드 앞부분 > 이름·초성 앞부분 > 영문명 앞부분 > 포함, 같으면 짧은 이름 먼저.

## 8. 기록 상세의 "통계" 묶음

통계 질문 목록이 넘긴 "고정비"·"쓴 사람" 토글의 자리다.

```
통계
 고정비            [켬]
 쓴 사람         민지 ▾     ← 공용 장부 기록만
 통계 제외         [끔]
```

- 기록 상세 맨 아래에 둔다. 가끔 고치는 값이다.
- **쓴 사람**은 공용 장부 기록에만 보인다(쓴 사람 통계가 공용 장부만 센다). 고를 수 있는 값은 `자동(계산값 이름)`·가구원들·`함께`다.
  - 내 카드로 둘이 먹을 장을 본 경우처럼 "함께"로 고칠 일이 흔하다. 그래서 `records.spender_shared`(boolean, 기본 false)를 더한다. 켜지면 "함께", `spender_member_id`가 있으면 그 사람, 둘 다 비면 계산이다. 둘이 함께 차는 것은 CHECK로 막는다(ADR 0017에 반영).
  - 직접 고른 값이면 옆에 "직접 바꿈"을 붙이고, `자동`을 고르면 두 칸을 비운다.
- **고정비**는 켬/끔 스위치만 둔다. 저장할 때 한 번 정하는 값이라(ADR 0017) 직접 고쳤는지 표시하지 않는다.
- **통계 제외**는 같은 묶음에 둔다.
- 입력 퍼널은 이 값들을 묻지 않는다. 확인 화면의 접힌 `더 보기`에 같은 세 칸이 있고, 저장 전에는 앱이 캐시한 뼈대로 계산한 미리보기 값을 보여준다(고정비는 고른 카테고리의 기본값, 쓴 사람은 낸 곳의 주인). 저장 값은 서버가 정한다.

## 9. 바텀시트·키보드

- **화면 단위**: 퍼널 단계는 입력 모달 안의 화면 이동(push)이다. 시트는 확인 화면에서 한 칸을 고칠 때(카테고리·낸 곳·날짜·금액 키패드)와, 다른 화면의 고르기(장부 필터 등)에만 쓴다.
- **시트는 한 겹**이다. 시트 위에 시트를 올리지 않고, 더 들어가야 하면 시트 안에서 화면을 넘긴다.
- **높이**: 짧은 목록은 내용만큼, 검색이 있는 긴 목록(카테고리·가맹점·종목)은 처음부터 크게 열고 검색칸을 맨 위에 둔다.
- **닫기**: 시트를 끌어 닫으면 취소다. 고르는 순간 반영하고 닫힌다. 입력 모달 전체를 끌어 닫을 때 입력한 게 있으면 "작성 중인 기록을 버릴까요?"를 묻는다.
- **키패드와 키보드는 한 번에 하나**다. 메모·검색칸을 누르면 키패드가 내려가고 시스템 키보드가 올라온다. 저장·다음 버튼은 키보드 바로 위에 붙어 가려지지 않는다(react-native-keyboard-controller).
- **라이브러리**: 시트는 react-native-true-sheet(iOS 순정 시트라 다크 모드·iOS 26 유리 효과·키보드 비켜 주기가 기본). 문제가 생기면 @gorhom/bottom-sheet. 앱 스택 PoC에서 둘의 손맛 차이는 없었다. 메모 입력칸(RN `TextInput` / `@expo/ui`)은 둘 다 한글 조합을 통과해서 구현 때 고른다.

## 10. 저장 실패와 "보내는 중"

서버는 집의 미니 PC라 잠깐 멈출 수 있고, 지하 매장처럼 신호가 약한 곳에서 적는 일이 흔하다(ADR 0028).

### 10.1 대기열

- **대상**: `+`로 만든 지출·수입·이체 새 기록만 대기열에 넣는다. 예정 확정(같은 회차 유니크), 매매(보유 수량 검사), 돌려받은 돈(한도 검사), 모든 수정·삭제는 온라인에서만 한다. 서버 상태에 따라 거절될 가능성이 커서다.
- 저장을 누르면 화면은 바로 닫히고, 보내지 못했으면 토스트가 "연결되면 보낼게요"로 바뀐다. 연결되면 자동으로 보내고, 앱을 껐다 켜도 이어간다. 만료 시한은 없다.
- **기록 id는 앱이 정한다(UUIDv7).** 서버는 같은 가구에 같은 id의 기록이 이미 있으면 새로 만들지 않고 그 기록을 돌려준다. 중복 방지 키는 7일 보관이라(서버 아키텍처 11번), 응답을 잃고 8일 뒤에 다시 보내면 기록이 두 번 생길 수 있다. id가 정해져 있으면 기록이 남아 있는 한 늘 막힌다. 다른 가구의 id를 맞혀도 아무것도 보이지 않는다(가구 안에서만 찾는다). 생성 시각이 id에 들어가므로 같은 날 순서는 앱에서 저장을 누른 순서다.
- 대기 중인 기록은 고칠 수 없다. 고치려면 대기열에서 빼고 새 초안으로 다시 적는다(같은 키에 다른 본문은 422라서).
- **응답별 처리**

| 응답 | 처리 |
|---|---|
| 네트워크 오류, 시간 초과, 5xx, Cloudflare 502·530 | 대기열에 남기고 다시 보낸다(간격을 늘려 가며) |
| 401(세션 끝남) | 남긴다. 같은 사람이 다시 로그인하면 보낸다 |
| 409(같은 키 처리 중) | 남기고 잠시 뒤 다시 보낸다 |
| 2xx, 또는 같은 id가 이미 있음 | 끝. 대기열에서 뺀다 |
| 422(검증 실패), 403(장부 권한 없음·나간 가구), 404(지갑·카테고리가 지워짐), 최소 앱 버전 미달 | `보내지 못한 기록`으로 옮긴다. 눌러서 고쳐 새 초안으로 보내거나 버린다 |

- **저장소**: 화면용 쿼리 캐시와 분리한 전용 저장소에 둔다. TanStack Query의 persist 기본값(24시간이 지나면 버림, 앱 버전이 바뀌면 버림)과 "멈춘 쓰기만 이어하기"는 이 요구에 맞지 않는다. 쓰기 실행은 TanStack Query를 써도 되지만, 대기열의 보관·재시도 규칙은 위 표를 따르는 우리 코드다.

### 10.2 보이는 곳

- 기록 탭 맨 위에 `보내는 중 N건` 줄이 생긴다. 그 기록은 목록에 "보내는 중" 표시를 달고 보인다(흐리게 하지 않는다).
- 잔액·통계는 서버가 받은 뒤에 반영된다(계산은 서버 몫). 그 사이 홈 맨 위 숫자, 자산 탭 잔액, 청구서 화면 위에 **"아직 반영 안 된 기록 N건"**을 붙인다. 그 숫자에 영향을 주는지 따지지 않는 문구다(이체·지난달 기록도 센다).
- 서버가 거절한 것은 `보내지 못한 기록` 줄로 따로 보인다.

### 10.3 폰에 남는 것

- 폰에 두는 것: 대기열, 마지막 홈 숫자(12절), 뼈대(장부·지갑·결제수단·카테고리)와 최근 가맹점 제안. 오프라인에서도 퍼널을 끝까지 갈 수 있게 하려는 것이다.
- 모두 **로그인한 사용자 id로 묶고**, iOS 데이터 보호(잠금 해제 전 읽기 불가)를 쓴다.
- 다른 사용자가 같은 폰에 로그인하면 앞 사용자의 것은 보이지 않는다(지우지는 않고 그 사람이 다시 로그인할 때 쓴다). 로그아웃할 때 대기열이 있으면 "보내지 못한 기록 N건을 지울까요?"를 묻고, 대기열 밖의 캐시는 지운다.
- 서버가 세션을 끝냈다고 알려 주면(가구 나가기·내보내기·다른 기기에서 계정 삭제) 그 사용자의 캐시와 대기열을 모두 지운다. 나간 가구의 기록은 어차피 403이다.

## 11. 접근성

출시 조건으로 App Store 접근성 라벨 **VoiceOver · 더 큰 텍스트 · 다크 인터페이스 · 색에만 의존하지 않음**을 표시할 수 있게 만든다. 라벨은 로그인·온보딩·입력·조회·설정의 공통 작업을 그 기능만으로 끝낼 수 있어야 붙일 수 있다.

### 11.1 VoiceOver

- **키패드**: 키마다 "키보드 키" 역할(`accessibilityRole="keyboardkey"`)과 이름("영영", "지우기"). 누를 때마다 금액을 한국어 단위로 읽는다("1만 2천 원", 순서 대기 알림). 금액 표시 자체도 같은 문장을 값으로 갖는다.
- **길게 누르기의 대체**: `⌫`에는 커스텀 액션 `모두 지우기`, 금액에는 `붙여넣기`. 줄의 `자동으로 맞추기`도 커스텀 액션이다.
- **퍼널**: 다음 단계로 넘어가면 포커스를 그 화면의 질문("얼마 썼어요?")으로 옮긴다.
- **모달·시트**: 바깥으로 포커스가 새지 않게 하고(`accessibilityViewIsModal`), 두 손가락 문지르기로 닫는다(끌어 닫기와 같은 취소).
- **토스트**: 나타날 때 문장을 읽고, VoiceOver가 켜져 있으면 손가락이 닿을 때까지 사라지지 않는다. 같은 되돌리기를 기록 상세에서도 할 수 있다.
- **줄 나누기**: 자동 줄은 "자동 계산"을 함께 읽는다.
- **홈 편집**: 끌기 손잡이와 함께 커스텀 액션 `위로 이동`·`아래로 이동`·`숨기기`(App Store 기준: 끌어 옮기기는 다른 방법도 줘야 한다).
- **차트**: 한 문장 요약을 읽는다("평소 이맘때보다 12만 원 덜"). 차트를 소리로 훑는 기능은 넣지 않는다.
- 색으로만 알리지 않는다(통계 화면 구성 9절의 부호 필수, 개인 장부의 자물쇠, 자동 줄 아이콘).

### 11.2 Dynamic Type

아래는 초안 규칙이고, 실기기(200% 글자, AX 크기)에서 확인한 뒤 디자인 스펙에서 확정한다. RN(Fabric)에서 `adjustsFontSizeToFit`의 실제 동작도 그때 확인한다.

- **맨 위 큰 숫자**(홈 숫자, 입력 금액, 자산 탭 묶음 금액): 글자 크기를 따라 커지고, 넘치면 폭에 맞게 줄인다. 줄여도 그 글자 크기 설정의 본문 금액보다는 커야 하고(최소 배율은 디자인 스펙), 그보다 더 줄여야 하면 두 줄로 내린다. "1,284만"처럼 줄여 쓰지 않는다(금액이 바뀐다).
- **키패드 글자**: 상한을 둔다(`maxFontSizeMultiplier`). 키 크기가 고정이고 이미 크다. 상한이 라벨 기준(200%)과 부딪히는지 함께 확인한다.
- **목록 줄**(이름 ··· 금액): 접근성 크기(AX1~)에서는 금액을 이름 아래로 내린다.
- 금액은 13pt 이상이다(통계 화면 구성 9절).

### 11.3 홈 편집

- 홈 맨 아래 `홈 편집` → 목록 화면. 맨 위 숫자 고르기가 맨 위에 따로 있고, 아래 카드 줄마다 켜기/끄기 스위치와 오른쪽 끌기 손잡이가 있다. 손잡이는 길게 누르지 않아도 바로 끌린다.
- 저장은 `household_members.home_layout`(통계 화면 구성 4절)이다.

## 12. 콜드 스타트

콜드 스타트는 앱이 메모리에 없을 때 아이콘을 눌러 쓸 수 있게 되기까지다.

| 지점 | 시작 → 끝 | 목표 | 출시 조건 |
|---|---|---|---|
| 첫 프레임 | 아이콘 탭 → 첫 화면이 그려짐 | Apple 권장 "400ms 안"(WWDC19) | 아님. 재서 기록한다 |
| 홈 숫자 보임 | 아이콘 탭(프로세스 시작) → 홈 맨 위 숫자가 그려짐(캐시 값 포함) | 1.5초 이하 | **예** |
| 빠른 동작 키패드 | 빠른 동작 탭 → 키패드 키가 눌림을 받음 | 1.5초 이하 | **예** |

- **잼 방법**: iPhone SE 2세대(가장 느린 테스트 폰), Release 빌드, 재부팅 뒤 콜드 실행 10회의 **중간값**. 시작·끝에 앱이 자체 표식을 찍어 기록한다(Xcode Instruments의 App Launch로 첫 프레임을 함께 본다).
- 출시 뒤에는 같은 자체 표식을 우리 서버로 보내 본다. Xcode Organizer·MetricKit은 첫 프레임까지만 재고 사용자가 적으면 자료가 모이지 않아서 보조로만 쓴다.
- 근거: Expo는 콜드 실행 1.5초·TTI 3초를 목표로 제시했고, Shopify는 콜드 p75 2초를 목표로 했다([사례 조사](../research/2026-11-21-mobile-input-cases.md) 10절). 우리 목표는 캐시를 먼저 보여주는 전제로 더 엄하게 잡았다. SE 2세대 실측은 아직 없다(앱 스택 PoC에서 재지 않았다). 첫 실측에서 크게 넘으면 목표를 다시 본다.
- **지키는 방법**
  - 마지막으로 본 홈 숫자를 폰에 두고 먼저 보여준다(10.3의 보호 규칙). 네트워크를 기다리지 않는다. 새 숫자가 오면 바꾸고, 오래된 값이면 "11/21 14:20 기준"을 붙인다.
  - 분석·자산 탭 화면과 차트는 처음 누를 때 불러온다.

## 13. 나중에 정할 것: 여러 건 한 번에

여러 건을 몰아 적는 일(장본 영수증 여러 장, 밀린 기록)이 종종 있다. 지금은 지침만 둔다.

- `저장하고 하나 더`가 장부·날짜·낸 곳을 이어받아 반복 입력의 탭을 줄인다(2.1).
- 영수증·카드 문자 묶음은 AI 연결(MCP)이 맡는 것이 기본이다. 앱은 "AI가 바꾼 기록"에서 확인·되돌리기를 한다.
- 일괄 입력 화면(표 모양, 여러 줄 한 번에 저장)은 실제로 몰아 적는 상황을 모은 뒤 따로 검토한다. 만들게 되면 각 건이 같은 퍼널 기본값 규칙(장부는 사람이 고름, 결제수단은 내가 쓸 수 있는 것만)을 지키고, 건마다 앱이 정한 id를 가진다.

## 14. 다른 티켓에 넘기는 것

- **디자인 스펙(디자인 그릴링)**: 퍼널 각 화면·확인 화면·나누기 화면의 최종 시안, 떠 있는 `+`의 크기와 탭 바와의 간격, 개인 장부 색과 자물쇠, 자동 줄 아이콘, "지난번과 같음" 표시, 작은 폰(SE)에서 확인 화면 배치, 큰 숫자 최소 배율과 두 줄 규칙(11.2 실기기 확인), 빈 상태 문구.
- **물리 DB 스키마**: `records.spender_shared`(boolean NOT NULL 기본 false, `spender_member_id`와 함께 차지 않는 CHECK). 새 기록의 id를 앱이 정할 수 있다는 예외(2절 4번). 이 티켓에서 반영했다.
- **서버 아키텍처**: 기록 생성은 앱이 정한 id를 받고, 같은 가구에 같은 id가 있으면 그 기록을 돌려준다(11번에 반영). 필수 테스트(34번)의 개인 장부 확인에 **가맹점 제안·종목 검색** 엔드포인트를 더한다(가구원 A·B 시점, 이 티켓에서 반영).
- **알림**: 예정·청구서 알림을 누르면 확인 화면(예정 확정)으로 바로 연다. `보내지 못한 기록`이 생기면 로컬 알림을 보낼지 정한다.
- **구현**: 가맹점 제안·종목 검색 엔드포인트(서버 계산), 대기열 저장소와 응답 표, `use-funnel`의 React Navigation 지원 확인, true-sheet 채택, 빠른 동작(expo-quick-actions 류), 콜드 스타트 자체 표식, 미국 주간거래 체결일 확인, 총액 입력의 단가 자릿수.
- **정식 출시 준비**: App Store 접근성 라벨 4개 표시와 그 전 점검(로그인·온보딩 포함 VoiceOver 완주, 200% 글자), 콜드 스타트 출시 조건 두 줄을 출시 조건 목록에 넣는다.
