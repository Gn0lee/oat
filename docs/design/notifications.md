- [통계 화면 구성](stats-screens.md) 10절, [모바일 입력 UX 원칙](mobile-input.md) 14절, [가구원 나가기·계정 삭제](member-leave.md) 3절, [서버 아키텍처](server-architecture.md) 3절, [정기 수입/지출과 자동이체](https://github.com/Gn0lee/oat/issues/519)에서 넘긴 것을 정해요. 기존 oat의 알림 설계(`.claude/docs/NOTIFICATIONS.md`)는 지금 앱의 경험을 파악하는 데만 참고했어요.

## 1. 한 장 요약

| 항목 | 결정 |
|---|---|
| 성격 | **할 일 알림**만 보내요. 사건(누가 무엇을 했다)을 알리는 소식 알림은 보내지 않고, **알림함은 두지 않아요**. 할 일을 다시 보는 곳은 홈 "확인할 것" 하나예요 |
| 횟수 | **아침 묶음**: 홈에 보이는데 아직 알리지 않은 할 일이 있는 날에만 오전 9시에 한 번. 알린 할 일은 키로 저장해서, 처리했다가 다시 열려도 두 번 울리지 않아요 |
| 예외 | 함께 쓰는 지갑 넘겨받음은 바로 따로 보내요. 보내지 못한 기록은 앱이 로컬 알림으로 알려요 |
| 문구 | 공용 장부 할 일이 **한 건뿐일 때만** 가맹점·금액을 넣어요. 여러 건이면 건수와 종류만, 개인 장부 할 일은 늘 건수만, 카드 청구서·카드대금은 공용 지갑이어도 금액을 넣지 않아요. 문구는 보내는 순간 남은 할 일로 다시 만들어요 |
| 수신 설정 | 스위치 하나 "할 일 알림 · 매일 오전 9시"(기본 켬, 사용자 단위). 종류별·시간 고르기는 나중에 더할 수 있게 저장과 작업 모양만 열어 둬요 |
| 권한 요청 | 할 일이 처음 생기는 순간(첫 정기 규칙, 결제일 있는 첫 카드 지갑)에 우리 시트로 먼저 묻고, `알려 주세요`일 때만 iOS 권한 창 |
| 누르면 | 한 건이면 그 확인 화면, 여러 건이면 홈 "확인할 것". 페이로드는 `{ kind, id, member }`만, 받는 사람 ≠ 지금 로그인한 사람이면 홈 |
| 발송 경로 | worker가 **APNs에 직접**(`apns2`, .p8 키). Android 이식 때 같은 worker에 FCM HTTP v1. Expo Push는 쓰지 않아요 |
| 기기 토큰 | `push_devices` 행을 **세션에 매달아요**(세션 삭제 CASCADE). 토큰 유니크, 포그라운드마다 다시 등록, 410·`UNREGISTERED`면 삭제 |
| 서버가 멈췄다면 | 9시를 놓친 묶음은 살아난 뒤 첫 정각에 그때 상태로 세어 보내요. 21시가 지났으면 다음 날로. 지갑 넘겨받음은 24시간 지나면 보내지 않아요 |
| 배지 | 쓰지 않아요 |

## 2. 할 일 알림만 보내는 이유

알림은 두 종류예요.

- **할 일**: 서버 상태에서 계산돼요(예정일이 됨, 청구서 확정을 기다림). 할 일이 끝나면 알림도 의미가 없고, 다시 볼 곳은 상태를 다시 계산해 보여주는 홈 "확인할 것"이에요.
- **소식**: 누가 무엇을 했다는 사건이에요(배우자가 공용 지출을 기록, AI가 기록을 바꿈). 지나간 소식을 다시 보려면 쌓아 두는 알림함이 필요해요.

할 일만 보내면 사용자가 할 일을 보는 곳이 "확인할 것" 하나라서 알림함과 두 군데에 같은 일이 쌓이지 않아요(One Thing). 푸시가 실패하거나 서버가 멈춰도 "확인할 것"은 상태에서 다시 계산되니 잃는 게 없어요. 알림함 테이블·읽음 상태·지난 알림 정리도 만들지 않아요. 사례 조사는 알림함을 권했지만(서버 정지 대비, 배지 숫자, 소식 다시 보기), 앞의 둘은 "확인할 것"이 해결하고 소식은 보내지 않아서 받아들이지 않았어요(ADR 0029).

| 후보 | 결정 |
|---|---|
| 확인 기다리는 예정, 청구서 확정, 실제 금액 확인, 연결 대기 정산, 30일 넘은 받을 돈 | 아침 묶음(3절) |
| 카드 결제일 | 카드대금 예정이 결제일 당일 아침 묶음에 "예정"으로 들어가요(금액 없음). 전날 알림은 따로 두지 않아요(통장에서 자동으로 빠지니까) |
| 함께 쓰는 지갑 넘겨받음 | 바로 보내요. 홈 "확인할 것"에 `확인` 한 번으로 사라지는 항목도 둬요(소식이지만 받은 사람이 할 일: 보관할지 정하기) |
| AI가 바꾼 기록 | 보내지 않아요. 사용자가 AI에게 시킨 일이고, 설정 → AI 연결 → "AI가 바꾼 기록"에서 봐요([MCP](mcp.md) 4.2) |
| 가구원이 남긴 공용 기록 | 보내지 않아요. 기록 탭의 "새로" 표시는 디자인 스펙에서 정해요 |
| 보내지 못한 기록 | 앱의 로컬 알림(8절) |
| 가구원 활동 묶음, 주간 요약, 큰 지출 | 나중에 검토해요(알림함이 없는 이번 범위 밖, 사례에서도 기본 꺼짐이 많음) |

알림은 모두 서비스 정보라서 정보통신망법 제50조의 광고성 정보가 아니에요(야간 별도 동의 대상 아님). 홍보 문구를 한 줄이라도 섞으면 그 알림 전체가 광고가 되므로 섞지 않아요. App Store 4.5.4도 같아요.

## 3. 아침 묶음

### 3.1 새 할 일과 알린 할 일 키

할 일 대부분은 저장된 행이 아니라 계산값이에요(예정, ADR 0008). 그래서 "언제 생겼나"를 따지지 않고, **지금 홈 "확인할 것"에 보이는데 아직 알리지 않은 것**을 새 할 일로 봐요. 알린 할 일은 멤버마다 키로 저장해요(`notified_todos`).

| 할 일 | 키 | 홈 위치 |
|---|---|---|
| 확인 기다리는 예정(자동 기록 실패 포함) | `occ:{규칙}:{원래 회차 날짜}` | 확인할 것 |
| 카드대금 예정(결제일 당일) | `cardpay:{지갑}:{이용기간 끝 날짜}` | 확인할 것 |
| 배당 예정 | `div:{배당 이벤트}:{증권 계좌}` | 확인할 것 |
| 청구서 확정 | `bill:{지갑}:{이용기간 끝 날짜}` | 확인할 것 |
| 실제 금액 확인(추정 기록 날짜 + 3일부터) | `est:{기록}` | 확인할 것 |
| 연결 대기 정산 | `unlinked:{줄}` | 확인할 것 |
| 받을 돈(예상 정산·혜택이 **30일 넘게** 남음) | `recv30:{기록}` | 받을 돈 카드 |
| 함께 쓰는 지갑 넘겨받음 | `handover:{지갑}:{넘겨받은 시각}` | 확인할 것 |

- **키는 흔들리지 않는 값으로 만들어요.** 예정은 공휴일로 옮기기 전의 원래 회차 날짜, 청구서와 카드대금은 결제일이 아니라 이용기간 끝 날짜를 써요. 결제일을 바꾸거나 공휴일 규칙이 바뀌어도 같은 할 일은 같은 키예요. 청구서 확정과 카드대금 예정은 다른 날 생기는 다른 할 일이라 키를 나눠요.
- 받을 돈은 "30일째"가 아니라 "30일 넘게 아직 예상 상태"예요. 서버가 그날을 놓쳐도 다음 날 잡혀요.
- **한 번 알린 할 일은 다시 알리지 않아요.** 처리해서 목록에서 빠져도 키를 바로 지우지 않으니, 건너뛴 예정을 되돌리거나 숨긴 지갑을 다시 보이게 해서 같은 할 일이 다시 열려도 울리지 않아요(되돌린 사람이 이미 알아요). 홈 "확인할 것"에는 보여요. 키는 **지금 할 일 목록에 없고 알린 지 90일이 지난 것**만 worker가 지워요.
- 세는 범위는 받는 사람이 **볼 수 있는 장부**예요(권한 모듈의 접근 문맥). 공용 장부의 할 일은 가구원 모두에게, 개인 장부의 할 일은 주인에게만 세요. 먼저 처리한 사람이 있으면 그때 목록에서 빠져요.
- **알리지 않아도 키는 넣어요.** 스위치를 꺼 둔 사람, 기기가 없는 사람도 매일 키를 쌓아요. 나중에 켜거나 앱을 처음 설치해도 밀린 할 일이 한꺼번에 울리지 않아요. 같은 이유로 새 가구원이 들어올 때, 나갔던 사람이 돌아올 때, 기존 데이터 전환 때는 그 순간의 할 일 키를 보내지 않고 채워 둬요.
- 키에 개인 장부 기록 id가 들어가서 `notified_todos`는 가구 소유 테이블(RLS)이에요. 나가기 때 그 멤버의 키를 지우고(돌아오면 다시 채움), 가구 삭제 때 함께 지워요. 내 데이터 내려받기에는 넣지 않아요.

### 3.2 언제 보내나

```
매시 00분 worker (pg-boss 스케줄)
 └ 가구마다 app 롤 + 가구 설정으로
    └ 활동 멤버 중 지금 ≥ 받을 시각(9시) 이고 < 21시인 사람마다, 트랜잭션 하나:
       ├ 오늘 몫 가져가기: UPDATE … SET last_digest_on = 오늘
       │                  WHERE last_digest_on IS DISTINCT FROM 오늘 RETURNING
       │                  (0행이면 이미 다른 실행이 가져감 → 끝)
       ├ 지금 할 일 목록 − 알린 키 = 새 키
       ├ 새 키를 notified_todos에 넣기 (스위치·기기와 관계없이)
       └ 스위치 켜짐 + 새 키 있음 → 기기마다 발송 작업 예약 { member, device, keys }
```

- 작업은 **처음부터 매시 도는 모양**이에요. 지금은 모두 9시라 9시에만 실제로 보내지만, 받을 시각을 고르게 할 때(4절) worker를 바꾸지 않아요.
- 하루 한 번은 조건부 UPDATE로 지켜요. 두 실행이 겹쳐도 하나만 오늘 몫을 가져가요. 발송 작업의 pg-boss `singletonKey`는 `digest:{member}:{device}:{날짜}`예요(기기마다 하나). 작업은 최소 1회 실행이라고 봐요(서버 아키텍처 27번).
- 작업 데이터에는 **문구를 넣지 않아요.** 보내는 순간 `keys` 중 아직 지금 할 일 목록에 있는 것만 남기고, 그 남은 것으로 3.3 규칙에 따라 문구를 다시 만들어요. 0건이면 보내지 않아요. 그사이 배우자가 처리했거나 공용 장부가 개인 장부로 바뀌어도 옛 문구가 나가지 않아요.
- **서버가 멈춰 9시를 놓쳤으면** 살아난 뒤 첫 정각에 그때 상태로 세어 보내요. 21시가 지났으면 그날은 세지 않고 다음 날 9시 묶음이 두 날의 새 할 일을 함께 세요. 밀린 알림을 쌓아 두지 않으니 옛 숫자를 보낼 일이 없어요.
- 21시~9시 사이에 생긴 할 일은 다음 날 아침 묶음으로 가요. 조용한 시간 설정을 따로 두지 않는 이유예요.
- **함께 쓰는 지갑 넘겨받음**은 나가기 트랜잭션에서 받는 멤버의 `handover:` 키를 미리 넣고 바로 발송 작업을 예약해요. 그래서 다음 아침 묶음에 다시 들어가지 않아요.
- **알려진 한계**: 해외에 있는 사람도 서울 9시에 받아요(현지 새벽일 수 있음). 나중에 기기 시간대로 맞출 수 있게 `push_devices.timezone`을 지금부터 저장해요.

### 3.3 문구

| 경우 | 문구 예 |
|---|---|
| 공용 장부 예정 한 건 | "넷플릭스 17,000원 · 오늘 예정이에요" |
| 카드대금 예정 한 건 | "카드대금 1건이 오늘 나가요"(카드 이름·금액 없음, 공용 지갑이어도 같음) |
| 배당 예정 한 건 | 공용 장부 증권 계좌면 "삼성전자 배당 12,000원 · 오늘 예정이에요", 개인 장부 계좌면 "내 배당 예정 1건이 있어요" |
| 공용 장부 실제 금액 확인 한 건 | "스타벅스 · 실제 출금액을 넣어 주세요"(추정 금액은 넣지 않음) |
| 개인 장부 할 일 한 건 | "내 예정 1건을 확인해 주세요" |
| 카드 청구서 확정 한 건 | "카드 청구서 1건이 확정을 기다려요"(카드 이름·합계 없음) |
| 받을 돈 한 건(공용) | "회사 · 받을 돈이 30일 넘었어요"(상대 이름만) |
| 여러 건 | "확인할 것 3건 · 예정 2건, 청구서 1건" |
| 지갑 넘겨받음 | "함께 쓰던 지갑 1개를 넘겨받았어요"(지갑 이름·보낸 사람 없음) |

- 잠금화면은 옆의 가족이 가장 쉽게 보는 곳이고, 개인 장부는 바로 그 가족에게 숨기는 기록이에요. 그래서 기준은 "받는 사람이 볼 수 있는 것"이 아니라 **가구원 모두가 이미 보는 것**이에요. 공용 장부 한 건은 가족이 어차피 같이 보는 기록이라 새는 게 없어요.
- 카드 청구서는 지갑 단위라서 공용 지갑이어도 다른 가구원의 개인 기록이 합계에 섞여 있을 수 있어요(ADR 0025). 합계도 넣지 않아요. 카드대금 예정도 그 청구서 금액이라 같아요. 배당은 증권 계좌 하나가 장부 하나에 묶여서(ADR 0009) 공용 장부 계좌일 때만 금액을 넣어요. ADR 0025의 "알림 문구는 청구서 합계만"을 "알림에는 청구서 합계도 넣지 않는다"로 좁혔어요.
- 금액 보이기 설정은 두지 않아요. 미리보기를 숨기고 싶은 사람은 iOS의 "미리보기 표시: 잠금 해제 시"를 써요.
- 최종 문구 다듬기는 디자인 스펙에서 해요. 위 규칙(무엇을 넣지 않는가)은 바꾸지 않아요.

## 4. 수신 설정

- 설정 → 알림에 **스위치 하나**: "할 일 알림 · 매일 오전 9시"(기본 켬). 함께 쓰는 지갑 넘겨받음도 이 스위치를 따라요. 사용자 단위라 모든 기기에 같이 적용돼요.
- 종류를 빼면 홈 "확인할 것"과 알림 숫자가 달라져서 종류별 스위치를 두지 않아요. 시간도 9시로 고정해요.
- **나중에 더하기 쉽게**: 설정은 `household_members.notify_prefs`(jsonb) 묶음으로 저장해요. `{ "version": 1, "todo": true }`. 종류별은 `kinds`, 시간은 `time` 키를 더하면 되고 없는 키는 기본값으로 읽어요(`home_layout`과 같은 규칙). 아침 작업은 이미 매시 도는 모양이에요(3.2).
- iOS 권한이 꺼져 있으면 스위치 자리에 "iOS 설정에서 알림을 켜야 해요"와 `설정 열기`를 보여줘요.
- 앱 아이콘 배지는 쓰지 않아요. 푸시가 올 때만 바뀌어서 배우자가 낮에 처리해도 숫자가 남고, 빨간 숫자는 부담을 줘요. 필요하면 페이로드 `badge`와 앱을 열 때 `setBadgeCountAsync`로 더해요.

## 5. 권한 요청

- iOS 권한 창은 한 번만 뜨고, 거절하면 앱이 다시 띄울 수 없어요. 그래서 **할 일이 처음 생기는 순간**에 우리 시트로 먼저 물어요.
  - 계기: 정기 규칙을 처음 저장했을 때, 결제일이 있는 카드 지갑을 처음 만들었을 때.
  - 시트: "예정일 아침 9시에 알려 드릴까요?" `알려 주세요` / `나중에`. `알려 주세요`일 때만 iOS 권한 창을 띄워요. `나중에`는 다음 계기에 다시 물어요.
- 첫 실행·온보딩에서 묻지 않아요. 조용한 허락(provisional)도 쓰지 않아요(소리·배너가 없어 아침 묶음의 뜻이 약해져요).
- 허락하면 바로 기기 토큰을 등록해요(7절).

## 6. 누르면 어디로

| 알림 | 누르면 |
|---|---|
| 할 일 한 건 | 그 확인 화면(예정 확정·청구서 확정·실제 출금액 넣기·받을 돈) |
| 할 일 여러 건 | 홈, "확인할 것" 카드로 스크롤 |
| 지갑 넘겨받음 | 한 개면 그 지갑, 여러 개면 자산 탭 |
| 보내지 못한 기록(로컬) | 기록 탭 맨 위 `보내는 중` 줄 |

- 페이로드에는 화면 주소가 아니라 `{ kind, id, member }`만 넣고, 앱이 화면으로 바꿔요(얇은 클라이언트, ADR 0011).
- 그사이 다른 가구원이 처리했으면 토스트 "이미 확인됐어요"와 홈.
- 세션이 끝났으면(401) 로그인 뒤 원래 가려던 화면으로 이어가요.
- `member`가 지금 로그인한 사람의 멤버 행이 아니면(계정·가구가 바뀜) 알림을 버리고 홈으로 열어요. 이 비교는 **누를 때만** 쓸모 있어요. 앱이 꺼져 있을 때 온 알림은 iOS가 그대로 띄우므로, 잘못 가는 것 자체는 7.2의 로그아웃 처리로 막아요.
- 꺼진 앱에서 누른 경우는 `expo-notifications`의 마지막 응답(`useLastNotificationResponse`)으로 받아요.

## 7. 발송 경로와 기기 토큰

```
worker ──(토큰 + 문구, .p8 키로 서명한 JWT)──▶ APNs ──▶ 폰
   ▲                                             │
   └──── 410 Unregistered ◀──────────────────────┘ → push_devices 행 삭제
```

### 7.1 APNs 직접

- Expo Push는 Expo 프로젝트(`projectId`)와 APNs 키 업로드가 필요하고 문구가 Expo 서버를 거쳐요. EAS를 쓰지 않는 전제와 부딪히고, 실패 확인도 15분 뒤 따로 해야 해요(결과는 24시간 뒤 사라짐). 그래서 직접 보내요.
- 앱은 `getDevicePushTokenAsync`로 기기 토큰을 받아요. iOS는 APNs 토큰, Android는 FCM 등록 토큰이라 앱 코드는 하나예요.
- 서버 라이브러리는 `apns2`(TypeScript)를 먼저 쓰고, 안 되면 `@parse/node-apn`을 써요. .p8 키·Key ID·Team ID는 서버 시크릿이에요.
- 보내는 값: `apns-push-type: alert`, 중요도 `active`(시간 민감 알림은 쓰지 않음), `thread-id` = 알림 종류, `apns-collapse-id` = 묶음이면 `digest:{날짜}`, `apns-expiration` = 묶음은 그날 21시, 지갑 넘겨받음은 24시간 뒤. APNs가 폰이 꺼진 동안 들고 있다가 늦게 띄우는 것도 같은 기준으로 막아요.
- 실패: 410이나 400 `BadDeviceToken`이 아닌 실패(429·5xx·네트워크)는 pg-boss 재시도(늘어나는 간격)로 `apns-expiration` 전까지만 다시 보내요. 400 `BadDeviceToken`은 sandbox·production 토큰이 섞였는지 먼저 의심하고 로그를 남긴 뒤 그 행을 지워요(폰이 다음 포그라운드에 다시 등록해요).
- Android 이식 때 FCM HTTP v1을 같은 worker에 더해요(`UNREGISTERED`면 삭제). 알림 채널은 만든 뒤 동작을 바꿀 수 없어서, 이식 전에 "할 일"·"보내지 못한 기록" 두 채널로 정해 둬요.
- 운영: 아침 묶음 작업의 성공을 Healthchecks.io로 확인하고, 발송 실패율이 높으면(키 만료·인증서 문제) 운영자에게 알려요([셀프호스팅 운영](../research/2026-11-11-self-hosting-ops.md) 4절).

### 7.2 기기 토큰은 세션에 매단다

- `push_devices` 행은 `session_id`를 갖고 **세션 삭제 FK CASCADE**예요. 그래서 로그아웃, 나가기·내보내기(세션 전부 삭제), 계정 삭제(user → session CASCADE)에서 따로 짤 것 없이 토큰이 사라져요. 발송 때는 세션 만료 시각도 함께 봐서 60일 안 쓴 세션의 기기에는 보내지 않아요.
- 앱은 **포그라운드마다** 세션 확인과 함께 토큰을 다시 등록해요(토큰을 캐시하지 말고 매번 등록하라는 Apple 권장, 백업 복원·새 기기에서 토큰이 바뀜).
- `token`은 유니크예요. 한 폰에서 계정을 바꾸면 같은 토큰이 다른 세션으로 등록되므로 앞 행을 지우고 새로 넣어요. 그 폰에는 지금 로그인한 사람의 알림만 와요.
- **로그아웃은 폰에서 먼저 끊어요.** 앱이 `unregisterForNotificationsAsync`로 이 앱의 원격 알림 등록을 끊은 뒤 서버에 로그아웃을 보내요. 오프라인이라 서버 요청이 실패하면 다음 실행 때 다시 보내요. 서버 행이 남아 있어도 끊긴 토큰은 APNs가 410으로 돌려줘서 지워져요. 다시 로그인하면 토큰을 새로 받아 등록해요.
- `timezone`(기기 시간대)을 등록 때 함께 저장해요. 지금은 쓰지 않고, 받을 시각을 현지 시간으로 맞출 때 써요(3.2).
- `env`(`sandbox`·`production`)를 저장해요. Xcode 디버그 빌드는 sandbox 토큰, TestFlight·App Store는 production 토큰이라 엔드포인트를 골라야 해요.
- 지운 기기(로그아웃한 폰)로는 아무것도 가지 않아요. 기기 목록 화면은 두지 않아요.

## 8. 보내지 못한 기록의 로컬 알림

iOS는 백그라운드 앱이 자유롭게 다시 보내게 하지 않아서, 지하에서 적고 앱을 닫으면 다시 열 때까지 기록이 폰에 남아요([모바일 입력 UX 원칙](mobile-input.md) 10절).

- 앱이 **백그라운드로 갈 때 대기열(보내는 중 + 보내지 못한 기록)이 있으면 1시간 뒤 로컬 알림**을 하나 예약해요. 식별자를 고정해 다시 예약하면 덮어써요.
- 문구: "아직 보내지 않은 기록 2건이 있어요. 열면 보낼게요". 내용(금액·가맹점)은 넣지 않아요.
- 앱을 열어 대기열이 비면 예약을 취소해요. 1시간 뒤에도 안 열면 더 보내지 않아요(한 번만).
- "할 일 알림" 스위치를 따르지 않고 iOS 권한만 따라요. 편의 기능이 아니라 기록이 폰에만 있다는 안전장치라서요. 권한이 없으면 보내지 않아요.
- 로그아웃·다른 사용자 로그인으로 대기열을 지우면 예약도 취소해요.

## 9. 스키마 변경

[물리 DB 스키마](physical-db-schema.md)에 반영했어요.

- `household_members.notify_prefs`(jsonb, NULL이면 기본값 `{ version: 1, todo: true }`), `last_digest_on`(date, 오늘 몫을 가져간 서울 날짜). 계정 삭제 때 비우고, 내 데이터 내려받기에 설정만 넣어요.
- **`notified_todos`**(가구 소유, RLS): `household_id`, `member_id`(→ 멤버 행), `key`(3.1의 키), `notified_at`. PK `(member_id, key)`. 나가기 때 그 멤버 행을 지우고 가구 삭제 때 함께 지워요. 알린 지 90일이 지났고 지금 할 일 목록에 없는 키는 worker가 지워요.
- **`push_devices`**(가구 소유 아님, RLS 없음): `id`, `user_id`(→ `user` CASCADE), `session_id`(→ `session` CASCADE), `token`(유니크), `platform`(`ios`·`android`), `env`(`sandbox`·`production`), `timezone`, `app_version`, `created_at`, `last_seen_at`. api 롤이 등록·삭제하고 worker 롤이 읽고 지워요.
- 지갑 넘겨받음은 지갑 쪽 두 칸으로 표시해요: `wallets.handed_over_at`(넘겨받은 시각, 나가기 트랜잭션이 채움)과 `handover_ack_at`(받은 사람이 `확인`을 누르면 채움). "확인할 것" 항목은 `handed_over_at IS NOT NULL AND handover_ack_at IS NULL AND 주인 = 나`예요. `erasure_log`는 백업 복원용이라 화면 판정에 쓰지 않아요.

## 10. 구현 때 통합 테스트

- 가구원 A·B 시점: B의 개인 장부 예정은 A의 묶음 숫자에 들어가지 않는다. A의 공용 장부 한 건 문구에만 가맹점·금액이 있고, 개인 장부·카드 청구서 문구에는 금액이 없다.
- 공용 예정을 B가 9시 전에 확정하면 A의 묶음에서 빠진다(0건이면 보내지 않음). 카드대금 예정 한 건과 개인 장부 증권 계좌의 배당 예정 한 건 문구에 금액이 없다.
- 같은 날 매시 작업이 여러 번 돌거나 동시에 돌아도 기기마다 한 번만 보낸다. 9시~12시에 서버를 멈추면 12시에 한 번, 21시 이후 재시작이면 그날은 보내지 않고 다음 날 두 날 치를 센다.
- 알린 할 일 키: 건너뛴 예정을 되돌려도 다시 보내지 않는다. 공휴일 조정·결제일 변경 뒤에도 같은 할 일이 두 번 울리지 않는다. 받을 돈은 30일째 날 서버가 멈춰도 다음 날 묶음에 들어간다. 스위치를 껐다 켜거나, 새로 들어오거나 돌아온 가구원의 첫 묶음에 밀린 할 일이 없다. 발송 작업 예약 뒤 할 일이 처리되면 남은 것으로 문구가 바뀌고, 0건이면 보내지 않는다. B의 개인 장부 키는 A의 앱 롤로 읽히지 않는다(RLS).
- 지갑 넘겨받음은 바로 한 번 오고, 다음 아침 묶음에 다시 들어가지 않는다. `확인`을 누르면 "확인할 것"에서 빠진다.
- 로그아웃·나가기·계정 삭제 뒤 `push_devices` 행이 없다. 오프라인에서 로그아웃하면 폰의 원격 알림 등록이 끊기고 다음 실행 때 서버 로그아웃이 다시 간다. 한 폰에서 계정을 바꾸면 토큰 행이 새 사용자 것 하나뿐이다.
- 410을 받으면 행이 지워지고, 5xx는 `apns-expiration`까지만 재시도한다.
- 꺼진 앱에서 알림을 누르면 확인 화면이 열린다(시뮬레이터 `simctl push`). 다른 멤버의 알림을 누르면 홈이 열린다.
- 대기열이 있는 채로 백그라운드에 가면 로컬 알림이 1시간 뒤로 하나 예약되고, 다 보내면 취소된다.

## 11. 다른 티켓에 넘기는 것

- **디자인 스펙(디자인 그릴링)**: 권한 요청 시트, 설정 → 알림 화면, 알림 문구의 최종 다듬기(3.3의 규칙 안에서), 홈 "확인할 것"의 지갑 넘겨받음 항목, 기록 탭의 가구원 새 기록 "새로" 표시 여부.
- **정식 출시 준비**: 유료 Apple 개발자 계정과 APNs .p8 키 발급, 실기기에서 원격 푸시 확인(sandbox·production 둘 다), 개인정보처리방침에 기기 토큰 수집 고지, Android 이식 때 FCM 프로젝트와 알림 채널 두 개.
- **구현**: `apns2`의 Node 버전 요구 확인, Notification Service Extension은 쓰지 않음(필요해지면 CNG 설정 플러그인 확인), 시간 민감 알림 엔타이틀먼트는 쓰지 않음.
- **나중에 검토**: 가구원 활동 묶음, 주간 요약, 큰 지출 알림, 종류별 스위치, 받을 시각 고르기, 앱 아이콘 배지, 알림에 금액 보이기 설정.
