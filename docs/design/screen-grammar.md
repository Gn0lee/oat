# 화면 문법

- 결정일: 2026-11-26
- 티켓: [주요 화면 시안: 홈·분석·자산·투자·입력 퍼널·나만 보기](https://github.com/Gn0lee/oat/issues/538)
- 관련 ADR: 0035(카드는 요약 화면에만, 나머지는 평면과 띠), 0036(화면 뼈대와 부품 목록은 닫혀 있다), 0033(숫자 색), 0031(숨긴 지갑), 0027(입력 퍼널)
- 토큰: [DESIGN.md](DESIGN.md) (색·글자·간격·모서리·컴포넌트 값)
- 전제: [통계 화면 구성](stats-screens.md), [모바일 입력 UX 원칙](mobile-input.md), [숨긴 지갑과 공용 장부 기록](hidden-wallets.md), [브랜드](brand.md)
- 조사·시안: [화면 문법 사례·원칙 조사](../research/2026-11-26-screen-grammar-cases.md), [화면 문법 PoC](../research/2026-11-26-screen-mockups-poc.md)

이 문서는 화면 하나하나의 배치가 아니라 **어느 화면을 그려도 같은 앱처럼 보이게 하는 규칙**이다. 화면별 세부(여백 미세 조정, 문구 다듬기)는 구현 때 이 규칙 안에서 정한다. 시안은 규칙이 통하는지 보는 예시다.

## 0. 한 장 요약

| 항목 | 결정 |
|---|---|
| 면 | 요약 화면(홈·자산 탭)만 회색 바탕 + 주제마다 흰 카드. 나머지는 흰 평면이고 주제가 크게 바뀌면 회색 띠 16 |
| 홈 위계 | 큰 숫자는 맨 위 카드에만. 다른 카드는 17pt 줄로 가볍게. 한 줄 정보는 카드 없이 바탕 위에 |
| 뼈대 | 요약·목록·리포트/상세·퍼널 질문·확인·시트 6종. 화면마다 주인공 하나 |
| 부품 | 18개로 닫음. 새 부품은 DESIGN.md에 먼저 더함 |
| 목록 줄 | 왼쪽 이름·보조 줄, 오른쪽 금액·보조 값. 아이콘 없음. 배지와 🔒은 보조 줄 맨 앞 |
| 행동 | 화면에 보이게. 밀어서 삭제 없음. 칸을 눌러 고침. 나머지 행동은 맨 아래 섹션 |
| 상태 | 배지 세 갈래(중립·주의 주황·실패 빨강). 빈 상태는 그림 없이 한 줄 + 행동 하나. 저장된 값 먼저, 스피너 없음 |
| 말투 | 해요체, 짧은 동사 버튼, 사람 탓 안 함, 가구원 문구 중립, 설정 이름은 문장에서 동사로 |

## 1. 면

### 1.1 카드는 요약 화면에만

- **요약 화면(홈·자산 탭)**: 회색 바탕(`background`) 위에 주제마다 흰 카드(`card`). 바깥 12, 안 20, 카드 사이 12, 모서리 20(토스 홈 실측).
- **그 밖의 화면**(기록 목록·기록 상세·분석·투자·지갑·설정·입력 확인): 흰 평면(`surface`). 카드를 쓰지 않는다.
- 카드 안에 카드를 넣지 않는다. 목록의 줄마다 카드를 씌우지 않는다.
- 카드 안 목록은 3줄까지, 넘치면 `N건 더 보기`.
- 근거: 토스·카카오뱅크·현대카드 홈은 모두 회색 바탕 위 카드를 연달아 쓴다(사용자 캡처). 같은 종류가 반복되는 목록은 카드가 아니라 목록이다(Material, NN/g). 기존 oat는 카드를 너무 많이 써서 어색했다.

### 1.2 평면 화면

- **상단 바는 회색 바탕 위**에 있고, 흰 면은 내용부터 시작한다(토스 통장 화면).
- **띠**(`band`, 16, `background` 색)는 **주제가 크게 바뀔 때만** 넣는다. 띠 사이에는 줄 3개 이상이나 섹션 제목이 있어야 한다. 그보다 짧으면 얇은 선이나 여백으로 나눈다. 띠가 잦으면 줄무늬처럼 보인다.
- **띠 아래에는 섹션 제목**(`footnote` 13, `text-sub`)을 둔다. 위 24, 아래 8. 맨 위 숫자 블록 바로 아래처럼 제목이 필요 없는 곳은 예외.
- **줄 사이에는 선을 긋지 않는 것이 기본**이다. 여백으로 나눈다. 한 줄짜리 줄이 길게 이어져 경계가 흐려지거나, 줄 안 요소가 많아 소속이 헷갈리면 선을 제안할 수 있다. 쓸 때는 **양쪽 24를 띄운** 1px `divider` 하나뿐이다. 띠 바로 위아래에는 선을 긋지 않는다.
- 좌우 여백은 24. 상단 바·섹션 제목·목록 줄의 글자가 같은 선에서 시작한다.
- iOS 설정 앱 같은 둥근 묶음(inset grouped)은 사실상 카드라 쓰지 않는다. 설정도 평면 + 띠다.

### 1.3 바탕색

- 바탕은 디자인 토큰의 귀리 회색 `#F4F5F3`을 그대로 쓴다. 토스 `#F2F4F6`(푸른 회색), Pine 회색 `#F0F5F3`, Linen `#EFECEA`와 나란히 비교했고, 처음의 어색함은 색이 아니라 구조(흰 상단 바, 잦은 띠, 제목 없는 띠) 때문이었다.

## 2. 홈 위계

- **맨 위 숫자 카드만 무겁다.** 큰 숫자(`amount-hero` 32)는 이 카드에만 있다.
- **다른 카드는 가볍다.** 제목 대신 숫자가 앞에 오는 17pt 줄(`1,120,000원` / `곧 나갈 돈 3건`)이고, 대표 행동은 알약 하나(`확정`·`보기`).
- **한 줄로 끝나는 정보는 카드로 만들지 않는다.** "눈에 띄는 것"은 맨 위 숫자 카드 바로 아래 바탕 위 한 줄이다(누르면 분석 탭). 홈 편집의 켜고 끄기는 그대로.
- "있을 때만" 카드(확인할 것·받을 돈)는 할 일이 생길 때만 나타난다. 평소 홈은 숫자 카드 + 곧 나갈 돈 1장이고, 바쁜 날은 많아야 4장이다.
- 분산은 카드 수가 아니라 위계로 막는다. 같은 무게의 상자가 반복되면 시선이 흩어진다(NN/g 시각 위계·공통 영역).
- 주인공 카드에 색조를 입히는 것(카카오뱅크)은 보류한다. Pine은 큰 면에 쓰지 않고, 크기 위계로 부족하면 그때 본다.
- **자산 탭**도 요약 화면이라 같은 규칙이다. 순자산 합계 줄이 없어서(ADR 0016) 큰 숫자 카드 없이 묶음별 잔액 카드 1장과 월별 자산 추이 카드 1장이다. 묶음 금액은 `amount-hero`(디자인 토큰)이고, 묶음을 누르면 그 묶음의 평면 화면으로 간다.

## 3. 화면 뼈대

새 화면은 이 6종 중 하나에 내용을 채운다. 안 맞으면 틀을 늘리기 전에 기존 틀로 풀 수 있는지 먼저 본다.

| 뼈대 | 쓰는 곳 | 주인공 | 면 |
|---|---|---|---|
| ① 요약 | 홈, 자산 탭 | 맨 위 카드(홈은 숫자, 자산 탭은 묶음별 잔액) | 회색 바탕 + 카드 |
| ② 목록 | 기록 탭, 지갑 내역, 종목 목록, 검색 결과 | 날짜·묶음별 줄 목록 | 평면 |
| ③ 리포트·상세 | 분석, 투자, 기록 상세, 지갑 상세, 묶음 상세 | 맨 위 숫자 블록 | 평면 + 띠 |
| ④ 퍼널 질문 | 입력 한 단계 | 질문 하나(`title-1`) | 평면 |
| ⑤ 확인 | 입력 마지막, 예정 고쳐서 확정 | 금액 | 평면 + 아래 고정 버튼 |
| ⑥ 시트 | 한 칸 고르기·고치기, 확인 시트 | 질문과 고를 목록 | 가림막 위 시트 |

- **주인공은 하나**: 화면 맨 위에 가장 큰 것 하나(숫자 또는 질문). 토스 One Thing.
- **상단 바**: 탭 첫 화면은 왼쪽 큰 제목(`title-2`). 들어간 화면은 `‹` + 가운데 작은 제목. 입력 모달은 `✕`.
- **아래 고정 주 버튼**은 퍼널·확인 틀에만. 홈·기록 탭의 주 행동은 떠 있는 `+` 하나(모바일 입력 UX 원칙 1절).
- 퍼널의 고르는 단계는 버튼 없이 고르면 넘어간다. 시트는 한 겹(모바일 입력 UX 원칙 9절).
- 로그인·온보딩은 ④ 퍼널 질문 틀을 쓴다.

## 4. 부품

새 부품은 화면에서 바로 만들지 않고 [DESIGN.md](DESIGN.md) `components`에 먼저 더한다(ADR 0036).

| 묶음 | 부품 |
|---|---|
| 내용 | ① 숫자 블록(라벨 + 큰 숫자 + 비교 한 줄, 화면당 하나) · ② 섹션 제목 · ③ 목록 줄 · ④ 칸 줄(라벨 ··· 값 ›, 누르면 시트) |
| 면 | ⑤ 띠 · ⑥ 카드(요약 화면만) |
| 행동 | ⑦ 버튼 · ⑧ 칩 · ⑩ 스위치 · ⑪ 입력칸 · ⑫ 달 넘기기(`‹ 11월 ›`) · ⑭ 떠 있는 `+` |
| 표시 | ⑨ 배지 · ⑬ 토스트 |
| 틀 | ⑮ 시트 · ⑯ 탭 바 · ⑰ 키패드 · ⑱ 차트(페이스 선·가로 막대·쌓은 막대) |

### 4.1 버튼 위계

| 단계 | 모양 | 예 | 규칙 |
|---|---|---|---|
| 주 버튼 | Pine 면, 높이 56 | `저장`·`다음` | 화면당 하나, 아래 고정. 비활성은 `surface-alt` 면 + `text-disabled` |
| 보조 버튼 | 회색 면, 높이 56 | `저장하고 하나 더`, 확인 시트 `취소` | 주 버튼 위 |
| 알약 | 높이 36, 완전 둥글게 | `확정`·`보기` | 줄·카드 안 작은 행동. 대표 하나만 연한 Pine |
| 글자 버튼 | Pine 글자 | `더 보기`·`건너뛰기` | |
| 위험 | 빨강 글자 | `기록 삭제` | 빨강 면 버튼은 없다. 확인 시트를 한 번 거친다 |

### 4.2 칩과 배지

- **칩은 누를 수 있다**: 완전 둥근 알약 + 테두리. `전체 장부 ▾`, 통화 `원 ▾`, 범례, `🔒 내 장부`.
- **배지는 표시만 한다**: 모서리 6의 작은 네모, 테두리 없음. 모양으로 누를 수 있는지 안다.

## 5. 목록 줄

앱에서 가장 많이 반복되는 부품이다(기록 탭, 지갑 내역, 홈 카드, 검색).

| 자리 | 내용 | 글자 |
|---|---|---|
| 왼쪽 위 | 이름(가맹점·제목). 길면 한 줄 말줄임 | `body` 17 |
| 왼쪽 아래 | `카테고리 · 결제 칸("주인 · 지갑")` | `footnote` 13 `text-sub` |
| 오른쪽 위 | 금액. 말줄임하지 않는다 | `amount` 17 |
| 오른쪽 아래(있을 때) | 지갑 내역의 거래 후 잔액, 해외 결제의 외화 금액 | `footnote` 13 `text-sub` |

- **아이콘 자리를 두지 않는다**(토스 통장 내역처럼 글자만). 카테고리는 사용자가 만들어서 아이콘 세트를 관리하기 어렵고, 금액 열이 넓어진다.
- 금액 색·부호는 ADR 0033: 지출 무색 `−`, 수입 파랑 `+`, 환불·정산 무색 `+`.
- **이체**: 기록 탭(가구 전체 목록)에서는 부호 없이, 보조 줄에 `보내는 곳 → 받는 곳`. 지갑 내역에서는 그 지갑 기준 `+`/`−`.
- **배지**(추정·보내는 중)는 **보조 줄 맨 앞**. 금액 옆에 두지 않아 금액 열이 흔들리지 않는다.
- **내 개인 장부 기록**: 보조 줄 맨 앞에 자두색 `🔒 내 장부`(칩 바탕 없이 글자만). 본인 화면에만.
- **다른 가구원 화면**: 숨긴 지갑은 결제 칸이 "민호"만. 개인 기록 합계 줄은 `민호의 개인 기록 · 11월 합계`이고 색·자물쇠·`›`가 없고 누를 수 없다.
- **더 큰 텍스트(AX)**: 금액이 이름 아래로 내려간다(모바일 입력 UX 원칙 11.2).
- 최소 높이 56, 누르는 동안 `pressed` 덮개.

## 6. 행동을 두는 곳

1. **행동은 화면에 보이게 둔다.** 줄을 밀어야 나오는 삭제는 쓰지 않는다. 길게 누르기는 지름길이고, 같은 행동이 화면 어딘가에 꼭 보인다(VoiceOver 대체 동작, 모바일 입력 UX 원칙 11.1).
2. **고치기는 칸을 바로 누른다.** 기록 상세의 칸 줄을 누르면 그 칸만 시트로 열린다(확인 화면과 같은 부품). 오른쪽 위 `고치기`는 없다. 고칠 수 없는 칸은 `›`가 없고, 누르면 이유를 알려 준다(숨긴 지갑의 금액·날짜 등, 숨긴 지갑 7절).
3. **나머지 행동은 화면 맨 아래 섹션**에 모은다(`돌려받은 돈 기록`, `다시 기록`, 맨 끝 `기록 삭제`).
4. **오른쪽 위는 탭 첫 화면에만**, 아이콘 최대 2개(홈 프로필, 기록 검색·거르기). 들어간 화면은 비운다.

## 7. 상태 표시

### 7.1 배지 세 갈래

| 갈래 | 색 | 예 |
|---|---|---|
| 중립 | `surface-alt` 바탕 + `text-sub` | 보내는 중, 추정, 지난번과 같음 |
| 주의 | `warning-soft` 바탕 + `warning` 주황 | 시세 [지연], 갚기로 한 날 지남 |
| 실패 | `danger` 글자 + ⚠ | 보내지 못한 기록, 입력 오류 |

- 기한 지남에 빨강을 쓰지 않는다. 빨강은 상승 숫자와 삭제·오류의 색이고, 빌려준 돈의 기한은 사람 사이의 일이라 빨강이면 "연체·잘못"으로 읽힌다(토스는 "10일 지남"에 빨강).
- 숫자를 흐리게 하지 않는다(지연·보내는 중 모두, 통계 화면 구성 7절).

### 7.2 빈·로딩·오류

- **빈 상태**: 그림 없이 한 줄 + 행동 하나("아직 기록이 없어요 · 기록 추가"). 일러스트를 두지 않는다. 비교 기준이 없으면 그 줄을 숨기는 등 통계 화면 구성 9.1의 원칙은 그대로.
- **로딩**: 폰에 저장된 값이 있으면 바로 보여주고 뒤에서 새로 받는다. 저장된 값이 없는 처음 열 때만 회색 자리표시(`surface-alt`). 내용 위에 도는 스피너는 쓰지 않는다. 목록은 당겨서 새로고침.
- **오류**: 저장된 값이 있으면 그대로 두고 위에 한 줄 "11/26 09:12에 받은 내용이에요 · 다시 시도". 저장된 값도 없을 때만 화면 전체 "불러오지 못했어요 · 연결을 확인하고 다시 시도해 주세요 · `다시 시도`".

## 8. 말투

1. **해요체.** 느낌표를 쓰지 않는다.
2. **버튼은 짧은 동사**(`저장`, `확정`, `보이게 하기`). 확인 시트 제목은 질문("지수에게도 보이게 할까요?").
3. **사람 탓을 하지 않는다.** 막힐 때는 이유 한 문장 + 할 수 있는 길 하나. 규칙으로 막힌 것에는 경고 아이콘과 빨강을 쓰지 않는다.
4. **숫자 표기**: 금액 칸은 원 단위 전부(`12,800원`, 줄여 쓰지 않음). 문장 속은 만 단위(`12만 원 덜`). 날짜는 `11월 26일 수요일`, 좁으면 `11/26`. 시각은 `18:42`.
5. **가구원 문구는 중립**: 이름만 쓰고 "숨긴", "냄", "대신", "연체"를 쓰지 않는다(숨긴 지갑 5.3).
6. **가구원을 부르는 법**: 다른 가구원이 한 명이면 이름("지수에게는"), 두 명 이상이면 "다른 가구원에게는".
7. **설정 이름(명사)은 스위치 라벨에만** 쓰고, 문장 안에서는 동사로 풀어 쓴다. "나만 보기"는 라벨이고, 문장은 "나만 보게 할 수 없어요", "나만 볼 수 있는 지갑 만들기".

### 8.1 나만 보기 문구

- **확인 화면(주인)**: 낸 곳 아래 `ⓘ 지수에게는 결제가 '민호'로만 보여요`. 기록 상세에도 같은 줄.
- **지갑 설정의 스위치**: 라벨 `나만 보기`, 설명 "켜면 지수에게 이 지갑이 보이지 않아요".
- **막힘**: 스위치를 누르면 켜지지 않고 그 자리에서 이유가 펼쳐진다. 문구는 [숨긴 지갑](hidden-wallets.md) 6절의 이유별 문구이고, 전환한 지갑도 "기록이 있는 지갑" 문구로 다룬다([전환 당일 절차](cutover.md)). 아래에 길 하나 `나만 볼 수 있는 지갑 만들기 ›`.
- **보이게 바꾸기 확인 시트**: 제목 "지수에게도 보이게 할까요?", "보이게 하면 다시 나만 보게 할 수 없어요.", 드러나는 것 셋(지갑 이름·잔액·지난 달 자산 추이 / 공용 기록의 결제가 '민호 · 비상금 카드'로 / **이 지갑에 적은 내 장부 기록의 달마다 합계**). 버튼 `보이게 하기` / `취소`.
