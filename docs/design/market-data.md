## 1. 한 장 요약

| 데이터 | 초대제 단계 공급원 | 주기 | 저장 |
|---|---|---|---|
| 종목 마스터 | KIS 마스터파일(`kospi_code.mst`·`kosdaq_code.mst`·`nasmst.cod`·`nysmst.cod`·`amsmst.cod`) | 매일 08:00 KST | `securities`, `security_code_history` |
| 장중 현재가 | KIS REST(국내 멀티종목 30개 묶음, 해외 종목당 1건) | 정규장 동안 1분, 지금 보유 중인 종목만 | `security_live_quotes`(UNLOGGED) |

| 배당 일정 | KIS 국내 예탁원 배당일정, 해외 기간별 권리 | 매일, 추적 중인 종목만 | `dividend_events` |

- 기존 ExchangeRate-API는 쓰지 않는다. KIS 휴장일 API(`chk-holiday`)도 새 서버에서는 쓰지 않는다(3.2·3.4 참고).
- "시세 조회 MCP"는 택하지 않았다. MCP는 AI 클라이언트가 우리 서버를 쓰는 통로이고, worker가 정해진 시각에 부르는 공급원으로는 맞지 않는다.

## 2. 이용 권리(가장 큰 제약)

시세는 "받을 권리"와 "남에게 보여줄 권리"(표시·재배포 라이선스)가 따로 팔린다. 무료·저가 플랜은 거의 모두 본인 또는 사내 내부용이다. oat 서버가 받은 시세를 다른 가구의 앱에 띄우면 "남에게 보여주는 것"이다.

| 후보 | 다른 사용자에게 표시 | 비용 |
|---|---|---|
| KIS Open API(개인 앱키) | 금지: "개인의 업무에 한하여 이용 … 제3자에게 제공해서는 아니 된다"(고객 약관 제5조 ③). 계좌 보유 필수. 제3자 서비스는 법인 제휴 + 거래소·코스콤 정보이용계약 | 무료 |
| KRX 정보데이터시스템 Open API | 금지: 비상업 목적 한정(제6조), 제3자 제공 금지(제11조) | 무료 |
| data.go.kr 금융위원회 시세 | 공공누리 제4유형: 출처표시 + 비상업 + 변경금지. 상업 이용은 KRX Data Marketplace 유료 | 무료 |
| data.go.kr 배당·권리 일정(예탁원) | 공공누리 제2유형: 출처표시 + 비상업 | 무료 |
| 미국 표시 허용 플랜 | 허용: Tiingo 재배포 스타트업 등급(약 $250/월, 조건 서면 확인 필요), Massive Business·EODHD Enterprise($2,499/월) | 유료 |
| 한국은행 ECOS, 수출입은행 | 상업 이용·출처 표시 조건 원문 미확인(수출입은행은 data.go.kr 카탈로그에 "이용허락범위 제한 없음") | 무료 |

**결정(ADR 0019)**: 단계별로 간다.

1. **초대제(무료·비상업) 동안**: 운영자 한 사람의 KIS 앱키로 받는다. 제5조 ③과 부딪치는 회색지대라는 것을 알고 받아들인다. 지금 운영 중인 oat와 같은 위험 수준이다. data.go.kr 데이터를 쓰는 화면에는 출처를 표시한다.
2. **정식 출시 전**: 표시 라이선스가 있는 공급원으로 바꾼다. 이건 출시 준비의 조건이다. 국내는 KRX·코스콤 정보이용계약 또는 증권사 제휴, 미국은 Tiingo 재배포 등급 같은 플랜이다. 유료화를 시작하면 data.go.kr(비상업 조건)도 같이 바꾼다.
3. 교체는 시세 공급원 구현체를 바꾸는 일이고 테이블·화면은 그대로다(3절의 규칙이 이를 보장한다).

## 3. 시세 공급원 인터페이스

worker만 공급원을 부른다(서버 아키텍처 28번). 사용자 요청 중에는 외부 호출을 하지 않는다. 인터페이스는 데이터 종류마다 따로 두고, 종류별로 구현체와 대체 순서를 설정으로 고른다.

```ts
interface SecurityMasterSource { listSecurities(market): AsyncIterable<MasterRow> }
interface LiveQuoteSource     { getQuotes(securities): Promise<Quote[]> }            // price, asOf
interface DailyCloseSource    { getCloses(security, from, to): Promise<Close[]> }   // 현지 거래일, 원주가
interface DividendSource      { getEvents(security, from, to): Promise<DividendEvent[]> }
interface FxRateSource        { getDailyRates(pair, from, to): Promise<FxRate[]> }  // 고시일, 값

// 설정 예: closes: [kis, dataGoKr(KR만)] — 앞의 것이 실패하거나 빈 결과면 다음 것
```

### 3.1 공급원이 바뀌어도 값이 흔들리지 않게 하는 규칙

1. **DB에는 우리 모양만 저장한다.** 우리 코드, 원주가, 현지 거래일, 우리 유형 이름이다. 공급원 응답을 우리 모양으로 바꾸는 일은 그 공급원의 어댑터만 한다.
2. **코드 표기는 우리 것이 정본이다.** 같은 종목을 공급원마다 `BRK.B`·`BRK-B`·`BRK/B`처럼 다르게 쓴다. 공급원 표기와의 대응은 어댑터 안에서만 한다.
3. **종가는 원주가(수정 전 가격)다.** 기록의 수량은 분할 기록 전후로 실제 수량이라서, 월말 평가 "수량 × 종가"는 그날 찍힌 가격이어야 맞는다. 수정주가는 분할·배당 때 과거 값이 거꾸로 바뀌기도 한다. 원주가를 따로 주지 않는 공급원은 종가 공급원으로 쓰지 않는다(KIS `FID_ORG_ADJ_PRC=1`·`MODP=0`, Tiingo·EODHD는 `close`).
4. **배당 이벤트의 자연키는 우리 구분이다.** `(security_id, ex_date, kind)`이고 `kind`는 `regular`(일반)·`special`(특별)이다. 공급원의 이벤트 번호를 키에 넣으면 공급원을 바꿀 때 같은 배당이 두 번 생겨 제안이 중복된다.
5. **빈 값으로 기존 값을 덮지 않는다.** 미국 종목의 한글 이름("애플")은 KIS 마스터에서만 온다. 새 공급원에 한글 이름이 없으면 기존 값을 유지한다. 다른 칸도 마찬가지다.
6. **유형 대응은 어댑터 테스트로 지킨다.** 주식·ETF·ETN·REIT 등의 분류는 공급원마다 다르고, 거래세 세율이 유형에 따라 달라진다(`tax_rate_periods`). 어댑터마다 유형 대응 표의 테스트를 둔다.
7. **모든 행에 출처를 남긴다.** 이미 저장된 과거 종가·환율은 다른 출처의 값으로 덮어쓰지 않는다. 값이 다르면 로그에 남기고, 고치는 건 운영자가 한다.

### 3.2 추적할 종목

`system` 롤은 가구 소유 테이블을 읽지 못한다(물리 DB 스키마 6절). 그래서 worker가 "누가 무엇을 보유하나"를 직접 볼 수 없다. 대신 가구 소유가 아닌 **`security_tracking`** 표에 종목 단위로만 적는다. 어느 가구가 들고 있는지는 남기지 않는다.

- 칸: `security_id`(PK), `needed_from`(이 종목이 처음 나온 기록 날짜 중 가장 이른 날), `held_now`, `last_held_date`, `updated_at`.
- 매매 기록을 저장할 때 같은 트랜잭션에서 작업 "종목 추적 갱신(security_id, 기록 날짜)"을 예약한다. worker(`system`)가 `needed_from`을 더 이른 날로 당기면 그 구간을 백필한다.
- 매일 한 번 가구마다 `app` 롤로 보유 종목을 계산해 `held_now`·`last_held_date`를 다시 맞춘다(가구 횡단 작업의 정해진 방식).
- 현재가는 `held_now`인 종목만 받는다. 종가는 `held_now`인 종목을 매일 받는다(판 종목은 보유하던 구간의 종가가 이미 있다). 배당 일정은 `held_now`이거나 `last_held_date`가 최근 90일 안인 종목을 받는다(배당락일 뒤에 팔아도 배당을 받기 때문이다).

### 3.3 종목 마스터

- 자연키는 `securities (market, code)`이고 `market`은 `KR`·`US`다. 거래소(KOSPI·KOSDAQ·NYSE·NASDAQ·AMEX)는 속성이다. 미국 종목은 거래소를 옮겨도 같은 행이다. 기존 데이터의 `(market, ticker)`로 바로 찾는다.
- 칸을 더한다: `exchange`, `isin`(받을 수 있을 때만, KIS 국내 마스터의 표준코드. KIS 미국 마스터에는 없다), `name_en`, `listed`(상장 여부), `delisted_detected_at`.
- **사라진 코드**: 마스터에서 빠진 코드는 행을 지우지 않고 `listed = false`, `delisted_detected_at`을 채운다. 전역 행을 가리키는 FK는 RESTRICT다.
- **티커 변경**(FB → META): 자동으로 이어주지 않는다. 보유 중인 종목이 마스터에서 사라지면 worker가 운영자에게 알린다. 운영자는 같은 행의 `code`를 새 코드로 바꾸고, 옛 코드를 **`security_code_history`**(`security_id`, `market`, `code`, `valid_until`)에 남긴다. 마스터 동기화가 새 코드로 이미 만든 행이 있으면, 아무 기록도 그 행을 가리키지 않을 때 지우고 옛 행 하나로 합친다. 코드로 찾을 때는 `securities`를 먼저 보고, 없으면 이력을 본다. 나중에 ISIN을 주는 공급원으로 바꾸면 ISIN이 같은 행을 자동으로 잇는 것으로 바꿀 수 있다.
- **처음부터 마스터에 없는 종목**(이미 폐지된 종목으로 과거 매매를 입력하려는 경우): 초대제 단계에서는 운영자가 `listed = false` 행을 만든다. 전환에서는 기존 `stock_master` 사본에서 만든다(5절).
- KIS 국내 마스터의 그룹코드(ST·EF·EN·RT 등)와 미국 증권유형(2 주식·3 ETP)은 지금 oat의 `scripts/lib/mappings.ts`가 쓰는 대응을 출발점으로 한다.

### 3.4 장중 현재가

- 정규장 동안 1분 간격이다(국내 09:00~15:30 KST, 미국 09:30~16:00 미 동부). 넥스트레이드 시간외·미국 프리/애프터마켓은 넣지 않는다.
- 휴장일 달력은 따로 두지 않는다. 평일 정규장 시간에 부르고, 응답의 기준 시각이 바뀌지 않으면 그냥 덮어쓴다.
- 지금 규모(국내 25개 안팎, 미국 10개 안팎)면 1분에 10건 남짓이다. KIS 실전 한도는 초당 20건이다.
- `security_live_quotes`에 `(security_id, price, as_of, source)`로 덮어쓴다. 신선도는 기준 시각으로 판단하고, 오래됐거나 비었으면 마지막 종가를 기준 시각과 함께 보여준다(물리 DB 스키마 5.5).
- 보유하지 않은 종목을 검색하거나 매매 입력 화면에서 단가 기본값이 필요하면 마스터에 함께 오는 전일 종가(`base_price`)를 쓴다. 사용자 요청 때문에 외부를 부르지 않는다.
- KIS 접근 토큰은 1일 유효하고 재발급은 1분에 1회이며, 발급할 때마다 알림톡이 온다. 토큰은 Postgres의 전역 운영 행에 두고 worker만 갱신한다.

### 3.5 일별 종가

- 장 마감 뒤 하루 한 번, `held_now`인 종목의 최근 며칠치를 받아 `(security_id, trade_date)`로 UPSERT한다. 며칠치를 겹쳐 받으므로 실패한 날이 있어도 다음 날 메워진다. 휴장일에는 행이 없을 뿐이다.
- 이미 있는 날짜의 값은 같은 출처일 때만 고친다(3.1의 7).
- **백필**: `needed_from`이 당겨지면 그 날짜부터 받는다. KIS 국내는 한 번에 100건씩 날짜를 당겨가며 부른다.
- **대체 순서**: KIS → (국내만) data.go.kr 날짜별 조회 → 없으면 "시세 없음". data.go.kr은 기준일 다음 영업일 13시 이후에 올라오므로 백필 전용이다. 미국 폐지 종목의 과거 종가는 초대제 단계에서는 받을 곳이 없다. 그 달 평가에서 빠지고 "시세 없음"으로 보인다(통계 질문 목록 A2).
- `trade_date`는 그 시장의 현지 거래일이다(ADR 0014).

### 3.6 배당 일정

- **국내**(KIS `HHKDB669102C0`): 기준일(`record_date`), 현금배당금(`per_sto_divi_amt`), 지급일(`divi_pay_dt`), 결산/중간 구분을 준다. 배당락일 칸은 없다. **배당락일 = 기준일의 직전 영업일**로 계산한다(T+2 결제라서 기준일 하루 전 영업일에 사면 배당을 받지 못한다). 영업일은 `holidays`(공휴일)와 연말 휴장일로 계산한다. 공시된 값만 오므로 `status = confirmed`로 저장한다.
- **미국**(KIS `CTRGT011R`, 권리유형 03 배당·75 특별배당): 현지 기준일, 주당 외화 금액, 통화, 확정 여부(`dfnt_yn`)를 준다. 예정은 `expected`로 저장하고, 확정되면 같은 자연키 행을 고친다. 배당락일 칸이 응답에 없으면 미국 결제 주기 규칙으로 계산한다(구현 전 확인).
- 공식 예제는 연속 조회를 10번에서 끊어서 기간이 길면 조용히 잘린다. 기간을 나눠 부른다.
- 배당 예정 제안과 세금 계산은 ADR 0009와 [주식 수수료·세금·배당 리서치](../research/2026-11-11-stock-fees-dividends.md)를 따른다.

## 4. 그날 기준환율(ADR 0020)

- **정의를 바꾼다.** 그날 기준환율은 **기록 날짜의 서울외국환중개 매매기준율**이다. 그날 값이 없으면(주말·휴일) 직전 영업일 값이다.
  - 옛 정의 "기록 날짜에 마지막으로 고시된 환율"은 은행 고시(하루 여러 회차)에서만 뜻이 있는데, 은행 고시는 공식 API가 없고 스크래핑밖에 없다.
  - 서울외국환중개 매매기준율은 전 영업일 거래의 거래량 가중평균으로 영업일 아침(USD 08시)에 한 번 고시되고, 은행들은 이 값을 그날 1회차 고시로 쓴다.
- **출처**: 한국은행 ECOS `731Y001`(주요국통화의 대원화환율, 일별), 항목 `0000001`(원/미국달러). 해외 결제의 원화 추정을 위해 같은 표의 주요 통화(엔·유로·위안 등)도 받는다(목록은 구현 때, [모바일 입력 UX 원칙](mobile-input.md) 2.2). `fx_rates.pair`에 `JPY/KRW` 등으로 저장한다. 엔처럼 100단위로 고시되는 통화는 받을 때 1단위당으로 나눠 저장한다. 수출입은행 교차 검증은 USD만 한다. USD 외 통화의 ECOS 값은 재정환율이다. 1964-05-04부터 있다. 영업일 아침에 받고, 실패하면 낮에 다시 부른다.
- **교차 검증**: 수출입은행 AP01의 `kftc_deal_bas_r`(서울외국환중개 값)를 매일 한 번 받아 ECOS 값과 비교하고, 다르면 로그를 남긴다. 하루 1,000회 한도라 걸릴 일이 없다.
- **저장**: `fx_rates (pair 'USD/KRW', rate_date)`에 값 `numeric(18,6)`과 `source`(`ecos-731Y001`)를 저장한다. 기록에는 지금처럼 `records.fx_rate`·`fx_rate_date`를 함께 저장하고, 사용자가 증권사 적용 환율로 덮어쓸 수 있다.
- **최신 환율**(통계 A1의 평가 시점 환율): 가장 최근 고시일의 값이다. 하루에 한 번 바뀐다.
- **백필**: 전환 전에 2025-01-01부터 받는다(운영 데이터의 가장 이른 USD 매매일보다 앞선다). 호출 몇 번으로 끝난다.
- **제도 변경**: 매매기준율 산정 방식을 시간가중평균(TWAP)으로 바꾸는 외국환거래규정 개정이 2027-01-01 시행 예정으로 행정예고되었다. 정의("그날의 매매기준율")는 그대로 두고, 산정 방식이 바뀌어도 `source`·고시일로 구분한다. 과거 값은 다시 계산하지 않는다.

## 5. 전환에 필요한 것

- **환율 백필 먼저**: 전환 스크립트가 USD 매매의 `fx_rate`를 채우기 전에 `fx_rates`를 2025-01-01부터 채운다([기존 데이터 전환](legacy-migration.md) 6절).
- **종목 찾기**: 기존 `household_stock_settings`의 `(market, ticker)`로 `securities (market, code)`를 찾는다. 새 마스터에 없는 코드(그사이 폐지·변경)는 기존 oat `stock_master` 행(기존 동기화는 UPSERT만 해서 폐지 종목도 남아 있다)에서 `listed = false` 행을 만들고 보고한다. 그래서 전환용 덤프에는 `stock_master`의 이름·시장·거래소 칸을 포함한다(리허설 덤프에서는 뺐다).
- **종가 백필은 전환 뒤**: 전환 검증(V1~V11)에는 종가가 필요 없다. 전환이 매매 기록을 만들면서 예약한 종목 추적 작업이 백필을 돌린다.

## 6. 구현 전 확인

- data.go.kr 주식시세의 제공 시작일과, 이미 폐지된 종목이 과거 기준일 조회에 나오는지(폐지 코드로 직접 호출).
- KIS 일봉으로 이미 폐지된 종목의 과거 시세가 나오는지. 해외 일봉의 1회 건수와 최대 과거 범위.
- KIS 국내 배당일정에 ETF 분배금이 들어오는지. 해외 권리 응답에 배당락일 칸이 있는지.
- KIS 해외 REST 현재가가 지연 없는 값인지(실시간 웹소켓 문서에는 미국 0분 지연).
- ECOS·수출입은행 이용약관의 상업 이용·출처 표시 원문. 수출입은행 공공누리 유형.
- 정식 출시용 공급원: KRX Data Marketplace·코스콤 정보이용계약 가격과 조건, Tiingo 재배포 등급의 조건(서면), 그 등급에 장중 시세가 포함되는지.

## 7. 다른 티켓에 넘기는 것

- **정식 출시 준비**: 시세 표시 라이선스가 있는 공급원 계약(국내 시세·배당, 미국 시세·배당). 계약 전에는 정식 출시하지 않는다. 유료화를 시작하면 data.go.kr 데이터도 바꾼다.
- **전환 당일 절차**: 환율 백필 확인 단계는 2025-01-01부터의 `fx_rates` 행 존재 확인이다. 전환용 덤프에 기존 `stock_master`를 포함한다.
- **통계 화면 구성**: data.go.kr 데이터를 쓰는 화면의 출처 표시 위치. "시세 없음"과 "기준 시각" 표시 방식. → [통계 화면 구성](stats-screens.md) 7절에서 정했다.
- **모바일 입력 UX 원칙**: 종목 검색은 API 메모리의 마스터 사본으로 한다. 폐지(`listed = false`) 종목은 검색 결과에서 기본으로 숨기고, 보유 중인 종목은 계속 보인다. → [모바일 입력 UX 원칙](mobile-input.md) 7절에 반영했다.
- **셀프호스팅 운영 스택**: worker 작업 목록에 종목 마스터·현재가·종가·배당·환율·종목 추적 갱신 작업을 더한다. 각 작업의 성공을 Healthchecks.io로 확인한다. "보유 종목이 마스터에서 사라짐" 알림을 운영자에게 보낸다.
