# 서버 아키텍처

- 결정일: 2026-11-17
- 티켓: [서버 아키텍처: 레포 구조·프레임워크·API 방식·권한 모델](https://github.com/Gn0lee/oat/issues/522)
- 관련 ADR: 0010(Expo 앱), 0011(얇은 클라이언트 + OpenAPI 계약), 0012(앱 레이어 권한 + RLS 안전망), 0013(Postgres 단일 정본)
- 관련 리서치: `docs/research/2026-11-17-better-auth-mobile-session-transport.md`(앱 세션 전달 방식)
- 전제: 1인 개발, 미니 PC 한 대(Docker Compose, Cloudflare Tunnel, pgBackRest), TypeScript 서버, Expo 앱(OTA 미사용), Better Auth 셀프호스팅, 원격 MCP 제공
- 리뷰: 초안을 독립 리뷰어(Fable 5.2)가 검토했고, 지적 12건을 반영했어요(R1~R4는 결정 변경, 나머지는 보강).

## 1. 전체 모양

```
Expo 앱 ──────────┐  (생성된 API 클라이언트, 헤더로 보내는 세션)
미래 네이티브 앱 ─┤  (같은 세션을 Authorization: Bearer로)
AI 클라이언트 ────┘  (원격 MCP, 별도 resource의 OAuth 액세스 토큰)
        │  Cloudflare Tunnel
        ▼
api 컨테이너 (Node LTS + Hono)
  ├─ 입구: REST 라우트 /v1/* (zod-openapi) · MCP 툴 /mcp · Better Auth 핸들러 /api/auth/*
  │     └─ 접근 문맥 생성: 사용자 · 가구(DB 멤버십에서) · 볼 수 있는 장부
  ├─ 도메인 서비스 (유스케이스): 권한 확인 · 트랜잭션 · 동시성 제어 · 감사 기록 · 작업 예약 · 중복 방지
  ├─ 순수 계산 모듈: 예상 청구액 · 이용기간 · 평단 · 예정 · 정산 반영 (DB 없음)
  └─ DB 접근 (Drizzle, app 롤)
worker 컨테이너 (같은 이미지): Postgres 큐 소비 · 스케줄 · 시세 공급원 호출 (system 롤로 찾고 app 롤로 씀)
migrate 컨테이너 (일회성, owner 롤): 배포 때 api·worker보다 먼저 마이그레이션 적용
PostgreSQL: 유일한 정본 저장소
```

## 2. 결정 목록

### 클라이언트 경계

1. **얇은 클라이언트.** 앱은 화면, 입력, 표시 포맷(통화·날짜), 입력 중 UX 검증만 맡는다. 잔액, 예상 청구액, 정산 반영, 혜택, 예정, 평단·실현손익, 통계 집계, 최종 검증, 권한은 모두 서버가 한다. (ADR 0011)
2. **온라인 전제.** 오프라인 입력은 지원하지 않는다. 앱은 보내지 못한 입력 초안만 기기에 남겨 다시 보낸다.
3. **화면용 조회 엔드포인트.** 쓰기와 단건 조회는 리소스 엔드포인트로 한다. 계산이 필요한 화면(홈 요약, 청구서, 월 통계, 이번 달 예정)은 서버가 계산을 끝낸 전용 조회 엔드포인트로 받는다. 앱은 받은 숫자를 다시 계산하지 않는다.
4. **가구원 간 실시간 반영은 처음엔 없다.** 화면 진입, 포그라운드 복귀, 당겨서 새로고침 때 다시 가져온다. 필요해지면 Postgres LISTEN/NOTIFY → SSE로 붙인다.

### API 계약

5. **REST + OpenAPI 3.1, 코드 우선.** 서버 라우트의 zod 스키마에서 OpenAPI 문서를 생성하고, 레포에 커밋해 단일 원천으로 둔다. tRPC·oRPC·GraphQL은 택하지 않았다. (ADR 0011)
6. **Expo 앱도 서버 코드를 import하지 않는다.** OpenAPI에서 생성한 클라이언트만 쓴다. TS 생성기는 `openapi-typescript` + `openapi-fetch`(타입만 생성하고, 모르는 필드·enum 값에 관대하다). 미래의 Swift·Kotlin 생성기는 모르는 enum 값 처리를 테스트로 확인하고 고른다.
7. **응답이 계약과 맞는지 테스트로 확인한다.** `@hono/zod-openapi`는 응답을 런타임에 검증하지 않으므로, 통합 테스트에서 실제 응답을 OpenAPI 스키마로 검증한다.
8. **값 표기 규약.**
   - 금액: 통화 최소 단위 정수 + `currency`. 통화별 소수 자릿수 표를 계약에 둔다(KRW 0, USD 2). 금액에 부동소수점을 쓰지 않는다.
   - 수량·단가·평단·환율·요율: 소수 문자열.
   - 반올림 방식과 반올림 시점(수량 × 단가, 환율 환산)은 물리 DB 스키마에서 정한다.
   - 기록 날짜(이용일·결제일·예정일 포함): 한국 기준 `YYYY-MM-DD`. 순간값(생성 시각 등)만 ISO 8601 UTC.
   - ID: UUIDv7. 초대 코드나 공개 토큰처럼 추측되면 안 되는 값에는 쓰지 않는다.
   - 오류: RFC 9457 Problem Details + 기계가 읽는 `code`.
   - 목록: `(정렬 키, id)` 커서 페이지네이션. 기록 목록의 정렬 키는 기록 날짜다.
9. **호환 규칙.**
   - 경로는 `/v1`. 같은 버전 안에서는 추가만 한다(필드·엔드포인트·enum 값 추가). 제거·이름 변경·의미 변경·선택→필수 전환은 하지 않는다.
   - CI가 커밋된 OpenAPI 문서를 이전 버전과 비교해(oasdiff 계열) 깨지는 변경을 막는다.
   - 모양을 바꿔야 하면 새 엔드포인트를 만들고, 옛 엔드포인트는 같은 도메인 서비스를 부르는 얇은 변환기로 남긴다. `X-App-Version` 로그로 옛 버전 사용자가 사라진 것을 확인한 뒤 지운다.
10. **업데이트 안내 두 단계.** 서버가 권장 버전(닫을 수 있는 안내)과 최소 버전(사용 차단)을 내려준다. 최소 버전은 보안 문제나 옛 앱이 데이터를 잘못 쓰는 경우에만 올린다. API 모양 변경은 최소 버전을 올릴 이유가 아니다.
11. **모든 쓰기 요청에 중복 방지 키.** 앱은 초안마다 UUID를 만들어 `Idempotency-Key`로 보낸다.
    - 키 범위는 사용자 + 키다.
    - 키 행을 쓰기와 같은 트랜잭션에서 먼저 INSERT해 유니크 제약으로 직렬화한다. 처리 중인 같은 키가 또 오면 409다.
    - 요청 본문의 해시를 같이 저장하고, 같은 키에 본문이 다르면 422로 거절한다. 앱은 초안을 고치면 새 키를 만든다.
    - 응답 본문이 아니라 만들어진 리소스 ID를 저장하고, 재요청에는 현재 상태를 다시 읽어 응답한다.
    - 7일 보존 후 worker가 지운다.
    - MCP 쓰기의 키 정책(재시도마다 새 키를 만드는 AI 클라이언트)은 MCP 툴 설계에서 정한다.
12. **동시 수정은 낙관적 잠금.** 기록 수정·삭제 요청은 읽은 `version`을 보낸다. 서버의 현재 version과 다르면 409로 거절하고, 앱은 새로 불러와 다시 수정하게 한다. 같은 지갑·계좌에 대한 불변식 검사(보유 수량을 넘는 매도 등)는 지갑 단위 행 잠금으로 줄을 세운다.

### 인증

13. **앱 세션은 헤더로 보낸다. 브라우저 쿠키는 쓰지 않는다.** `@better-auth/expo`가 세션을 `expo-secure-store`에 두고 `Cookie` 헤더로 직접 붙인다. 생성 클라이언트는 미들웨어에서 `getCookie()` 값을 붙인다. 카카오·네이버는 리다이렉트 로그인만 있고, 그 결과를 앱 딥링크로 넘기는 공식 장치가 Expo 플러그인에만 있어서 bearer 단독 대신 이 방식을 택했다.
    - 앱은 포그라운드마다 세션 확인을 한 번 부른다. 앱이 우리 API만 부르면 Expo 클라이언트가 서버에서는 아직 유효한 세션을 기기 쪽 만료 기록으로 버릴 수 있기 때문이다.
    - OpenAPI에는 헤더 세션으로 적는다. 네이티브 앱을 시작할 때 `bearer()`(서명 필수 옵션)를 더해 같은 세션을 `Authorization: Bearer`로도 받는다. 기능 추가라 기존 앱을 깨지 않는다.
14. **MCP는 별도 resource의 OAuth 액세스 토큰.** Better Auth가 OAuth 인가 서버를 겸한다. JWT 플러그인의 세션 JWT 발급(`/token`, `set-auth-jwt`)은 끈다. MCP 토큰은 앱 API와 다른 resource 값으로 검증하고, 앱 API는 세션 확인만 쓴다. 두 토큰을 서로의 엔드포인트에서 거부하는지 테스트한다. 랜딩 웹에는 로그인이 없다.
15. **가구는 요청마다 DB 멤버십에서 정한다.** 클라이언트가 보낸 헤더로 정하지 않는다. 가구원을 빼면 그 사람의 세션과 MCP 토큰을 무효화한다.
16. **Better Auth는 버전을 고정한다.** `better-auth`와 모든 `@better-auth/*` 패키지를 같은 정확한 버전으로 둔다. 인증 엔드포인트는 우리 OpenAPI 밖에 있으므로, 앱이 쓰는 엔드포인트의 Better Auth `openAPI()` 출력을 따로 스냅샷으로 남기고 CI에서 비교한다. 우리만의 인증 래퍼 엔드포인트는 만들지 않는다. Better Auth 테이블 스키마는 Better Auth CLI로 생성해 Drizzle 스키마에 넣는다.
17. **실기기 확인은 인증 PoC로.** 수동 Cookie 헤더 전달, 소셜 리다이렉트 복귀, 장기 방치 후 세션, 재설치 후 Keychain, MCP 토큰 교차 거부 등 리서치 9.2절의 항목을 인증 PoC 티켓에서 확인한다.

### 서버 내부

18. **프레임워크·런타임: Hono + `@hono/zod-openapi`, Node LTS.** Fastify, NestJS, Bun은 택하지 않았다.
19. **세 겹 구조.** 입구(REST·MCP) → 도메인 서비스 → 순수 계산 모듈 / DB 접근. REST와 MCP는 같은 도메인 서비스를 직접 부른다. MCP가 REST를 HTTP로 다시 부르지 않는다. worker도 같은 도메인 서비스를 부른다.
20. **도메인 모듈.** 기록·장부, 지갑, 신용카드, 정기, 주식, 통계, 가구·계정.
21. **MCP는 같은 서버 앱, 같은 이미지의 `/mcp`.** 툴 목록과 권한 범위는 MCP 툴 설계에서 정한다.
22. **서버의 "오늘"은 Asia/Seoul로 서버가 정한다.** 컨테이너 시간대에 기대지 않는다. 날짜 컬럼은 문자열로만 다루고 JS `Date`로 바꾸지 않는다. 시계는 테스트에서 바꿔 끼울 수 있게 주입한다. 해외 결제 이용일과 미국 주식 체결일의 정의는 물리 DB 스키마에서 정한다.
23. **감사 기록과 로그.** 모든 쓰기는 누가, 어떤 입구(앱·MCP·worker)로, 무엇을 바꿨는지 감사 기록을 같은 트랜잭션에 남긴다. 로그는 구조화하고 요청 ID를 붙인다. 레이트리밋과 로그의 클라이언트 IP는 `CF-Connecting-IP`를 신뢰 헤더로 쓴다(터널 뒤에서는 모든 요청이 cloudflared IP로 보인다). Better Auth에도 같은 설정을 한다.

### 데이터

24. **정본은 PostgreSQL 하나.** SQLite, TigerBeetle, MySQL, 문서형 DB는 택하지 않았다. (ADR 0013)
25. **저장 두 층.** 잃으면 안 되거나 쓰기와 원자적이어야 하는 것(정본, 세션, 시세·환율 이력, 작업 큐, 중복 방지 키, 감사 기록)은 Postgres에 둔다. 잃어도 되는 휘발성 값(장중 현재가 사본, 레이트리밋, 종목 마스터 사본)은 API 프로세스 메모리에 둔다. Redis는 API가 두 대 이상이 될 때 다시 검토하고, 넣게 되면 Valkey를 휘발성 전용으로 쓴다. 운영 스택의 Compose 목록에서 `redis`를 빼고 일회성 `migrate`를 더한다.
26. **작업 큐·스케줄은 Postgres 기반 큐(pg-boss 계열).** 환율, 종목 마스터, 휴장일·공휴일, 정기 예정 처리, 메일·푸시 발송, 중복 방지 키 정리를 worker에서 처리한다. 작업 예약은 기록 저장과 같은 트랜잭션으로 커밋한다(큐 라이브러리에 Drizzle 트랜잭션 실행기를 넘긴다).
27. **작업은 최소 1회 실행된다고 본다.** 작업은 멱등하게 만든다. 정기 자동 기록에는 `(규칙, 회차 날짜)` 유니크 제약을 건다. 백업 복구 뒤 큐가 되살아나도 중복 기록이 생기지 않아야 한다.
28. **외부 시세 호출을 사용자 요청에서 뺀다.** worker가 **시세 공급원** 인터페이스(종목 마스터, 현재가, 종가, 배당 일정) 뒤의 구현을 부른다. KIS는 구현 중 하나다. 장중에는 보유 종목 현재가를 주기적으로 갱신해 Postgres의 `UNLOGGED` 테이블에 덮어쓴다(WAL·백업을 키우지 않는다). API는 짧은 TTL로 메모리에 읽는다. 장 마감 후 종가는 일반 테이블 이력에 영구 저장한다. 현재가가 없으면 마지막 종가를 기준 시각과 함께 보여준다.
29. **집계는 조회 시 계산부터.** 측정해서 느린 곳만 Postgres 요약 테이블로 바꾸고, 요약 테이블은 기록 쓰기와 같은 트랜잭션에서 갱신한다. 그 밖의 캐시 레이어는 두지 않는다.
30. **DB 접근: Drizzle.** drizzle-kit이 만든 마이그레이션 SQL을 사람이 검토해 커밋하고, 배포 때 `migrate` 컨테이너가 먼저 적용한다. 마이그레이션에는 `lock_timeout`을 건다. DB 스키마와 API 스키마(zod)는 따로 정의한다.

### 권한

31. **판단은 앱 레이어, 가구 격리는 RLS 안전망.** 권한 모듈 하나가 요청자의 접근 문맥(볼 수 있는 장부 집합 등)을 계산하고, 모든 조회와 쓰기는 도메인 서비스에서 이것을 거친다. 개인 장부 프라이버시는 앱 레이어에서만 강제한다. (ADR 0012)
32. **DB 롤 셋.**
    - `owner`: 테이블 소유자이고 migrate만 쓴다. Postgres는 테이블 소유자에게 RLS를 적용하지 않으므로 api와 worker는 이 롤로 붙지 않는다.
    - `app`: api, MCP, 가구가 정해진 worker 작업이 쓴다. 요청마다 트랜잭션 안에서 `set_config('app.household_id', …, true)`를 설정한다. 가구 소유 테이블의 정책은 `current_setting('app.household_id', true)`와 비교해서, 설정이 없으면 0행이 보인다.
    - `system`: worker의 가구 횡단 작업 전용이다(오늘 예정이 있는 가구 찾기, 시세·환율 갱신). 가구 소유 테이블에서는 정해진 조회만 하고, 실제 쓰기는 가구마다 `app` 롤 + 가구 설정으로 바꿔서 한다.
    - 가구 소유가 아닌 테이블(인증, 큐, 중복 방지 키, 시세·환율, 종목 마스터, 공휴일)은 목록으로 명시하고 RLS를 걸지 않는다.

### 레포·테스트

33. **새 레포 하나, pnpm 워크스페이스 모노레포.** `apps/server`(api + worker + MCP), `apps/mobile`(Expo), `apps/landing`, `packages/api-client`(OpenAPI 생성물). 설계 문서(GLOSSARY, ADR, 리서치)도 이 레포로 옮긴다. 빌드 캐시 도구는 빌드가 느려지면 붙인다.
34. **테스트.** 순수 계산 모듈은 단위 테스트(Vitest). 도메인 서비스와 권한은 진짜 Postgres(테스트 컨테이너)에 대고, 운영과 같은 롤 구성으로 통합 테스트한다. DB 목은 쓰지 않는다. 필수 테스트:
    - **RLS 단독**: 권한 모듈을 우회한 쿼리를 `app` 롤로 실행해도 다른 가구 행이 안 보이는지, 가구 설정 없이는 0행인지.
    - **개인 장부**: 같은 가구의 다른 가구원에게 개인 장부 기록이 안 보이는지. 단건 조회뿐 아니라 **집계 엔드포인트마다**(홈 요약, 청구서, 월 통계, 예정) 가구원 A 시점과 B 시점으로 확인한다.
    - **토큰 교차**: 앱 세션으로 MCP를, MCP 토큰으로 앱 API를 부르면 거부되는지.
    - **응답 계약**: 실제 응답이 OpenAPI 스키마와 맞는지.

## 3. 다른 티켓에 넘기는 것

- **물리 DB 스키마**: 가구 소유 테이블마다 `household_id`(RLS 안전망 전제), UUIDv7 키, `version` 컬럼, 금액 정수(`bigint`, 드라이버가 문자열로 주는 것의 매핑)·수량 numeric 컬럼, 반올림 방식과 시점, 해외 결제 이용일·미국 주식 체결일·"그날 기준환율"의 날짜 정의, 중복 방지 키·큐·감사 기록·시세 이력 테이블, 가구 소유가 아닌 테이블 목록.
- **인증 PoC**: 리서치 9.2절의 실기기 확인 항목, 인증 리서치에서 미룬 Expo 패스키·Apple 토큰·원격 MCP 연결 검증.
- **MCP 툴 설계**: 같은 도메인 서비스와 중복 방지 키를 쓴다는 전제, MCP 쓰기의 키 정책, 연결된 AI 클라이언트 목록·해지 화면.
- **통계 화면 구성**: 공용 지갑(예: 가족카드가 가리키는 신용카드 지갑)의 잔액·예상 청구액에 개인 장부 기록이 어떻게 드러나는지의 표시 규칙. 이미 정한 "지갑 공개" 규칙의 연장이다.
- **알림**: worker 큐에서 푸시를 보낸다는 전제.
- **셀프호스팅 운영 스택**: Compose에서 `redis`를 빼고 일회성 `migrate`를 더한다. 최소 앱 버전은 권장/최소 두 단계로 바뀐다. 에러 추적에서 금융 데이터를 가리는 규칙과 시크릿 주입 방식은 구현 때 운영 설정으로 정한다.
- **시세 데이터 공급원 선택**(KIS 유지, 다른 시세 API, 시세 조회 MCP 등): 이용약관·호출 한도·지연을 확인해야 한다. 지금은 정하지 않는다.
