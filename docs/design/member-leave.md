# 가구원 나가기·계정 삭제

- 결정일: 2026-11-20
- 티켓: [가구원 나가기·계정 삭제: 남는 기록과 끊는 접근](https://github.com/Gn0lee/oat/issues/531)
- 관련 ADR: 0024(나가기는 얼리고 계정 삭제는 개인 데이터를 지운다), 0022(AI 연결은 세션과 별개), 0023(연결 행은 멤버 행에 묶임), 0012(앱 레이어 권한), 0004(잔액은 다리에서 계산)
- 리서치: [계정 삭제 요건·법·사례](../research/2026-11-20-account-deletion-rules.md). 접근 끊기는 [MCP PoC](../research/2026-11-20-mcp-poc.md)의 해지 흐름으로 확인돼서 PoC를 다시 하지 않았어요.
- [물리 DB 스키마](physical-db-schema.md) 9절의 남은 질문, [MCP](mcp.md) 5.6·8절, [인증](auth.md) 6절에서 넘긴 것을 정해요.

## 1. 한 장 요약

| 항목 | 결정 |
|---|---|
| 두 단계 | **나가기 = 얼리기**(접근만 끊고 데이터는 그대로, 같은 가구로 돌아오면 이어짐). **계정 삭제 = 그 사람만의 데이터 지우기**(개인 장부·숨긴 지갑과 그 감사 기록). 공용 장부 기록은 남기고 사람은 "탈퇴한 가구원"으로 가려요 |
| 지갑 | 나간 사람이 주인인 지갑은 보관하고 나간 날부터 가구 잔액·순자산에서 빠져요(과거 추이는 그대로). 함께 쓰는 지갑만 나갈 때 지갑마다 받을 가구원을 골라 넘겨요 |
| 개인 장부 지우기 | 남는 지갑에 닿은 다리는 **지갑 × 통화 × 월 잔액 맞춤**으로 바꿔요. 맞춤은 이름을 바꿔 보관한 그 사람의 개인 장부에 두어 아무도 못 봐요. 그 사람만 쓰던 지갑은 지갑째 지워요 |
| 감사 기록 | 나가기: 그대로. 계정 삭제: 지운 것의 감사 기록을 전용 DB 함수로 지워요. 공용 장부의 감사 기록은 남고 이름만 가려져요 |
| 접근 끊기 | 나가기 트랜잭션 하나에서 멤버 행 `left` → AI 연결 행 삭제 → 갱신 토큰 `revoked` → 세션 전부 삭제 |
| 역할 | **관리자** 1명 + 가구원. 관리자만 초대·내보내기. 관리자가 떠날 땐 본인이 다음 관리자를 고르고, 못 고르면 가장 먼저 들어온 가구원. 마지막 한 명은 나가기 대신 **가구 삭제** |
| 계정 삭제 시점 | **바로**. 안내(남는 것 고지) → 내려받기 권유 → 비밀번호 재입력 → 즉시 접근 차단, worker가 몇 분 안에 정리 → 완료 메일 |
| 데이터 들고 가기 | **내 데이터 내려받기**(JSON + CSV), 언제든. 범위는 앱에서 내가 볼 수 있는 것 전부. 새 가구로 옮기기는 만들지 않아요 |
| 백업 | 보관 **35일**(HDD·S3 같게), 처리방침에 적어요. **지운 목록**을 DB 안팎에 남겨 복원 뒤 다시 적용해요 |

## 2. 두 단계와 데이터별 처리

| 데이터 | 나가기(스스로·내보내기) | 계정 삭제 |
|---|---|---|
| 세션 | 전부 삭제(누른 기기 포함) | user 행과 함께 사라짐 |
| AI 연결 행·갱신 토큰 | 행 삭제, 갱신 토큰 `revoked` | 같음, 토큰 행은 user FK로 삭제 |
| 멤버 행 | `status = left`, `left_at`, 이름 유지(화면은 "이름(나감)") | `user_id = NULL`, `display_name = "탈퇴한 가구원"`(같은 가구에 여럿이면 번호) |
| 공용 장부 기록 | 그대로. 쓴 사람·작성자는 "이름(나감)" | 그대로. "탈퇴한 가구원" |
| 개인 장부 기록 | 얼림(아무도 못 봄, 잔액엔 계속 반영) | 지우고 남는 지갑엔 월별 잔액 맞춤(4절) |
| 개인 장부의 카테고리·상대·정기 규칙 | 얼림, 정기 규칙은 예정을 만들지 않음 | 지움 |
| 그 사람이 주인인 공개 지갑 | 보관(3절) | 공용 기록이 가리키면 보관 유지, 아니면 지갑째 지움 |
| 숨긴 지갑 | 얼림 | 공용 기록이 가리키면 보관 유지, 아니면 지갑째 지움 |
| 그 사람의 결제수단 | 보관 | 공용 기록이 가리키면 보관 유지, 아니면 지움 |
| 감사 기록 | 그대로(읽을 때 볼 수 있는 장부만) | 지운 것의 행만 지움(5절) |
| 중복 방지 키 | 그대로(7일 뒤 정리) | user FK로 삭제 |

- 같은 가구로 돌아오면(초대 수락) 옛 멤버 행이 `active`로 돌아오고 개인 장부·숨긴 지갑이 그대로 이어져요. 보관된 공개 지갑은 자동으로 풀지 않고 사용자가 풀어요. AI 연결은 다시 맺어요.
- 다른 가구에 들어가면 옛 가구의 얼린 데이터는 그대로 남아요. 계정을 지울 때 함께 지워져요.

## 3. 나간 사람의 지갑

- 그 사람이 주인인 지갑은 모두 `archived_at`을 채워요. 다리가 있는 지갑은 지울 수 없으니(물리 DB 스키마 5.8) 공용 기록이 가리키는 지갑 이름은 "A의 국민카드(나감)"처럼 그대로 보여요.
- **잔액·순자산**: 나간 날부터 가구 화면과 순자산에서 빠져요. 나가기 전 달의 월별 자산 추이는 바꾸지 않아요. 보관 지갑을 추이에서 어떻게 그릴지는 통계 화면 구성에서 정해요.
- **함께 쓰는 지갑 넘기기**: `allow_member_use`가 켜진 지갑은 나가기 화면에서 지갑마다 [남는 가구원 중 한 명 / 넘기지 않음]을 골라요. 넘기면 `owner_member_id`만 바꾸고 보관하지 않아요. 받은 사람의 동의는 받지 않고 알림만 보내요(받은 뒤 언제든 보관할 수 있어서). 내보내기면 내보내는 관리자가 골라요.
- **가족카드**: 다른 가구원의 결제수단이 보관된 카드 지갑을 가리키면 "연결된 카드 지갑이 보관됐어요"로 보여주고 새 기록에는 못 써요.
- **정기 규칙**: 공용 장부 규칙 중 보관된 지갑을 쓰는 것은 "확인 필요"(끊긴 규칙과 같은 동작). 그 사람의 개인 장부 규칙은 예정을 만들지 않아요.

## 4. 계정 삭제 때 개인 장부를 지우는 방법

공용 지갑의 잔액은 장부와 관계없이 그 지갑의 모든 다리를 더해요(통계 질문 목록 A1). 개인 장부 기록을 그냥 지우면 남은 가구원의 통장 잔액이 실제와 달라지고 월별 자산 추이도 바뀌어요.

1. **남는 지갑**을 정해요: 다른 가구원의 지갑, 넘겨준 지갑, 공용 기록(다른 장부의 다리)이나 다른 가구원의 결제수단이 가리켜서 보관으로 남는 그 사람의 지갑.
2. 그 사람의 개인 장부 기록 중 남는 지갑에 닿은 통화 다리를 **(지갑, 통화, 월)**로 더해요.
3. 묶음마다 잔액 맞춤 기록(`balance_adjustment`) 하나를 만들어요. 날짜는 그달 말일(이번 달이면 오늘), 다리 금액은 합계 그대로예요. 잔액 맞춤은 수입·지출 통계에 들어가지 않아요.
4. 맞춤은 그 사람의 **개인 장부**에 넣어요. 장부 이름을 "탈퇴한 가구원"으로 바꾸고 보관해요. 개인 장부라 아무도 볼 수 없어서, 남은 가구원이 보는 것은 탈퇴 전과 같아요(공용 지갑의 잔액만).
5. 개인 장부의 원래 기록, 그 장부 전용 카테고리·상대·정기 규칙, 남지 않는 지갑(다리가 전부 이 장부에만 있던 지갑, 숨긴 지갑 포함)과 그 하위 설정·청구서를 지워요. 그 지갑은 가구의 과거 자산 추이에서도 빠져요(그 사람만의 돈이었으므로).

- 월 단위인 이유: 한 건으로 합치면 지금 잔액만 맞고 과거 추이가 틀어지고, 하루 단위면 "그날 얼마"가 너무 자세히 남아요. 자산 추이가 월 단위라 그래프를 지키는 가장 거친 단위예요.
- **장부가 다른 이관**: 개인 장부의 `security_transfer_out`을 공용 장부의 `security_transfer_in`이 가리키면(`target_record_id`, NO ACTION), 지우기 전에 입고 기록을 `balance_adjustment`로 바꾸고 종목 다리에 그때의 출발 계좌 평단을 시작 평단으로 적어요. 공용 증권 계좌의 평단이 그대로예요.
- 돌려받은 돈·정산은 늘 원 기록과 같은 장부라(ADR 0006) 장부를 건너는 연결이 없어요.
- 이 작업은 가구마다 `app` 롤 + 그 가구 설정으로 트랜잭션 하나에서 해요(물리 DB 스키마 2절). 나갔던 가구가 여럿이면 가구마다 따로 해요.

## 5. 감사 기록

- 나가기: 손대지 않아요. 감사 기록을 읽을 때도 볼 수 있는 장부만 보이므로(물리 DB 스키마 5.4) 개인 장부의 행은 아무도 못 봐요.
- 계정 삭제: 지운 것(개인 장부의 기록·카테고리·상대·정기 규칙·장부 자체의 설정, 지갑째 지운 지갑과 결제수단)의 감사 행을 지워요.
  - `app` 롤은 감사 기록을 지울 수 없어요. **`erase_member_audit(member_id)` 함수 하나**(SECURITY DEFINER, `owner` 소유)만 지울 수 있고, 계정 삭제 작업만 불러요. 함수 안에서도 `app.household_id`의 가구 행만 지워요.
  - 맞춤 기록 생성·입고 기록 변환은 입구 `worker`, 행위자 NULL로 감사 기록을 남겨요.
- 공용 장부의 감사 행은 남아요. `actor_member_id`가 멤버 행을 가리키니 이름이 "탈퇴한 가구원"으로 바뀌면 화면도 가려져요.
- `ai_connection_id`는 남고 연결 행은 지워져서 "해지된 연결"로 보여요(MCP 4.3).

## 6. 접근 끊기

나가기는 트랜잭션 하나예요(계정·가구 경계 테이블과 Better Auth 테이블은 같은 Postgres에 있고 RLS가 없어요).

1. `household_members`: `status = 'left'`, `left_at = now()`. 앱 API와 `/mcp`는 요청마다 활동 멤버십을 보므로 이 순간 막혀요(서버 아키텍처 15번, MCP 5.4).
2. 그 멤버의 `ai_connections` 행을 지워요.
3. 그 사용자의 그 클라이언트들에 대한 `oauthRefreshToken`에 `revoked = now()`를 적어요. 행은 user FK로 계정 삭제 때 지워져요.
4. 그 사용자의 `session`을 모두 지워요. 쿠키 캐시를 껐으니 다음 요청부터 세션이 없어요(인증 2.2). 누른 기기도 로그인 화면으로 가요.
5. 지갑 보관·넘기기, 정기 규칙 표시(3절), 관리자 넘기기(7절).

Better Auth API를 따로 부르지 않는 이유: 멤버는 나갔는데 토큰이 남는 중간 상태를 없애려고요. MCP PoC의 해지도 같은 SQL로 했고 다음 요청 401, 갱신 `invalid_grant`를 확인했어요.

**계정 삭제 순서**

1. 요청 처리(동기): 비밀번호 재확인 → 활동 가구가 있으면 위 나가기 트랜잭션(관리자 넘기기 포함) → `user`에 삭제 예정 표시, 세션 전부 삭제 → 정리 작업을 큐에 넣어요(작업 데이터에 완료 메일용 이메일).
2. worker: 그 사용자의 멤버 행이 있는 가구마다(활동·나감 모두) 4·5절을 트랜잭션 하나로 → 멤버 행 이름 바꾸기 → 지운 목록 한 줄(9절).
3. worker: `user` 행 삭제. FK로 `session`·`account`·`verification`·OAuth 토큰·`idempotency_keys`가 함께 지워지고 `household_members.user_id`는 `SET NULL`.
4. 완료 메일을 보내고 작업 데이터의 이메일을 버려요.

## 7. 역할과 내보내기

- `household_members.role`: `admin` | `member`. 가구마다 활동 관리자 한 명(부분 유니크 `(household_id) WHERE role = 'admin' AND status = 'active'`).
- 관리자만 초대하고 **내보내요**. 나머지 권한(기록, 공용 장부)은 같아요. 관리자를 내보낼 사람은 없어요.
- 내보내기는 나가기와 같은 처리예요. 내보낸 사람도 그 사람의 개인 장부를 볼 수 없어요. 내보내진 사람에게 메일로 알려요.
- 관리자가 나가거나 계정을 지울 때 남는 사람 중 다음 관리자를 골라요. 한 명이면 자동이고, 고르지 못하면(운영자 처리 등) **가장 먼저 들어온 활동 가구원**이에요. 관리자가 연락 없이 사라지는 경우는 문제가 되면 운영자 처리나 미사용 넘기기를 더해요.
- **가구 삭제**: 마지막 활동 가구원은 나가기 대신 가구 삭제만 할 수 있어요(돌아올 초대가 없으니). 가구 소유 데이터, 감사 기록, 멤버 행(나갔던 사람 것 포함)까지 모두 지워요. "멤버 행은 지우지 않는다"의 유일한 예외예요(가구 자체가 사라지므로). 마지막 한 명이 계정을 지우면 가구 삭제도 함께 해요. 지운 목록에 남겨요.

## 8. 내 데이터 내려받기

- 설정 → 내 데이터 내려받기. 나가기·계정 삭제 화면에도 같은 버튼.
- 범위: 앱에서 내가 볼 수 있는 것 전부(공용 장부 + 내 개인 장부, 지갑, 결제수단, 카테고리, 정기 규칙). AI 연결과 같은 "그 사람이 보는 만큼" 규칙이라 새로 드러나는 건 없어요.
- 형식: JSON(다리·줄까지 전부, 계약의 스키마 이름 그대로)과 CSV(기록 한 줄, 줄이 여럿이면 줄마다 한 줄). iOS 공유 시트로 건네요.
- 새 가구로 옮기기는 만들지 않아요(ID 짝짓기·잔액 이어 붙이기가 전환을 하나 더 만드는 일). 요구가 생기면 JSON을 개인 장부로 가져오는 기능으로 더해요.
- 법적 의무(전송요구권)는 없어요(리서치 2절).

## 9. 백업과 지운 목록

- pgBackRest 보관 기간 **35일**(HDD·S3 같게, 주 1회 전체 백업 5개 정도). 개인정보처리방침에 "탈퇴 후 최대 35일 동안 백업에 남았다가 지워짐"을 적어요.
- **`erasure_log`**(운영 테이블, RLS 없음): `id`, `kind`(`account`·`household`), `household_id`, `member_id`, 지운 장부·지갑 ID 목록, `erased_at`. 개인정보는 넣지 않아요.
  - DB 밖에도 같은 줄을 남겨요(HDD와 S3의 추가 전용 파일). DB를 옛 시점으로 되돌리면 DB 안의 목록도 옛날로 돌아가기 때문이에요.
  - 복원 절차에 한 단계를 더해요: 복원 시점 이후의 줄을 순서대로 다시 실행해요(같은 정리 함수, 이미 지운 것은 건너뜀).
- 전환 보관본(기존 oat 덤프)의 보관 기간은 전환 당일 절차에서 정하고, 탈퇴자에게도 같은 기준을 적용해요.

## 10. 스키마 변경

- `household_members.role` 값(`admin`·`member`)과 활동 관리자 부분 유니크. `display_name`은 계정 삭제 때 바꿔요.
- `user` 삭제 FK: `session`·`account`·OAuth 토큰·`idempotency_keys`는 CASCADE, `household_members.user_id`는 `SET NULL (user_id)`.
- `erasure_log` 테이블(운영).
- `erase_member_audit(member_id)` 함수(SECURITY DEFINER).

## 12. 구현 때 통합 테스트

- 나가기 직후: 남은 액세스 토큰으로 `/mcp` 401, 갱신 `invalid_grant`, 모든 기기 세션 없음, 앱 API 401.
- 다시 들어오면 개인 장부·숨긴 지갑이 이어지고 AI 연결은 없음.
- 계정 삭제 뒤: 남은 지갑의 현재 잔액과 월말 잔액이 삭제 전과 같음, 개인 장부 원래 기록과 그 감사 행 0건, 공용 기록·감사 행은 그대로, `user_id` NULL.
- 장부가 다른 이관이 있을 때 공용 증권 계좌의 평단이 그대로.
- 복원 뒤 지운 목록을 다시 적용하면 같은 결과.
