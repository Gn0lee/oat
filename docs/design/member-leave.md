# 가구원 나가기·계정 삭제

- 결정일: 2026-11-20
- 티켓: [가구원 나가기·계정 삭제: 남는 기록과 끊는 접근](https://github.com/Gn0lee/oat/issues/531)
- 관련 ADR: 0024(나가기는 얼리고 계정 삭제는 개인 데이터를 지운다), 0022(AI 연결은 세션과 별개), 0023(연결 행은 멤버 행에 묶임), 0012(앱 레이어 권한), 0004(잔액은 다리에서 계산)
- 리서치: [계정 삭제 요건·법·사례](../research/2026-11-20-account-deletion-rules.md). 접근 끊기는 [MCP PoC](../research/2026-11-20-mcp-poc.md)의 해지 흐름으로 확인돼서 PoC를 다시 하지 않았어요.
- 리뷰: 독립 리뷰어(Fable 5.2)가 두 번 검토했어요. 계정 삭제 때 개인 기록을 "지갑 × 월 잔액 맞춤"으로 바꾸던 첫 안이 카드 청구서·할부·종목 보유에서 깨져서 **뼈대**로 바꿨고, 재검토에서 뼈대가 지울 지갑의 다리까지 붙잡는다는 지적으로 **보이는 남는 지갑의 다리만** 남기게 좁혔어요(4절). 나머지 지적은 보강했어요.
- [물리 DB 스키마](physical-db-schema.md) 9절의 남은 질문, [MCP](mcp.md) 5.6·8절, [인증](auth.md) 6절에서 넘긴 것을 정해요.

## 1. 한 장 요약

| 항목 | 결정 |
|---|---|
| 두 단계 | **나가기 = 얼리기**(접근만 끊고 데이터는 그대로, 같은 가구로 돌아오면 이어짐). **계정 삭제 = 그 사람만의 데이터 지우기**(개인 장부·숨긴 지갑과 그 감사 기록). 공용 장부 기록은 남기고 사람은 "탈퇴한 가구원"으로 가려요 |
| 지갑 | 나간 사람이 주인인 지갑은 보관하고 나간 날부터 가구 잔액·순자산에서 빠져요(과거 추이는 그대로). 함께 쓰는 지갑만 나갈 때 지갑마다 받을 가구원을 골라 넘겨요 |
| 개인 장부 지우기 | 남은 가구원이 보는 지갑(잔액·청구서)에 닿은 개인 기록은 **뼈대**로 남기고 나머지는 지워요. 뼈대에는 그 지갑들의 다리와 날짜·카드 칸, 통화별 미분류 줄 하나만 남아요. 예상 기록은 지워요. 뼈대는 이름을 바꿔 보관한 그 사람의 개인 장부에 있어 아무도 못 봐요 |
| 감사 기록 | 나가기: 그대로. 계정 삭제: 그 사람의 개인 장부와 지갑의 감사 기록을 전용 롤만 부르는 DB 함수로 지워요. 공용 장부의 감사 기록은 남고 이름만 가려져요 |
| 접근 끊기 | 나가기 트랜잭션 하나에서 멤버 행 `left` → AI 연결 행 삭제 → 갱신 토큰 `revoked` → 세션 전부 삭제 |
| 역할 | **관리자** 1명 + 가구원. 관리자만 초대·내보내기. 관리자가 떠날 땐 본인이 다음 관리자를 고르고, 못 고르면 가장 먼저 들어온 가구원. 마지막 한 명은 나가기 대신 **가구 삭제** |
| 계정 삭제 시점 | **바로**. 안내(남는 것 고지) → 내려받기 권유 → 비밀번호 재입력 → 즉시 차단(삭제 예정 표시로 로그인·초대 수락도 거절), worker가 몇 분 안에 정리 → 완료 메일 |
| 데이터 들고 가기 | **내 데이터 내려받기**(JSON + CSV), 언제든. 범위는 앱에서 내가 볼 수 있는 것 전부. 새 가구로 옮기기는 만들지 않아요 |
| 백업 | 보관 **35일**(HDD·S3 같게), 처리방침에 적어요. **지운 목록**(나가기·넘기기 포함)을 DB 안팎에 남겨 복원 뒤 다시 적용해요 |
| 얼린 데이터 | 나간 사람도 설정 → **이전 가구의 내 데이터**에서 내려받거나 지울 수 있어요. 손대지 않으면 나간 지 **1년** 뒤 자동으로 지워요(30일 전 메일) |

## 2. 두 단계와 데이터별 처리

| 데이터 | 나가기(스스로·내보내기) | 계정 삭제 |
|---|---|---|
| 세션 | 전부 삭제(누른 기기 포함) | user 행과 함께 사라짐 |
| AI 연결 행·갱신 토큰 | 행 삭제, 갱신 토큰 `revoked` | 같음, 토큰 행은 user FK로 삭제 |
| 멤버 행 | `status = left`, `left_at`, 관리자였으면 `role = member`, 이름 유지(화면은 "이름(나감)") | `user_id = NULL`, `display_name = "탈퇴한 가구원"`(같은 가구에 여럿이면 번호) |
| 공용 장부 기록 | 그대로. 쓴 사람·작성자는 "이름(나감)" | 그대로. "탈퇴한 가구원" |
| 개인 장부 기록 | 얼림(아무도 못 봄, 잔액엔 계속 반영) | 보이는 남는 지갑에 닿은 확정 기록은 그 다리만 남긴 뼈대, 나머지(예상 기록 포함)는 지움(4절) |
| 개인 장부의 카테고리·상대·정기 규칙 | 얼림, 정기 규칙은 예정을 만들지 않음 | 지움 |
| 그 사람이 주인인 공개 지갑 | 보관(3절) | 무엇이 가리키면 보관 유지, 아니면 지갑째 지움 |
| 숨긴 지갑·출처 미지정 지갑 | 얼림 | 무엇이 가리키면 보관 유지(그 사람의 개인 다리는 지움), 아니면 지갑째 지움. 잔액이 원래 화면에 없어서 뼈대 다리를 남기지 않아요 |
| 그 사람의 결제수단 | 보관 | 무엇이 가리키면 보관 유지, 아니면 지움 |
| 감사 기록 | 그대로(읽을 때 볼 수 있는 장부만) | 그 사람의 개인 장부와 지갑·결제수단의 행만 지움(5절) |
| 중복 방지 키 | 그대로(7일 뒤 정리) | user FK로 삭제 |
| 홈 설정(`home_layout`) | 그대로(돌아오면 이어짐) | 비움(NULL), [통계 화면 구성](stats-screens.md) 4절 |

- 같은 가구로 돌아오면(초대 수락) 옛 멤버 행이 `active`(`role = member`)로 돌아오고 개인 장부·숨긴 지갑이 그대로 이어져요. 보관된 공개 지갑은 자동으로 풀지 않고 사용자가 풀어요. AI 연결은 다시 맺어요.
- 다른 가구에 들어가도 옛 가구의 얼린 데이터는 남아요. 본인이 지우거나 1년이 지나면 지워져요(8.1).

## 3. 나간 사람의 지갑

- 그 사람이 주인인 지갑은 모두 `archived_at`을 채워요. 다리가 있는 지갑은 지울 수 없으니(물리 DB 스키마 5.8) 공용 기록이 가리키는 지갑 이름은 "A의 국민카드(나감)"처럼 그대로 보여요.
- **잔액·순자산**: 나간 날부터 가구 화면과 순자산에서 빠져요. 나가기 전 달의 월별 자산 추이는 바꾸지 않아요. 보관 지갑을 추이에서 어떻게 그릴지는 통계 화면 구성에서 정해요.
- **함께 쓰는 지갑 넘기기**: `allow_member_use`가 켜진 지갑은 나가기 화면에서 지갑마다 [남는 가구원 중 한 명 / 넘기지 않음]을 골라요. 넘기면 `owner_member_id`를 바꾸고 보관하지 않아요. 받은 사람의 동의는 받지 않고 알림만 보내요(받은 뒤 언제든 보관할 수 있어서). 내보내기면 내보내는 관리자가 골라요.
  - **증권 계좌**는 `wallet_brokerage_settings.ledger_id`가 나가는 사람의 개인 장부면 넘길 수 없어요(받은 사람이 그 장부를 볼 수 없어 매매를 적지 못해요). 공용 장부에 묶인 증권 계좌만 넘길 수 있어요.
- **가족카드**: 다른 가구원의 결제수단이 보관된 카드 지갑을 가리키면 "연결된 카드 지갑이 보관됐어요"로 보여주고 새 기록에는 못 써요.
- **정기 규칙**: 공용 장부 규칙 중 보관된 지갑을 쓰는 것은 "확인 필요"(끊긴 규칙과 같은 동작). 그 사람의 개인 장부 규칙은 예정을 만들지 않아요.

## 4. 계정 삭제 때 개인 장부를 지우는 방법

공용 지갑의 잔액은 장부와 관계없이 그 지갑의 모든 다리를 더해요(통계 질문 목록 A1). 신용카드 지갑의 예상 청구액도 매입일·할부 회차·카드대금으로 계산해요. 그래서 남은 가구원이 보는 지갑에 닿은 개인 기록을 그냥 지우면 잔액·청구서·보유 수량이 실제와 달라져요. 그런 기록은 **뼈대**로 남겨요. 뼈대에는 **남은 가구원이 보는 지갑의 다리만** 남겨요.

이 작업은 worker의 도메인 서비스가 해요(ADR 0012: 업무 규칙은 앱에). 평단 계산·kind 판정을 앱의 순수 계산 모듈과 같은 코드로 쓰려는 거예요. 가구마다 `app` 권한 + 그 가구 설정으로 트랜잭션 하나이고(물리 DB 스키마 2절), 감사 행 지우기만 DB 함수예요(5절).

1. **보이는 남는 지갑**을 정해요: 다른 가구원이 주인인 지갑, 넘겨준 지갑, 그리고 그 사람의 공개 지갑 중 **개인 장부 밖의 행이 가리키는 것**. "가리킨다"는 `wallets`를 가리키는 모든 FK(다른 장부의 다리, 공용 예상 기록의 `expected_wallet_id`, 다른 가구원의 결제수단·페이 연결, 공용 정기 규칙, 청구서, 시스템 예정 건너뜀 등)에서 찾아요. FK 목록은 손으로 적지 않고 카탈로그(`pg_constraint`)에서 만들고, 목록이 바뀌면 깨지는 테스트를 둬요. 숨긴 지갑과 출처 미지정 지갑은 잔액이 원래 다른 사람 화면에 없어서 넣지 않아요. 뼈대의 다리는 이 목록에만 남기므로 목록이 더 늘어나지 않아요.
2. **예상 기록**(`status = expected`)은 개인 장부 것이면 뼈대로 남기지 않고 지워요. 확정하거나 건너뛸 사람이 없어서 남은 가구원의 예상 청구액에 보이지 않는 금액으로 계속 남기 때문이에요.
3. 그 사람의 개인 장부 확정 기록 중 다리가 보이는 남는 지갑에 닿은 것을 **뼈대**로 바꿔요.
   - **다리**: 보이는 남는 지갑의 다리만 남기고 나머지 다리는 지워요. 다리의 `payment_method_id`는 그 결제수단이 남는 결제수단(1단계와 같은 방식으로 정함)일 때만 남기고 아니면 비워요. 청구서는 지갑 단위라 결제수단이 없어도 맞아요.
   - **줄**: 원래 줄을 모두 지우고, kind가 줄을 가질 수 있으면 통화별로 미분류 줄 하나(금액 = 남은 **교환이 아닌 통화 다리**의 합)를 넣어요. 합이 0이면 줄이 없어요. 줄 합 트리거(물리 DB 스키마 3.3)를 그대로 지켜요.
   - **기록 칸**: `kind`, `status`, `date`, 아래 표에서 남기는 칸, `fx_rate`·`fx_rate_date`만 남겨요. 그 밖(`title`, `memo`, 외화 원금, `excluded_from_stats`, `counterparty_id`, `recurring_rule_id`, `spender_member_id`, `expected_wallet_id`, 그리고 표에 없는 연결)은 비우고 `is_fixed`·`spender_shared`는 false예요. 기록의 `payment_method_id`도 다리와 같은 규칙이에요.
   - **연결**: 뼈대 장부는 아무도 통계를 보지 않으니 돌려받은 돈·소멸 같은 줄 역할과 `origin_record_id`·`target_record_id`를 지키지 않아요. 연결을 따라 다른 기록을 끌어오지 않아요.
   - **kind별 처리**:

     | 원래 kind | 뼈대 |
     |---|---|
     | `general`, `refund`, `benefit`, `benefit_reversal`, `settlement`, `settlement_return`, `expiry` | `general`. 미분류 줄. 카드 칸(`purchase_date`, `defer_to_next_bill`, 할부 개월·무이자)과 다리의 `is_estimated`를 남겨서 청구서 배정과 할부 회차가 그대로예요 |
     | `card_payment` | 카드 지갑 다리 하나만 남아도 `card_payment` 그대로(카드대금은 날짜로 청구서에 붙으므로 kind가 있어야 과거·미래 청구서 계산이 같아요). 출금 쪽 다리가 떨어지면 미분류 줄로 합을 맞춰요 |
     | `trade` | 현금·종목 다리가 같은 지갑이라 함께 남거나 함께 사라져요. 그대로 두고 `time`·체결 단가를 남겨요. 매매 비용 줄은 미분류 줄로 합쳐요 |
     | `fx_exchange` | 두 지갑이 모두 남으면 그대로. 한쪽만 남으면 `balance_adjustment`로 바꾸고 `is_exchange`를 끄고 줄 0개 |
     | `security_transfer`(같은 장부) | 두 계좌가 모두 남으면 그대로. 한쪽만 남으면 `balance_adjustment`로 바꾸고, 남는 종목 다리의 `unit_price`에 그 시점 출발 계좌 평단을 적어요(잔액 맞춤은 시작 평단 필수) |
     | `security_transfer_out` | 출발 계좌가 남으면 그대로(공용 입고 기록이 계속 가리켜요). 아니면 5단계 |
     | `corporate_action` | 그대로, `corporate_action_type`을 남겨요(병합과 상장폐지를 가르는 유일한 칸) |
     | `dividend` | 그대로, 배당 칸(`dividend_event_id`, `dividend_wallet_id`, 주당액, 기준 수량)을 남겨요. 같은 배당을 다시 제안하지 않게 하는 유니크가 이 칸이에요 |
     | `balance_adjustment` | 그대로(줄 없음) |

     `balance_adjustment`로 바꿀 때는 줄을 0개로 하고 카드 칸을 비워요(kind별 금지 칸 CHECK). 증권 계좌 다리가 있는 기록만 `time`을 남겨요(같은 날 순서가 평단을 정해서요).
4. 나머지 개인 장부 기록, 그 장부 전용 카테고리·상대·정기 규칙을 지워요.
5. **장부가 다른 이관**: 지워지는 개인 장부의 `security_transfer_out`을 공용 장부의 `security_transfer_in`이 가리키면(`target_record_id`, NO ACTION), 4단계 전에 입고 기록을 `balance_adjustment`로 바꾸고 종목 다리에 그때의 출발 계좌 평단을 시작 평단으로 적어요. 공용 증권 계좌의 평단이 그대로예요. 남은 가구원이 보는 기록이 바뀌는 것이라 이 변경은 감사 기록에 남겨요(입구 `worker`, 행위자 NULL).
6. 1단계에서 남지 않는다고 정한 그 사람의 지갑·결제수단을 지워요. 지갑째 지운 지갑은 가구의 과거 자산 추이에서도 빠져요(그 사람만의 돈이었으므로). 여기서 FK 위반이 나면 1단계 판정이 틀린 것이라 조용히 보관하지 않고 그 가구 트랜잭션을 되돌리고 운영자에게 알려요(일부 다리만 남은 지갑이 틀린 잔액으로 남는 것을 막아요).
7. 장부 이름을 "탈퇴한 가구원"으로 바꾸고 보관해요. 개인 장부라 아무도 볼 수 없어요. 뼈대가 하나도 없으면 장부도 지워요.

- 남은 가구원이 보는 것은 탈퇴 전과 같아요(잔액·청구서 합계만, 개인 기록 내용은 원래도 안 보임). 남는 정보는 "그 지갑에서 그날 얼마"와 청구서·평단 계산에 필요한 칸뿐이고, 남기는 이유는 "남은 가구원의 잔액과 청구서를 맞게 유지"예요. 그 지갑이 가구에 있는 동안 남고, 계정 삭제 화면과 처리방침에서 고지해요(11절).
- 나갔던 가구가 여럿이면 가구마다 따로 해요. 한 가구가 실패하면 그 가구만 되돌려 재시도하고, 세 번 실패하면 운영자에게 알려요(사용자는 이미 접근이 막혀 있어요).
- 같은 처리를 얼린 데이터 지우기(8.1)와 1년 기한에도 써요.

## 5. 감사 기록

- 나가기: 손대지 않아요. 감사 기록을 읽을 때도 볼 수 있는 장부만 보이므로(물리 DB 스키마 5.4) 개인 장부의 행은 아무도 못 봐요.
- 계정 삭제·얼린 데이터 지우기·가구 삭제: 4절(또는 가구 데이터 삭제)은 worker가 하고, 감사 행 지우기만 **`erase_member_audit(member_id)`·`erase_household_audit()` 두 함수**가 해요.
  - **worker 전용 로그인 롤**만 실행할 수 있어요. `app` 권한을 api용과 worker용 두 로그인 롤로 나누고(둘 다 `app` 권한을 물려받음), 함수의 EXECUTE는 worker 롤에만 줘요. API·MCP는 부를 수 없어요. 8.1의 [지우기]도 API가 큐에 넣고 worker가 실행해요.
  - 함수는 SECURITY DEFINER, `owner` 소유, `search_path` 고정, PUBLIC 실행 권한 회수예요. `audit_log`에도 `FORCE ROW LEVEL SECURITY`가 걸려 있어서 함수 안에서도 worker 트랜잭션이 설정한 `app.household_id`의 행만 보이고 지워져요.
  - `erase_member_audit`은 그 멤버가 나감 상태인지 먼저 확인하고(계정 삭제는 6절 순서상 이미 나감), 그 멤버 개인 장부의 행과 그 멤버가 주인이었던 지갑·결제수단의 행만 지워요. 공용 장부의 감사 행은 조건에 맞지 않아 지울 수 없어요.
  - 트랜잭션의 **맨 끝**에 불러요. 4절이 뼈대·삭제를 하면서 남긴 감사 행(바뀌기 전 모습에 개인 내용이 들어 있음)까지 지우기 위해서예요. 4절 5단계의 공용 입고 기록 변경 행은 공용 장부 행이라 남아요.
  - `erase_household_audit`은 가구 삭제 때 그 가구의 모든 감사 행을 지워요(7절).
- 공용 장부의 감사 행은 남아요. `actor_member_id`가 멤버 행을 가리키니 이름이 "탈퇴한 가구원"으로 바뀌면 화면도 가려져요.
- `ai_connection_id`는 남고 연결 행은 지워져서 "해지된 연결"로 보여요(MCP 4.3).

## 6. 접근 끊기

나가기는 트랜잭션 하나예요(계정·가구 경계 테이블과 Better Auth 테이블은 같은 Postgres에 있고 RLS가 없어요).

1. `household_members`: `status = 'left'`, `left_at = now()`, 관리자였으면 `role = 'member'`와 다음 관리자 지정(7절). 앱 API와 `/mcp`는 요청마다 활동 멤버십을 보므로 이 순간 막혀요(서버 아키텍처 15번, MCP 5.4).
2. 그 멤버의 `ai_connections` 행을 지워요.
3. 그 사용자의 그 클라이언트들에 대한 `oauthRefreshToken`에 `revoked = now()`를 적어요. 행은 user FK로 계정 삭제 때 지워져요.
4. 그 사용자의 `session`을 모두 지워요. 쿠키 캐시를 껐으니 다음 요청부터 세션이 없어요(인증 2.2). 누른 기기도 로그인 화면으로 가요.
5. 지갑 보관·넘기기, 정기 규칙 표시(3절).
6. 지운 목록에 `leave` 줄(9절).

폰에 남은 것: 나간 사람의 폰은 다음 요청에서 401을 받아요. 보내지 못한 새 기록(대기열)은 지우지 않고 남겨서, 다시 로그인했을 때 403이면 "보내지 못한 기록"으로 보여주고 사람이 버리게 해요. 조회 캐시는 다시 로그인했는데 가구가 없거나 바뀌었을 때 지워요. 계정 삭제는 로그인 거절 응답으로 알고 대기열과 캐시를 모두 지워요([모바일 입력 UX 원칙](mobile-input.md) 10.3).

Better Auth API를 따로 부르지 않는 이유: 멤버는 나갔는데 토큰이 남는 중간 상태를 없애려고요. MCP PoC의 해지도 같은 SQL로 했고 다음 요청 401, 갱신 `invalid_grant`를 확인했어요.

**계정 삭제 순서**

1. 요청 처리(동기, 트랜잭션 하나): 비밀번호 재확인 → 활동 가구가 있으면 위 나가기 절차(관리자 넘기기 포함, 마지막 한 명이면 가구 삭제 예약) → `user.deletion_requested_at = now()` → 세션 전부 삭제 → 정리 작업을 큐에 넣어요(작업 데이터에 완료 메일용 이메일). 큐가 같은 Postgres라 함께 커밋돼요.
2. `deletion_requested_at`이 있으면 로그인(앱·`/oauth/login`), 세션 생성, 초대 수락, 비밀번호 재설정을 모두 거절해요. Better Auth의 로그인 전 훅에서 막아요.
3. worker: 그 사용자의 멤버 행이 있는 가구마다(활동·나감 모두) 4절 + `erase_member_audit`을 트랜잭션 하나로 → 멤버 행 이름 바꾸기 → 지운 목록 `account` 줄.
4. worker: `user` 행 삭제. FK로 `session`·`account`·OAuth 토큰·`idempotency_keys`가 함께 지워지고 `household_members.user_id`는 `SET NULL`. `verification`은 user FK가 없으니(식별자가 이메일) 그 이메일의 행을 직접 지워요.
5. 완료 메일을 보내고 작업 데이터의 이메일을 버려요.

## 7. 역할과 내보내기

- `household_members.role`: `admin` | `member`. 가구마다 활동 관리자 한 명(부분 유니크 `(household_id) WHERE role = 'admin' AND status = 'active'`). 관리자가 나가면 그 행은 `member`로 내려서, 나중에 돌아와도 유니크에 걸리지 않아요.
- 관리자만 초대하고 **내보내요**. 나머지 권한(기록, 공용 장부)은 같아요. 관리자를 내보낼 사람은 없어요.
- 내보내기는 나가기와 같은 처리예요. 내보낸 사람도 그 사람의 개인 장부를 볼 수 없어요. 내보내진 사람에게 메일로 알려요.
- 관리자가 나가거나 계정을 지울 때 남는 사람 중 다음 관리자를 골라요. 한 명이면 자동이고, 고르지 못하면(운영자 처리 등) **가장 먼저 들어온 활동 가구원**이에요. 관리자가 연락 없이 사라지는 경우는 문제가 되면 운영자 처리나 미사용 넘기기를 더해요.
- **가구 삭제**: 마지막 활동 가구원은 나가기 대신 가구 삭제만 할 수 있어요(돌아올 초대가 없으니). 가구 소유 데이터, 감사 기록(`erase_household_audit`), 멤버 행(나갔던 사람 것 포함), 그 가구의 `ai_connections`·초대까지 모두 지워요. "멤버 행은 지우지 않는다"의 유일한 예외예요(가구 자체가 사라지므로). 마지막 한 명이 계정을 지우면 가구 삭제도 함께 해요. 지운 목록에 `household` 줄.

## 8. 내 데이터 내려받기

- 설정 → 내 데이터 내려받기. 나가기·계정 삭제 화면에도 같은 버튼.
- 범위: 앱에서 내가 볼 수 있는 것 전부(공용 장부 + 내 개인 장부, 지갑, 결제수단, 카테고리, 정기 규칙, 홈 설정). AI 연결과 같은 "그 사람이 보는 만큼" 규칙이라 새로 드러나는 건 없어요.
- 형식: JSON(다리·줄까지 전부, 계약의 스키마 이름 그대로)과 CSV(기록 한 줄, 줄이 여럿이면 줄마다 한 줄). iOS 공유 시트로 건네요.
- 새 가구로 옮기기는 만들지 않아요(ID 짝짓기·잔액 이어 붙이기가 전환을 하나 더 만드는 일). 요구가 생기면 JSON을 개인 장부로 가져오는 기능으로 더해요.
- 법적 의무(전송요구권)는 없어요(리서치 2절).

### 8.1 나간 사람의 얼린 데이터

나가거나 내보내진 사람은 옛 가구에 접근할 수 없어서, 그대로면 계정 전체를 지워야만 자기 개인 장부를 정리할 수 있고 보관도 무기한이 돼요. 그래서 본인 정리와 기한을 둬요.

- **설정 → 이전 가구의 내 데이터**: 나간 멤버 행이 있는 가구마다 한 줄.
  - [내려받기]: **내 개인 장부와 내가 주인인 지갑·결제수단**만이에요. 공용 장부는 넣지 않아요(나간 뒤 남은 가구원이 고치거나 과거 날짜로 넣은 기록이 섞이고, 내보낸 관리자의 "접근 차단" 기대와도 어긋나서요). 공용 기록이 필요하면 나가기 전에 8절 내려받기로 받아요. 형식은 8절과 같아요.
  - [지우기]: 비밀번호를 다시 확인하고 큐에 넣어요. worker가 4절 + `erase_member_audit`을 그 가구에만 해요(뼈대를 남기고 나머지와 그 감사 행을 지움). 멤버 행은 나감 상태로 이름도 그대로 남아요(계정은 살아 있으니까요). 옛 개인 장부는 "정리된 개인 장부"로 이름을 바꿔 보관해요.
  - 이 화면만은 활동 멤버십이 아니라 "그 사용자의 나간 멤버 행"으로 접근 문맥을 만들어요. 읽기 범위는 그 멤버의 개인 장부와 그 멤버가 주인인 지갑·결제수단이고, 쓰기는 [지우기] 요청뿐이에요.
- **1년 기한**: 나간 지 1년이 지나면 worker가 [지우기]와 같은 처리를 해요. 30일 전에 메일로 알리고, 그 사이에 같은 가구로 돌아오면 지우지 않아요.
- **내보내진 사람**에게 가는 메일에 "1년 동안 설정에서 내려받거나 지울 수 있어요"를 안내해요.
- 지운 뒤 같은 가구로 돌아오면 새 개인 장부를 만들어요. 정리된 옛 장부는 보관 상태로 남아 뼈대만 담아요.

## 9. 백업과 지운 목록

- pgBackRest 보관 기간 **35일**(HDD·S3 같게, 주 1회 전체 백업 5개 정도). 개인정보처리방침에 "탈퇴 후 최대 35일 동안 백업에 남았다가 지워짐"을 적어요.
- **`erasure_log`**(운영 테이블, RLS 없음): 백업을 옛 시점으로 되돌린 뒤 같은 결과를 다시 만들 수 있을 만큼 남겨요. 개인정보(이름·이메일·기록 내용)는 넣지 않아요.
  - `id`, `kind`(`leave`·`rejoin`·`left_data`·`account`·`household`), `household_id`, `member_id`, `user_id`, `payload`(jsonb), `created_at`, `exported_at`.
  - `leave`: 넘긴 지갑과 받은 멤버, 다음 관리자. 나가기 처리를 다시 하면 세션·연결·토큰도 다시 끊겨요(내보내진 사람이 복원으로 다시 들어오지 못하게).
  - `rejoin`: 다시 들어온 멤버. 복원 뒤 `leave`만 다시 적용돼 밖에 남는 일을 막아요.
  - `left_data`·`account`: 대상 멤버와, 확인용으로 뼈대로 만든·지운 ID 목록.
  - `household`: 가구 ID.
- **DB 밖에도 남겨요**(HDD와 S3의 추가 전용 파일). DB를 옛 시점으로 되돌리면 DB 안의 목록도 옛날로 돌아가기 때문이에요.
  - 순서: DB 트랜잭션에서 행을 넣고 커밋한 뒤, worker가 `exported_at`이 빈 행을 파일에 덧붙이고 `exported_at`을 채워요. 파일 쓰기가 실패하면 다음 주기에 다시 해요(같은 `id`는 한 번만 적용되므로 두 번 적혀도 괜찮아요).
  - 복원 절차에 한 단계를 더해요: 복원 시점 이후의 줄을 `id` 순서대로 다시 실행해요. 지우기 줄은 ID 목록이 아니라 **멤버 기준으로 같은 함수를 다시 부르고**(복원 시점과 삭제 사이에 본인이 지운 기록도 함께 정리되도록), ID 목록은 결과 확인에만 써요. 이미 처리된 것은 건너뛰어요.
- 전환 보관본(기존 oat 덤프)의 보관 기간은 전환 당일 절차에서 정하고, 탈퇴자에게도 같은 기준을 적용해요.

## 10. 스키마 변경

- `household_members.role` 값(`admin`·`member`)과 활동 관리자 부분 유니크. `display_name`은 계정 삭제 때 바꿔요.
- `user.deletion_requested_at`(Better Auth `additionalFields`).
- `household_members.personal_erased_at`(얼린 데이터를 지운 시각, 화면 표시용), `left_data_notice_at`(1년 기한 30일 전 메일을 보낸 시각).
- `user` 삭제 FK: `session`·`account`·OAuth 토큰·`idempotency_keys`는 CASCADE, `household_members.user_id`는 `SET NULL (user_id)`. `verification`은 FK 없음(이메일로 직접 지움).
- `erasure_log` 테이블(운영).
- `erase_member_audit(member_id)`·`erase_household_audit()` 함수(SECURITY DEFINER)와, `app` 권한을 api용·worker용 로그인 롤로 나눠 worker 롤에만 실행 권한.

## 11. 화면

- 설정 → 가구: 가구원 목록, (관리자) 초대·내보내기, 나가기.
- 나가기 화면: 끊기는 것(세션·AI 연결), 얼려 두는 것, 함께 쓰는 지갑 넘기기(증권 계좌는 공용 장부에 묶인 것만), (관리자) 다음 관리자, 내려받기.
- 설정 → 이전 가구의 내 데이터: 가구마다 나간 날, 자동 삭제 예정일, [내려받기]·[지우기].
- 계정 삭제 화면: 지워지는 것과 **남는 것** 고지(공용 장부 기록은 "탈퇴한 가구원"으로 남음, 남은 가구원의 잔액·청구서에 쓰인 내 개인 기록은 날짜·금액만 남음), 내려받기, 비밀번호, [삭제].

## 12. 구현 때 통합 테스트

- 나가기 직후: 남은 액세스 토큰으로 `/mcp` 401, 갱신 `invalid_grant`, 모든 기기 세션 없음, 앱 API 401.
- 다시 들어오면 개인 장부·숨긴 지갑이 이어지고 AI 연결은 없음, 옛 관리자도 `member`로 들어옴.
- 나간 뒤 폰: 대기열은 남고 다시 로그인하면 403 → 보내지 못한 기록, 다시 초대된 뒤에는 그대로 보내짐. 다른 가구로 들어가면 옛 가구의 뼈대·제안 캐시를 쓰지 않음. 계정 삭제 뒤 폰의 대기열·캐시가 지워짐.
- 계정 삭제 요청 뒤 worker 전: 로그인·`/oauth/login`·초대 수락이 거절됨.
- 계정 삭제 뒤: 남은 지갑의 현재 잔액·월말 잔액, 신용카드 지갑의 예상 청구액(남은 할부 포함, 예상 기록 제외분만 다름), 증권 계좌의 보유 수량·평단이 삭제 전과 같음. 뼈대에 제목·메모·카테고리·품목 이름이 없고 보이는 남는 지갑 밖의 다리가 없음. 개인 통장과 공동 통장 사이 이체가 있어도 개인 통장이 지갑째 지워짐. 지운 것과 뼈대의 감사 행 0건. 공용 기록·감사 행은 그대로. `user_id` NULL.
- 4절 6단계에서 FK 위반이 나면 그 가구 트랜잭션이 되돌려지고 운영자 알림이 감.
- api 롤로는 감사 지우기 함수를 실행할 수 없음. 활동 멤버 대상으로 부르면 아무것도 지우지 않음. 공용 장부 감사 행은 남음.
- kind별 뼈대: 남의 카드 지갑으로 보낸 카드대금, 할부 지출, 해외 추정 다리, 한쪽만 남는 환전·같은 장부 이관, 권리 변동, 배당이 있을 때 과거에 확정한 청구서의 "설명되지 않은 차이"와 남은 증권 계좌의 평단·실현손익이 삭제 전과 같음. 줄 합 트리거와 kind별 CHECK를 통과함.
- `wallets`를 가리키는 FK를 새로 더하면 1단계 판정 테스트가 깨짐.
- 나간 사람이 이전 가구의 내 데이터를 내려받을 때 공용 장부와 다른 가구원의 개인 장부가 없음. 1년 기한 처리 뒤 결과가 [지우기]와 같음.
- 복원 뒤 지운 목록을 다시 적용하면 같은 결과(넘긴 지갑의 주인, 내보낸 사람의 접근 차단, 다시 들어온 사람의 활동 상태 포함).
