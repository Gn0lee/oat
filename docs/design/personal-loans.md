# 빌려준 돈·빌린 돈

- 결정일: 2026-11-23
- 티켓: [빌려준 돈·빌린 돈: 가구 밖 개인 사이의 채권·채무](https://github.com/Gn0lee/oat/issues/532)
- 관련 ADR: 0030(빌려준 돈·빌린 돈은 사람마다 지갑이다), 0004(기록은 지갑별 다리), 0006(돌려받은 돈은 원 기록의 달), 0016(묶음, 여섯 번째 묶음 추가로 수정), 0025(개인 기록 합계 한 줄), 0027(입력 퍼널), 0028(보내는 중 대기열), 0029(할 일 알림)
- 리서치: [개인 간 대여 기록 사례 조사](../research/2026-11-23-personal-loans-cases.md). 검증: [시나리오 계산기와 목업](../research/2026-11-23-loans-poc/) (`node docs/research/2026-11-23-loans-poc/scenario.mjs`, 확인 11개 통과, 결과는 `result.txt`)
- 리뷰: 독립 리뷰어(Fable 5.2)가 한 번 검토했어요. 다시 빌려줄 때 옛 갚기로 한 날, 외화 대여, 새 지갑과 대기열, 음수 잔액·보관 지갑의 할 일, 나가기 때 공용 대여, 숨긴 지갑과 공용 기록, 갚은 원금 정의, 카드로 대신 결제, 섞인 결제와 남이 대신 낸 지출, 문서 불일치를 반영했어요.
- [지출의 일부를 돌려받는 돈](https://github.com/Gn0lee/oat/issues/524)에서 "상대를 붙이는 곳"을 정산으로 좁히고 빌려준 돈을 미룬 것을 정해요. 기존 oat에는 이 기능이 없어서 전환 영향은 없어요.

## 1. 한 장 요약

| 항목 | 결정 |
|---|---|
| 기록 위치 | 사람마다 **지갑** 하나. 빌려주기·돌려받기·갚기는 **이체**(다리 합 0)라 수입·지출이 아니에요 |
| 지갑 종류 | 새 kind 둘: `lent`(**빌려준 돈**, 자산), `borrowed`(**빌린 돈**, 부채). 은행 대출(`loan`)과 나눠요 |
| 상대 | 지갑에 **상대**를 연결하지 않아요. 지갑 이름이 사람이에요(은행 대출 지갑과 같음) |
| 묶음 | 여섯 번째 묶음 **빌려준 돈**(`lent`). `lent` kind만, 늘 이 묶음. 빌린 돈은 갚아야 할 돈 |
| 통화 | 처음 보낸(받은) 지갑의 통화로 자동. 이후 같은 통화 지갑끼리만 빌려주고 받아요 |
| 이자 | 갚는 기록 안의 수입 줄(받은 이자)·지출 줄(낸 이자). 은행 대출과 같아요 |
| 탕감 | **탕감한 날의 지출**(기본 카테고리 "못 받은 돈"), 빌린 쪽은 **탕감받은 날의 수입**("갚지 않아도 된 돈"). 카테고리는 선물 등으로 바꿀 수 있어요 |
| 정산과의 경계 | "그걸 내(우리 가구)가 썼나?" 썼으면 지출 + 정산, 안 썼으면 빌려준 돈. 정산을 빌려준 돈으로 바꾸는 기능은 없어요 |
| 남의 것을 함께 결제 | 지출 퍼널 확인 화면의 조건부 칸 `일부는 남의 것`(누구 + 금액). 카드 칸(할부·해외·매입일)이 그대로 쓰여요. 남이 내 지출을 대신 냈으면 "어디서 냈어요?"에서 빌린 돈 지갑을 골라요 |
| 갚기로 한 날 | 지갑의 선택 칸. 지났는데 아직 받을(갚을) 잔액이 남으면 **할 일** 한 번(키 `loan_due:{지갑}:{날짜}`). 날짜가 없으면 알리지 않아요. 다 갚은 지갑에 다시 잔액이 생기면 비워요 |
| 홈 | "받을 돈" 카드는 정산·혜택만 그대로. 빌려준 돈 전체는 자산 탭 묶음, 기한 지난 것만 홈 "확인할 것" |
| 입력 | 이체 퍼널의 받는/보내는 지갑 목록 맨 아래 `+ 새로 빌려주기`·`+ 새로 빌리기`(이름만, **온라인에서만**). 지갑 상세에 `받았어요`·`안 받기로 했어요`(빌린 돈은 `갚았어요`·`안 갚아도 된대요`)와 갚기로 한 날 줄 |
| 공개 범위 | 퍼널에서 고른 장부를 따라가요. 공용 장부 → 가구가 보는 **함께 쓰는 지갑**, 개인 장부 → 가구에서 숨긴 지갑. 숨긴 대여 지갑은 주인의 개인 장부 기록에만 써요 |
| 다 갚은 지갑 | 다리가 있었고 잔액 0이면 화면에서 "다 받음/다 갚음 N명"으로 접어요(계산, 저장 없음). 다시 빌려주면 같은 지갑을 써요 |
| 흐름 | "갚은 대출 원금" → **갚은 원금**(대출 + 빌린 돈, 자산에서 나간 금액까지만). 빌려준 돈은 흐름에 줄이 없어요 |
| AI 연결 | 새 툴 없음. `add_transfer`·`add_spending`·`add_income`으로 적고(`add_spending`에 남의 몫 선택 인자), 지갑은 앱에서 만들어요 |

## 2. 왜 지갑인가

빌려준 돈은 쓴 돈이 아니라 받을 권리가 남은 돈이에요. oat에서 잔액이 있는 것은 모두 지갑이고(ADR 0004), 다리 합이 0이면 이체예요. 그래서 철수에게 100만 원을 보내면:

| 지갑 | 다리 |
|---|---|
| 우리은행 | −1,000,000 |
| 철수(빌려준 돈) | +1,000,000 |

지출이 아니고 순자산도 그대로예요. 철수 지갑의 잔액이 곧 아직 받을 돈이에요. 사례 조사에서도 Firefly III·YNAB·GnuCash가 같은 방식(받을 돈 자산 계좌로 옮기는 이체)을 안내해요.

받아들이지 않은 안:

- **지갑 없이 기록에 상대만**: 다리 합이 0이 아니라 지출이 되고, 막으려면 통계 제외를 켜야 해요. 순자산에서 빌려준 돈이 사라지고 "잔액이 있으면 지갑" 규칙이 깨져요.
- **"빌려준 돈" 지갑 하나 + 다리마다 상대**: 사람별 잔액을 보려면 다리에 상대 칸과 규칙이 생겨서 지갑 모델을 고쳐야 해요.

### 2.1 은행 대출과 같은 점, 다른 점

문법은 같아요(잔액 있는 지갑, 원금은 이체, 이자는 줄). 다른 건 사람 사이의 사정이에요.

| | 은행 대출(`loan`) | 빌린 돈(`borrowed`) / 빌려준 돈(`lent`) |
|---|---|---|
| 상대 | 금융기관 | 친구·가족 |
| 방향 | 빌린 것만 | 둘 다 |
| 상환 | 정기 규칙(매달) | 아무 때나 |
| 이자 | 거의 항상 | 대개 없음 |
| 탕감 | 거의 없음 | 흔함 |
| 화면 문구 | 대출 잔액 | 철수에게 받을 돈 / 엄마에게 갚을 돈 |

kind를 나눠서 화면 문구·갚기로 한 날·탕감 버튼이 은행 대출과 섞이지 않아요. 방향 칸 하나로 합치는 안(Firefly III 방식)은 "자산/부채는 kind가 정한다"와 묶음 CHECK를 고쳐야 해서 받아들이지 않았어요.

### 2.2 상대를 연결하지 않는 이유

**상대**는 장부에 속하고(공용 장부의 상대는 가구 모두, 개인 장부의 상대는 만든 사람만), 지갑은 장부에 속하지 않아요(주인과 숨김 설정이 공개 범위). 둘을 이으면 가구가 보는 지갑에 개인 장부 상대가 붙어 이름이 새어 나갈 수 있고, 막으려면 "지갑을 보는 사람 모두가 볼 수 있는 장부의 상대만" 같은 규칙과 공개 범위 변경 때 재검사가 필요해요. 사람 사이 대여는 한 사람에 한두 건이라, 같은 사람의 정산과 대여를 한 줄로 합치는 이득보다 비용이 커요. 필요해지면 `wallets.counterparty_id`를 더하는 변경(칸 추가)으로 열 수 있어요.

## 3. 기록 문법

부호는 [물리 DB 스키마](physical-db-schema.md) 3절과 같아요(들어오면 +, 수입 줄 +, 지출 줄 −). 예시는 [시나리오 계산기](../research/2026-11-23-loans-poc/scenario.mjs)에 있는 그대로예요.

| 상황 | 다리 | 줄 | 통계 |
|---|---|---|---|
| 철수에게 100만 빌려줌 | 통장 −100만, 철수 +100만 | 없음 | 없음(이체) |
| 친구 물건 5만 원을 내 카드로 대신 결제 | 카드 −5만, 친구 +5만 | 없음 | 없음(4절, 지출 퍼널의 남의 몫) |
| 내 것 3만 + 지수 것 5만을 한 번에 카드 결제 | 카드 −8만, 지수 +5만 | 지출 −3만 | 지출 3만 |
| 엄마가 내 병원비 5만을 대신 냄 | 엄마 −5만 | 지출 −5만(의료) | 지출 5만 |
| 철수가 51만 갚음(이자 1만) | 통장 +51만, 철수 −50만 | 수입 +1만(이자) | 수입 1만 |
| 철수 30만 안 받기로 함 | 철수 −30만 | 지출 −30만(못 받은 돈) | 그날 지출 30만 |
| 엄마에게 300만 빌림 | 엄마 −300만, 통장 +300만 | 없음 | 없음 |
| 엄마에게 100만 갚음 | 통장 −100만, 엄마 +100만 | 없음 | 갚은 원금 100만 |
| 엄마가 50만 안 갚아도 된대요 | 엄마 +50만 | 수입 +50만(갚지 않아도 된 돈) | 그날 수입 50만 |
| 엄마 돈 100만으로 전세대출을 갚음 | 엄마 −100만, 대출 +100만 | 없음 | 갚은 원금 0(빚을 갈아탄 것) |

- 모두 `kind = general`이에요. 새 기록 kind는 없고, 지갑 kind와 줄로 구분해요. 지갑이 이미 있으면 보내는 중 대기열(ADR 0028)에 들어갈 수 있어요(탕감·이자·남의 몫 포함). **새 지갑을 만드는 `+ 새로 빌려주기`는 온라인에서만** 돼요. 지갑 id가 서버에서 정해지고, 대기열은 새 기록만 담아요(ADR 0028).
- 탕감을 지출로 세는 이유: 실제로 내 돈이 사라진 것이고, 예상 정산을 "받지 않기"로 지우면 내 부담으로 남는 규칙과 같아요. 통계 제외는 "나를 거쳐 가기만 한 돈"에만 써요. 빌려준 달로 소급하지 않는 이유: 빌려줄 때는 받을 생각이었고 지난 통계가 바뀌어요.
- 시스템 카테고리 둘을 더해요: "못 받은 돈"(지출), "갚지 않아도 된 돈"(수입). `system_key`로 찾고 이름은 가구가 바꿀 수 있어요. 고정비 기본값은 꺼짐이에요.
- **통화**: 빌려준 돈·빌린 돈 지갑의 통화(`wallets.currency`)는 처음 보낸(빌릴 때는 받은) 지갑의 통화로 자동으로 정해요. 달러 현금을 빌려주면 달러 지갑이에요. 이후에는 같은 통화 지갑끼리만 빌려주고 받아요. 원화로 빌려주고 달러로 받은 것처럼 통화가 다르면 "통화가 달라요. 받은 지갑의 금액을 원화로 적어 주세요"로 안내해요(한 기록에 두 통화를 담으면 통화별 줄 합 규칙에 걸리고, 환전 기록은 퍼널 밖이에요). 환율 차이는 따로 세지 않아요.
- 앱을 쓰기 전부터 있던 대여는 지갑을 만든 뒤 지갑 화면의 잔액 맞춤으로 시작 잔액을 넣어요. 잔액 맞춤은 흐름과 갚은 원금에 들어가지 않아요.
- 가구원 사이 대여는 범위 밖이에요. 가구 안의 돈은 가구원 지갑 사이 이체로 적어요.

## 4. 정산과의 경계

둘 다 "나중에 받을 돈"이지만 통계에서 움직이는 방식이 달라요. 정산은 내 지출로 적은 뒤 받은 만큼 그 달 지출을 줄이고(ADR 0006), 빌려준 돈은 처음부터 지출이 아니에요.

**기준: 그 돈으로 산 것을 내(우리 가구)가 썼나?**

| 상황 | 기록 |
|---|---|
| 밥값 4만 원 내고 친구 몫 2만 원 받을 예정(같이 먹음) | 지출 4만 + 예상 정산 2만 |
| 친구 물건을 내 카드로 대신 결제 | 지출 퍼널 + 남의 몫 전부 → 카드 → 친구 지갑 이체 |
| 내 것과 친구 것을 한 번에 결제 | 지출 퍼널 + 남의 몫 일부 → 내 몫만 지출 |
| 철수에게 계좌로 100만 원 | 이체 퍼널 → 빌려준 돈 |
| 회사 출장비를 내 카드로 내고 회사가 줄 예정 | 지출 + 예상 정산(내가 출장에서 씀) |
| 엄마가 내 병원비를 대신 냄 | 지출 퍼널, 낸 곳 = 엄마(빌린 돈 지갑) |

- 같이 먹은 밥값처럼 **한 물건을 나눠 쓴 것**은 정산이고, **물건 자체가 남의 것**이면 남의 몫이에요.
- "결제했으면 정산"으로 나누면 받을 때까지 이번 달 지출과 평소 대비 페이스가 남의 물건으로 부풀어서 받아들이지 않았어요.
- 정산으로 적었다가 오래 못 받아도 빌려준 돈으로 바꾸는 기능은 두지 않아요. 원 기록의 지출 줄까지 고쳐야 해서예요. 못 받으면 지금처럼 "받지 않기"로 내 부담이 돼요.

## 5. 지갑 칸과 묶음

- `wallets.kind`에 `lent`·`borrowed`를 더해요(추가만). 자산/부채는 kind에서 정해요: `lent` 자산, `borrowed` 부채.
- `wallets.stats_group`에 `lent`(빌려준 돈)를 더해요. CHECK: `kind = 'lent'` ⇔ `stats_group = 'lent'`, 부채 kind(`credit_card`·`loan`·`borrowed`)는 `liability`. 다른 자산 지갑은 `lent`를 고를 수 없어요.
- `wallets.repay_due_date`(date, NULL 허용, `lent`·`borrowed`만 CHECK): **갚기로 한 날**. 고칠 수 있어요. 잔액이 0인(다리가 있었던) 지갑에 다시 잔액이 생기는 기록을 저장하면 서버가 이 칸을 비우고, 그 요청에 새 날짜가 있으면 그 날짜를 넣어요. 옛 약속이 새 대여에 남지 않게요.
- 묶음 순서: 쓸 수 있는 돈, 모으는 돈, 투자, 포인트·상품권, **빌려준 돈**, 갚아야 할 돈. 빌려준 돈 지갑이 없으면 묶음이 보이지 않아요(잔액 0인 지갑만 있으면 "다 받음 N명"만).
- 월별 자산 추이의 묶음 색이 여섯 개가 돼요(디자인 스펙).
- 묶음 이름은 "받을 돈"이 아니라 **빌려준 돈**이에요. 홈 "받을 돈" 카드(예상 정산·혜택)와 헷갈리지 않게요.

| 흐름 | 순서 |
|---|---|
| 빌려주기 | `+` → `이체` → 어느 장부?(하나면 건너뜀) → 금액 → 보내는 지갑 → 받는 지갑 목록 맨 아래 `+ 새로 빌려주기` → 누구에게?(이름) → 확인. 이름만 받고 지갑이 그 자리에서 생겨요(온라인에서만, 통화는 보내는 지갑과 같음). 갚기로 한 날은 확인 화면의 조건부 칸(선택) |
| 빌리기 | 같은 순서, 보내는 지갑 목록 맨 아래 `+ 새로 빌리기` |
| 카드로 남의 것을 결제 | `+` → 지출 → … → 확인 화면의 조건부 칸 `일부는 남의 것` → 누구?(빌려준 돈 지갑, `+ 새로 빌려주기` 포함) → 금액(기본 전액). 결제수단·할부·해외·매입일 칸은 지출과 같아요. 확인 화면은 "지출 ○원 · 지수에게 빌려줌 ○원" |
| 남이 내 지출을 대신 냄 | 지출 퍼널 "어디서 냈어요?" 목록에 빌린 돈 지갑이 보여요 |
| 돌려받기·갚기 | 이체 퍼널(빌려준 돈 지갑은 목록에 "빌려준 돈" 꼬리표) 또는 지갑 상세 `받았어요`/`갚았어요`. 상세 버튼은 `이자 포함` 스위치로 원금·이자 칸을 펼쳐요 |
| 탕감 | 지갑 상세 `안 받기로 했어요`/`안 갚아도 된대요` → 금액(기본 남은 잔액) → 카테고리(기본 시스템 카테고리) → 확인. "○원이 오늘 지출(수입)로 잡혀요" 안내 |

- 퍼널의 첫 단계 네 갈래(ADR 0027)는 그대로예요. 드문 기록 때문에 매일 쓰는 메뉴를 늘리지 않아요.
- 카드로 남의 것을 결제할 때 이체 퍼널이 아니라 지출 퍼널을 쓰는 이유: 신용카드 다리는 결제수단(카드 한 장)·할부·매입일이 있어야 청구서에 맞게 배정되는데, 그 칸이 지출 퍼널 확인 화면에만 있어요. 이체 퍼널에 같은 칸을 또 두지 않고, 내 것과 남의 것이 섞인 결제도 같은 칸으로 풀어요. 남의 몫이 전액이면 줄이 없는 기록, 곧 이체가 돼요. 남의 몫 다리도 그 카드 결제수단의 이용분이라 청구서·할부 회차·실적 계산에 그대로 들어가요.
- `+ 새로 빌려주기` 목록에는 잔액 0으로 접힌 지갑도 "다 받음" 꼬리표로 보여서 같은 사람에게 다시 빌려주면 그 지갑을 고를 수 있어요. 이때 확인 화면의 갚기로 한 날은 비어 있고 다시 물어요(5절). 같은 이름을 새로 입력하면 "이미 있는 철수를 쓸까요?"를 물어요.
- **많이 받았을 때**: 받은 금액이 잔액보다 크면 확인 화면에 "빌려준 돈보다 ○원 많아요. 차액을 이자로 적을까요?"(기본 켬). 끄고 저장하면 잔액이 음수로 남고 지갑 상세에 "○원 더 받았어요" 안내가 보여요. 빌린 돈에서 더 많이 갚은 경우도 같아요(차액은 낸 이자).
- 이체 퍼널의 "어느 장부?"가 기록의 장부이고, 새 지갑의 공개 범위도 정해요(6.3).

### 6.2 보이는 곳

| 곳 | 보이는 것 |
|---|---|
| 자산 탭 | 빌려준 돈 묶음(사람별 잔액, 갚기로 한 날, 지난 것은 표시), 빌린 돈은 갚아야 할 돈 묶음 안. 다리가 있었고 잔액 0이면 "다 받음/다 갚음 N명"으로 접힘. 음수(더 받음)는 "○원 더 받음"으로 펼쳐 둬요 |
| 지갑 상세 | "철수에게 받을 돈" + 갚기로 한 날 줄(누르면 고침) + 이력 + 버튼 둘(`받았어요`·`안 받기로 했어요`) |
| 홈 "확인할 것" | 갚기로 한 날이 지나고 아직 받을(갚을) 잔액이 남은 지갑(7절) |
| 홈 "받을 돈" 카드 | 바뀌지 않아요(예상 정산·혜택만). 오래가는 대여가 카드를 늘 차지하고, "N일째"와 "갚기로 한 날"이 섞이며, "확인할 것"과 겹쳐서예요 |
| 분석 흐름 | **갚은 원금**(8절). 빌려준 돈은 줄이 없어요(자산 사이 이동, "모으는 지갑으로 옮긴 돈"을 흐름에 세지 않는 것과 같음) |
| 결제수단별 통계 | 결제수단 없이 빌려준 돈·빌린 돈 지갑에서 나간 지출(탕감, 엄마가 대신 낸 병원비)은 지갑 이름이 아니라 "결제수단 없음"으로 묶어요 |

### 6.3 공개 범위

- 새 지갑의 주인은 만든 사람이에요. 퍼널에서 공용 장부를 골랐으면 가구가 보는 지갑이고 **`allow_member_use = true`(함께 쓰는 지갑)**예요. 가구원 누구나 `받았어요`를 적을 수 있고, 주인이 나갈 때 남는 가구원에게 넘길 수 있어요([가구원 나가기·계정 삭제](member-leave.md)). 개인 장부를 골랐으면 `hidden_from_household = true`예요. 지갑 설정에서 바꿀 수 있어요.
- **숨긴 빌려준 돈·빌린 돈 지갑은 주인의 개인 장부 기록에만 써요.** 공용 장부 퍼널의 지갑 목록에 나오지 않아요. 공용 장부 기록이 닿은 대여 지갑은 숨길 수 없어요("공용 기록이 있어 숨길 수 없어요"). 지갑 이름이 사람 이름이라, 공용 기록에서 숨긴 대여가 드러나지 않게 하는 규칙이에요. 다른 종류의 숨긴 지갑과 공용 기록이 만나는 경우는 이 티켓 밖이에요(11절).
- 갚은 원금을 지갑별로 펼칠 때도 내가 볼 수 있는 지갑만 이름이 보이고, 볼 수 없는 지갑은 ADR 0025대로 합계 한 줄이에요.
- 가구가 보는 빌려준 돈 지갑에 다른 가구원의 개인 장부 기록이 닿으면 ADR 0025대로 "○○의 개인 기록" 합계 한 줄이에요.
- 나간 사람의 대여 지갑 중 넘기지 않은 것은 다른 지갑처럼 보관되어 가구 잔액에서 빠지고, 할 일에서도 빠져요.

## 7. 갚기로 한 날과 할 일

- 할 일 조건: 지갑에 `repay_due_date`가 있고, 그날이 **지났고**(서울 날짜 기준 다음 날부터), 지갑이 보관되지 않았고, **아직 받을(갚을) 쪽으로 잔액이 남았다**(빌려준 돈은 잔액 > 0, 빌린 돈은 잔액 < 0). 더 받아서 음수가 된 빌려준 돈은 할 일이 아니에요.
- 알린 할 일 키는 `loan_due:{지갑}:{repay_due_date}`예요. 날짜를 바꾸면 새 할 일로 한 번 더 알려요(사용자가 새 약속을 정한 것). 같은 날짜로 되돌리면 이미 알린 키라 다시 울리지 않아요(ADR 0029).
- 다 갚은 지갑에 다시 빌려주면 옛 날짜가 비워져서(5절), 옛 약속 때문에 다음 날 "지났어요"가 뜨지 않아요.
- 홈 위치는 "확인할 것"이고, 누르면 지갑 상세예요. 할 일은 잔액이 0이 되거나 날짜를 지우거나 미루면 빠져요.
- 받는 사람: 가구가 보는 지갑이면 가구원 모두, 숨긴 지갑이면 주인만이에요. 할 일 세는 범위를 장부 대신 **지갑 공개 범위**로 정하는 첫 할 일이에요(함께 쓰는 지갑 넘겨받음은 받은 사람 한 명).
- 잠금화면 문구: 가구가 보는 지갑 한 건이면 "철수 · 갚기로 한 날이 지났어요"(이름만, **금액 없음**: 잔액에 다른 가구원의 개인 기록이 섞일 수 있어서 카드 청구서와 같은 규칙). 숨긴 지갑은 건수만이에요. 여러 건 묶음의 종류 이름은 "갚기로 한 날 N건"이에요.
- 30일 넘은 받을 돈(`recv30`)은 예상 정산·혜택에만 그대로예요. 대여에 30일 규칙을 쓰면 장기 대여가 모두 알림이 돼요.
- 날짜가 없으면 알리지 않아요. 사람 사이 대여는 기한이 없는 경우가 많아요.

## 8. 흐름의 갚은 원금(통계 질문 F1 수정)

- 이름: "갚은 대출 원금" → **갚은 원금**. 대출 또는 빌린 돈 지갑이 하나라도 있으면 보여요. 누르면 지갑별로 펼쳐요.
- 정의: 기록마다 **대출·빌린 돈 지갑에 들어간 + 다리의 합**과 **같은 기록에서 부채가 아닌 지갑에서 나간 금액**(− 다리 합의 절댓값) 중 작은 값을 더해요. 잔액 맞춤은 빼요.
  - 통장 −51만, 대출 +50만, 이자 줄 −1만 → 50만
  - 엄마 +50만, 수입 줄 +50만(탕감받음) → 0(자산에서 나간 돈이 없음)
  - 엄마 −100만, 대출 +100만(빚 갈아타기) → 0(빚 합계가 그대로)
  - 통장 −100만, 엄마 +150만, 수입 줄 +50만(갚으며 일부 탕감) → 100만
- 계산기 v1에서 탕감받음이 잡히는 문제를 찾아 "다리 하나뿐인 기록 제외"로 고쳤다가, 리뷰에서 빚 갈아타기·한 기록 탕감이 여전히 틀린다는 지적을 받아 이 정의로 바꿨어요.
- 빌려준 돈은 흐름에 줄을 두지 않아요.

## 9. AI 연결(MCP)

기존 의도별 툴로 적어요. 지갑 쓰기는 AI 권한 밖이라 지갑은 앱에서 만들어요.

| 하는 일 | 툴 |
|---|---|
| 빌려주기·돌려받기·빌리기·갚기 | `add_transfer`(이자가 있으면 원금 이체 + `add_income`/`add_spending` 이자 기록 둘. 앱의 `받았어요`는 한 기록) |
| 남의 것을 함께 결제 | `add_spending`의 선택 인자 `others_share`(빌려준 돈 지갑 id, 금액). 인자 추가는 하위 호환이에요 |
| 남이 내 지출을 대신 냄 | `add_spending`의 지갑 = 빌린 돈 지갑 |
| 탕감 | 빌려준 돈 지갑에서 나가는 `add_spending`(카테고리 "못 받은 돈"), 빌린 돈 지갑으로 들어오는 `add_income`("갚지 않아도 된 돈") |
| 잔액 확인 | `get_balances`(빌려준 돈 묶음) |

서버 안내문(`instructions`)에 한 줄 더해요: "친구에게 빌려주거나 빌린 돈은 지출·수입이 아니라 그 사람 지갑과의 `add_transfer`예요. 지갑이 없으면 앱에서 `+ 새로 빌려주기`로 만들어 달라고 안내해요." AI가 쓰는 지갑 목록도 앱과 같은 규칙이라 숨긴 대여 지갑은 개인 장부 기록에만 받아요.

## 10. 검증

[시나리오 계산기](../research/2026-11-23-loans-poc/scenario.mjs)는 3~7월에 빌려주기·대신 결제·섞인 결제·빌리기·남이 대신 낸 지출·대출 상환·더치페이 정산·일부 상환(이자)·탕감 양방향·빚 갈아타기·갚으며 일부 탕감·다시 빌려주기·초과 상환을 섞어서 확인 11개를 돌려요.

1. 빌려주기·돌려받기 원금은 수입·지출에 없고, 섞인 결제는 내 몫만 지출이에요.
2. 받은 이자만 수입, 남이 대신 낸 내 지출은 지출, 엄마에게 갚은 100만은 갚은 원금이에요.
3. 탕감은 그날 지출/수입, 빚 갈아타기는 갚은 원금 0, 갚으며 일부 탕감은 실제 낸 돈만이에요.
4. 빌려준 돈 묶음 = 사람별 잔액 합(보관 지갑 제외), 빌린 돈은 갚아야 할 돈이에요.
5. 기간 전체의 순자산 변화 = 남은 돈 합(돈이 새거나 두 번 세지지 않음).
6. 받을 돈 카드에는 예상 정산만 있어요.
7. 기한 지난 지갑만 할 일이고, 다 갚은 지갑·보관 지갑은 아니에요.
8. 다리가 있었고 잔액 0인 지갑만 접히고, 다시 빌려주면 펼쳐져요.
9. 숨긴 지갑의 할 일은 잠금화면에 건수만이고, 새 날짜로 다시 알려요.
10. 다 갚은 지갑에 날짜 없이 다시 빌려주면 옛 날짜가 비워져 할 일이 아니에요.
11. 더 받아서 음수가 된 빌려준 돈은 할 일이 아니에요.

## 11. 넘긴 것

- **디자인 스펙**: 자산 추이 묶음 색 여섯 개(빌려준 돈 추가), 지갑 상세·`받았어요`·`안 받기로 했어요`·남의 몫 칸 시안.
- **숨긴 지갑과 공용 장부 기록**: 숨긴 지갑(대여 지갑 밖, 예: 내 비상금 카드로 낸 공용 저녁)에 공용 장부 기록이 닿을 때 다른 가구원에게 무엇이 보이는지는 기존 문서에 규칙이 없어요. 지도의 Not yet specified에 올려요.
- 상대 연결(`wallets.counterparty_id`)과 같은 사람의 정산·대여 합치기는 필요해질 때 더해요.
- 정기 상환이 있는 개인 대여(매달 엄마에게 30만)는 기존 정기 규칙(이체)으로 적을 수 있어요. 별도 기능은 없어요.
- 통화가 다른 대여(원화로 빌려주고 달러로 받음)의 환전·환차는 필요해질 때 정해요.
