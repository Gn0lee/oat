# 금융·가계부 앱 알림 사례 조사

- 조사일: 2026-11-22
- 관련 티켓: 알림 기능 설계(wayfinder-535), 기존 설계 노트 `.claude/docs/NOTIFICATIONS.md`(웹 시절 Issue #341)
- 전제: iOS 우선 Expo(CNG + Xcode 로컬 빌드, EAS 미사용), Android는 정식 출시 직전 이식. 서버는 셀프호스팅 미니 PC(Node/Hono, Postgres 큐 worker)라 잠깐 멈출 수 있어요. 가구원끼리 공용 장부를 함께 쓰고, 개인 장부는 본인만 봐요.
- 방법: 공식 도움말·앱스토어 설명·공식 블로그·법령 해설서를 우선 인용했어요. 공식 페이지가 막혀(403, SPA) 검색 엔진 요약으로만 본 항목은 "검색 요약"이라고 적었어요. 블로그만 근거인 항목은 "블로그"라고 적었어요. 찾지 못한 항목은 "확인 못 함"으로 남겼어요. 실제 앱을 설치해 화면을 본 것은 아니에요.

## 1. 결론 먼저

- **해외 가계부 앱은 "모든 거래 알림"을 보내지 않아요.** Copilot은 새 거래마다 알림을 보내지 않는다고 명시하고, 큰 지출($500 초과)·잔액 부족·예산 초과·주간 요약처럼 **판단이 필요한 사건만** 보내요. 거래 알림은 국내 카드사·은행 앱의 몫이에요.
- **설정 단위는 "알림 종류별 토글"이 표준이에요.** Copilot은 10종을 하나씩 켜고 끄고, Rocket Money는 "알림/팁/업데이트" 3묶음 × 푸시/이메일로 나눠요. 시간대(방해 금지)를 앱이 직접 제공한다는 공식 근거는 해외 앱에서 찾지 못했어요. OS의 집중 모드에 맡기는 쪽이에요.
- **공유 가계부는 "같은 화면, 알림은 각자"예요.** Monarch는 가구가 한 대시보드를 같이 보지만 알림 설정은 구성원마다 따로라고 해요. Splitwise는 다른 사람이 비용을 추가하면 기본으로 푸시를 보내요.
- **잠금화면에 금액·가맹점을 넣을지 앱이 따로 옵션을 주는 사례는 찾지 못했어요.** 카카오뱅크는 반대로 "잔액 표시"를 켜야 잔액이 붙는 방식이에요(블로그). Apple 심사 지침 4.5.4는 푸시로 민감한 개인정보를 보내지 말라고 해요.
- **법규: oat의 가구 협업·청구서 알림은 광고성 정보가 아니라서 정보통신망법 제50조(야간 21~08시 별도 동의, 2년마다 수신동의 확인)의 적용 대상이 아니에요.** 다만 같은 알림에 홍보 문구를 섞으면 알림 전체가 광고성 정보가 돼요(KISA 안내서).
- **oat 추천:** 협업 알림(요청·응답)과 결제일·청구서 알림만 기본 켜고, 파트너의 새 기록 알림은 기본 끔 또는 묶어 보내기. 설정은 종류별 토글 1단, 알림함은 필수, 잠금화면 문구는 기본으로 금액을 빼기. 조용한 시간은 법적 의무는 없지만 "밤에 만든 비긴급 알림은 아침에 보내기"를 서버 규칙으로 두는 걸 추천해요(7절).

## 3. 국내 앱

### 3.1 토스

- **카드 알림**: '전체' 탭 → 설정 → 알림 → 카드 알림에서 카드별 토글로 켜고 꺼요. 카드사가 보내는 본인 명의 카드의 승인·승인 취소 알림을 토스 앱 알림으로 대신 보내주는 무료 서비스예요. 토스로 신청하면 기존 카드사 알림은 해지·중지돼요. (검색 요약, 원문: https://support.toss.im/faq/5589 , https://support.toss.im/faq/5315)
- **토스뱅크 카드**: 설정 → 알림 → "기능별 알림" → 토스뱅크 카드 알림이고, 문자 알림은 없어요. 즉 설정 화면이 **기능(상품)별 묶음**으로 나뉘어 있어요. (검색 요약, https://support.toss.im/faq/5315)
- **결제일(카드값) 사전 알림**: 공식 FAQ에서 확인 못 함.
- **알림함**: 앱 안 종 모양 버튼으로 푸시로 안 온 알림까지 볼 수 있다는 블로그 설명이 있어요. 공식 확인은 못 했어요. (블로그: https://seedmoa.com/%ED%86%A0%EC%8A%A4-%EC%95%8C%EB%A6%BC-%EB%81%84%EA%B8%B0-%EC%84%A4%EC%A0%95-%EB%B0%A9%EB%B2%95-3%EA%B0%80%EC%A7%80-%EC%A6%9D%EA%B6%8C-%EC%9D%B4%EB%B2%A4%ED%8A%B8-%ED%91%B8%EC%8B%9C%ED%8C%9D/)
- **잠금화면·금액**: 토스에는 홈 화면 잔액을 가리는 "금액 숨기기"가 있지만, 이것이 알림 문구에 적용되는지는 확인 못 함. (블로그: https://thisthatbase.com/toss-app-account-amount-hide/)
- **광고 알림·야간**: 토스 자체의 야간 광고 정책 원문은 확인 못 함. 토스 앱에 입점한 판매자 동의 문서에 "야간 별도 동의를 받지 않으므로 21시~08시에 광고를 보내지 않는다"는 문구가 있어요. (https://pages.tossplace.com/policies/625/436)
- **누르면 어디로 가는지**: 확인 못 함.

### 3.2 뱅크샐러드

- 앱스토어 설명에서 알림 관련 문구는 접근 권한 안내의 "중요 공지 및 이벤트, 프로모션 정보 알림" 한 줄뿐이에요. (https://apps.apple.com/kr/app/%EB%B1%85%ED%81%AC%EC%83%90%EB%9F%AC%EB%93%9C/id1195804784)
- 결제 예정 카드값은 [자산-조회] → [카드] → '이번에 낼 카드값'에서 **화면으로** 보여줘요. 연회비·연체이자 등은 카드사가 안 보내서 빠질 수 있다고 안내해요. (https://help.banksalad.com/770) 결제 예정 카드값을 푸시로 알려주는지는 확인 못 함.
- 2021년 기사는 주간·월간 자산관리 알림과 리포트를 보낸다고 소개해요. 현재 설정 항목은 확인 못 함. (검색 요약, https://www.fnnews.com/news/202107021522203069)

### 3.3 현대카드

- **앱 알림 종류(공식)**: 이용내역은 "실시간 결제금액, 승인내역, 취소내역 등", 안내 정보는 "결제예정금액, 이용대금명세서, 포인트 추가 적립, 후불교통카드 이용금액 및 부가 정보 등"이에요. 앱 알림은 "이용 횟수와 상관없이 모든 알림 무료"예요. (https://www.hyundaicard.com/cms_content/ma/M_CPACO0101_01_CMS04.html)
- 문자 알림은 유료이고 "건당 5만원 이상 이용내역"만 무료예요. 즉 **금액 기준선**이 채널 비용과 묶여 있어요. (같은 출처)
- **설정**: 설정 → 알림 → 알림 설정 → "카드 이용 알림(카드 이용내역, 결제 예정금액 등 알림 받기)" 한 토글로 묶여 있다고 해요. (블로그: https://newskurly.com/%ED%98%84%EB%8C%80%EC%B9%B4%EB%93%9C-%EA%B2%B0%EC%A0%9C-%EC%95%8C%EB%A6%BC-%EB%B0%8F-%EC%95%8C%EB%A6%BC%EC%9D%8C-%EC%84%A4%EC%A0%95-%EB%B0%A9%EB%B2%95/)
- **소비 잔소리**: 누적 이용 금액이 정한 기준을 넘으면 알려주고, 기준을 3차까지 둘 수 있다는 벤치마킹 글이 있어요(약 3년 전). (블로그: https://brunch.co.kr/@d590968353774ad/1)
- 야간 제한, 잠금화면 문구 옵션, 알림함, 누른 뒤 이동은 확인 못 함.

### 3.4 신한 SOL페이(신한카드)

- 전체 메뉴 → MY → 알림 관리에서 이용 승인 알림을 켜고, 앱 푸시·문자 중 수단을 고르고, **알림 기준 금액**을 정한다고 해요. (블로그: https://card.ambitstock.com/guides/card-spending-alert-setup-2026)
- 실시간 결제 입금 내역을 SOL페이 푸시로 자동 발송하도록 개선했다는 공지가 있어요. (https://www.shinhancard.com/pconts/html/helpdesk/consumerPotal/refresh/CONFM90116/2013841_10124.html)
- 방해 금지 시간은 신한 SOL뱅크(은행) 입출금 알림에서만 블로그로 확인되고, 카드 알림은 확인 못 함. (블로그: https://thisthatbase.com/shinhanbank-alarm-service-apply/)

### 3.5 카카오뱅크

- **공식 설명서**: 입출금 거래내역과 체크카드 이용내역을 알림톡·앱푸시·SMS로 보내요. "앱푸시를 통한 알림서비스는 이용자의 신청이 없더라도 기본적으로 제공됩니다." 앱푸시·알림톡은 무료, SMS는 월 300원(카드만)·900원(입출금+카드)이에요. (https://og.kakaobank.io/download/47675835-342e-4254-88c7-d4fb885a02b5)
- **설정**: 더보기 → 앱설정 → 입출금/카드결제 알림. 계좌별로 설정하고, 화면 맨 아래 **"잔액을 표시하겠습니다"를 켜야 알림에 잔액이 붙어요.** (블로그: https://sungu4rd.com/%EC%B9%B4%EC%B9%B4%EC%98%A4%EB%B1%85%ED%81%AC-%EC%9E%85%EC%B6%9C%EA%B8%88-%EB%B0%8F-%EC%B9%B4%EB%93%9C%EA%B2%B0%EC%A0%9C-%EC%95%8C%EB%A6%BC-%EC%84%A4%EC%A0%95-%EB%B0%A9%EB%B2%95/ , https://www.semogle.com/2025/12/blog-post_14.html)
- **야간**: 블로그 한 곳은 방해 금지 시간(예: 23~07시)을 둘 수 있다고 하고, 다른 글은 22~06시 거래 알림을 08시부터 차례로 보낸다고 해요(SMS 한정인지 불명). 두 주장 모두 공식 확인 못 함. (검색 요약, https://www.semogle.com/2025/12/blog-post_14.html)
- 알림 내용 숨기기, 알림함, 누른 뒤 이동은 확인 못 함.

## 4. 해외 앱

### 4.1 Copilot Money

- **알림 10종(공식)**: Bank Fee Alert, Big Expense Alert("$500 초과, 반복 거래 아닌 것"), Budgets updates(카테고리 예산 초과), Credit Utilization alert(30·60·90%), Income update($10 이상 수입), Low balance alert($100 미만), Recurring paid alert(반복 거래 결제됨), Spending update("매주 월요일" 지난주와 그 전주 비교), Uncategorized transfer alert, Venmo transaction alert. (https://help.copilot.money/en/articles/11062072-settings-overview)
- **보내지 않는 것**: "Copilot doesn't currently send notifications for every new transaction" — 새 거래는 대시보드에서 보라고 해요. 신용카드 결제일 알림도 "not supported"예요. (https://help.copilot.money/en/articles/10671399-notifications)
- **설정**: Settings → Notifications에서 종류별로 골라요. 기본값, 앱 자체 조용한 시간, 잠금화면 문구, 누른 뒤 이동, 알림함은 문서에 없어요(확인 못 함). 방해 금지 같은 OS 집중 모드가 알림을 막을 수 있다고만 적어요. (같은 출처)
- 기준 금액($500, $100)을 바꿀 수 있는지는 확인 못 함.

### 4.2 Monarch Money

- **가구 공유**: "each household will share one dashboard ... but each member can personalize their own notification settings". 계좌·거래를 가구원에게 숨길 수는 없어요. (검색 요약, 원문 403: https://help.monarch.com/hc/en-us/articles/20926382202004-Monarch-for-Couples-and-Households)
- **반복 거래**: "Notification (push or email) 3 days before a recurring transaction is expected". (https://www.monarch.com/blog/track-recurring-bills-and-subscriptions) 반복 가맹점·계좌 관련 알림 종류는 Settings → Notifications에서 고르고, 새 검토 항목이 생기면 알려줘요. (검색 요약, https://help.monarch.com/hc/en-us/articles/4890751141908-Tracking-Recurring-Expenses-and-Bills)
- **채널**: 릴리스 노트에 푸시·앱 내(in-app)·이메일을 아무 조합으로 고를 수 있다고 나와요(영수증 전달 알림 맥락). (검색 요약, https://releasebot.io/updates/monarch)
- **주간 요약**: "You can find your latest weekly recap on your dashboard, and we'll send you a weekly email as well." 푸시가 아니라 **대시보드 + 이메일**이에요. (https://www.monarch.com/blog/winter-release)
- **큰 거래**: 전용 알림은 확인 못 함. 규칙으로 큰 거래를 "needs review"로 표시하고, 검토 알림을 이메일·푸시로 받는 우회로가 있어요. (https://www.monarch.com/blog/transaction-review)
- 파트너가 기록을 추가할 때 다른 구성원에게 알림이 가는지는 확인 못 함.

### 4.3 YNAB

- 앱 알림(폰에 뜨는 것)과 **배지**(앱 안에서 처리할 일을 표시)를 나눠요. 앱 알림 예시는 "Did that latest transaction cause cash overspending in your plan?"이고, 가져올·승인할 거래, 수입 도착, 계좌 연결 문제도 있다고 해요. 설정 → Settings & Privacy → Notifications. (검색 요약, 원문 본문은 JS 렌더링이라 못 읽음: https://support.ynab.com/en_us/managing-notifications-a-guide-HySdCwtCc)
- 예산을 "넘기 직전" 경고는 없고 넘은 뒤 알린다는 제3자 비교가 있어요. (https://gethinder.app/blog/budgeting-apps-that-alert-before-overspending)
- 공유 플랜에서 상대 활동 알림, 기본값, 조용한 시간은 확인 못 함.

### 4.4 Honeydue (커플 가계부)

- **공개 범위(공식)**: 계좌 주인이 "Share both balances and transactions / Share balances only / Nothing at all" 중에서 골라요. 거래 하나만 "Visibility"로 숨길 수도 있어요(깜짝 선물 등). (https://support.honeydue.com/en/articles/3283211-how-to-change-what-my-partner-can-see) 이 문서는 알림을 다루지 않아요.
- **파트너 활동 알림**: 알림 설정을 맞게 해두면 파트너가 내 거래 알림을 받고, 그 거래에 질문·이모지 반응을 남길 수 있다고 해요. (리뷰: https://www.moneycrashers.com/honeydue-review , https://getoutofdebt.org/106687/review-honeydue-a-personal-finance-app-for-couple-2)
- **청구서 리마인더**: 나·파트너·둘 다 중 **누구에게 보낼지** 고르고, 최대 1주 전까지 보낼 수 있다고 해요. (리뷰: https://clark.com/personal-finance-credit/budgeting-saving/honeydue/)
- **예산**: 월 카테고리 한도의 75%에 닿으면 알려주는 것이 기본이라고 해요. 검색 요약에서 본 리뷰 문구라 어느 리뷰인지 특정하지 못했고, 공식 확인은 못 했어요. (검색 결과 후보: https://millennialmoney.com/honeydue-review/ , https://www.nerdwallet.com/finance/learn/honeydue-app-review)
- 공식 홈페이지는 "Activity", "Bills" 화면과 거래별 댓글·이모지를 소개해요. (https://www.honeydue.com/)
- 앱스토어 원문, 조용한 시간, 잠금화면 문구, 누른 뒤 이동은 확인 못 함.

### 4.5 Rocket Money

- **설정 단위(공식)**: Alerts·Tips·Updates 3묶음을 푸시·이메일로 따로 켜고 꺼요. 개별 알림 단위 토글은 문서에 없어요. (https://help.rocketmoney.com/en/articles/934668-updating-your-notification-settings)
- **잔액 부족 기본값(공식)**: 입출금 계좌 잔액이 "below $200"이면 알리는 알림을 **자동으로 만들어 둬요.** 기준 금액 수정과 추가는 모바일 앱에서만 돼요. (https://help.rocketmoney.com/en/articles/8418019-how-to-customize-a-low-balance-alert)
- **청구서**: "our notifications for bill charges are based on when you paid the bill the previous month" — 지난달 결제일 기준이라 며칠 어긋날 수 있다는 개발사 답변이에요. 예산 근접 알림, 가격 인상 경고도 있어요. (https://apps.apple.com/us/app/rocket-money-bills-budgets/id1130616675)
- 큰 거래 알림은 공식 문서로 확인 못 함. 몇 일 전에 청구서를 알리는지도 확인 못 함.

### 4.6 Splitwise

- 직원 답변: "Splitwise should send you a push notification by default any time that another person adds a bill or payment with you". 설정의 알림 항목에서 끌 수 있고, 앱 아이콘 배지는 지원하지 않는다고 했어요(2016년 답변). (https://feedback.splitwise.com/forums/162446-general/suggestions/7577058-iphone-app-notification)
- 이메일은 종류별(그룹·친구, 비용 추가·수정·삭제·댓글, 결제, 만기) 토글이에요. (제3자: https://www.hardreset.info/devices/apps/apps-splitwise/change-email-notifications/)
- 보안·계정 메일은 끌 수 없다고 개인정보처리방침에 있어요. (https://www.splitwise.com/privacy)

## 5. 플랫폼 규칙 (스택과 무관하게 해당)

- **Apple 4.5.4**: "Push Notifications must not be required for the app to function, and should not be used to send sensitive personal or confidential information." 홍보성 푸시는 앱 UI에서 명시적 동의를 받고 앱 안에서 끌 수 있어야 해요. (https://developer.apple.com/app-store/review/guidelines/) 금액·가맹점이 "민감한 개인정보"인지 Apple이 정의하진 않았지만, 잠금화면 문구를 보수적으로 잡을 근거가 돼요.
- **Android 알림 채널**: Android 8.0부터 모든 알림은 채널에 속해야 하고, 사용자가 채널별로 소리·표시를 바꿔요. 채널을 만든 뒤에는 앱이 동작을 바꿀 수 없고 이름·설명만 바꿀 수 있어요. (https://developer.android.com/develop/ui/views/notifications/channels) 그래서 **Android 이식 전에 알림 종류 목록을 확정**해야 나중에 채널을 갈아엎지 않아요.
- **iOS 중단 수준(time-sensitive 등)과 잠금화면 미리보기**: Apple HIG 본문을 받지 못해 확인 못 함(https://developer.apple.com/design/human-interface-guidelines/notifications). 일반적으로 사용자가 설정에서 미리보기를 "잠겨 있지 않을 때"로 바꿀 수 있다는 정도만 알고 있어요.

## 6. 한국 법규: 정보통신망법 제50조

근거는 KISA·방송미디어통신위원회 「불법스팸 방지를 위한 정보통신망법 안내서」 제8차 개정판(KISA-GD-2025-0037, 2025.12)이에요. (재게시본: https://t1.kakaocdn.net/rocket/user-guide/latest-kisa-guide-1.pdf , 발간처 안내: https://spam.kisa.or.kr) 법령 원문은 국가법령정보센터에서 본문을 받지 못해 안내서에 실린 조문으로 대신했어요.

### 6.1 무엇을 규제하나

- 제50조는 **"영리목적의 광고성 정보"** 전송만 규제해요. 앱 푸시도 전자적 전송매체라 광고라면 명시적 사전동의가 필요해요. (안내서 p.10~13)
- 야간: "오후 9시부터 그 다음 날 오전 8시까지" 광고를 보내려면 **별도의 사전동의**가 필요하고, 시각은 **수신자에게 도달한 한국 표준시** 기준이에요. 이메일만 예외예요. (제50조제3항, 시행령 제61조제2항, 안내서 p.18)
- 2년 확인: 광고 수신동의를 받은 날부터 **2년마다** 전송자 명칭·동의 날짜·유지/철회 방법을 알려야 해요. 다음 확인은 안내한 날이 아니라 최초 동의 시점부터 세요. (제50조제8항, 시행령 제62조의3, 안내서 p.25~26)
- 과태료: 동의·야간·2년 확인 위반은 3천만원 이하예요. (안내서 p.6 표)

### 6.2 정보성과 광고성의 구분 (KISA 기준)

- 광고성: "전송자가 널리 경제적 이득을 취할 목적으로 전송하는 ... 재화나 서비스에 관한 정보". 이미지 홍보도 포함하고, **부수적으로 광고가 섞이면 정보 전체가 광고성**이에요. 예로 "신용카드 거래내역(결제)정보를 이메일로 전송하면서 하단에 광고성 정보를 포함하는 경우" 전체를 광고로 봐요. (p.11)
- 광고성이 아닌 것: 계약·거래 관계 때문에 "반드시 전달해야 할 필요가 있는 정보", 수신자의 요청·신청에 따른 정보, 계약 이행 정보(설명서, 변경사항, "안전·보안·업데이트 사항 등 계약 관련 고지"). 판단은 전송자·수신자 관계를 종합해서 해요. (p.11)
- 앱 안에서 보는 정보는 "전송"이 아니에요: "수신자가 웹사이트, 앱 등에 접속 ... 하면서 영리목적의 광고성 정보를 보게 된 경우에는 ... '전송'된 것에 해당하지 않습니다." (p.12)
- OS 푸시 허용은 광고 동의가 아니에요: "앱 푸시 알림의 허용 여부는 해당 기기에 수신된 정보를 화면에 띄워주겠다는 의미일 뿐 광고성 정보 수신동의에 해당하지 않음". (FAQ 02-03, p.55)
- 동의 문구 함정: "혜택알림 동의, 마케팅 동의" 같은 이름이나 기본 체크로 받은 동의는 명시적 동의로 안 쳐요. (p.12)

### 6.3 oat에 적용하면

- 가구원의 수정·삭제 요청, 초대 응답, 결제일·청구서 리마인더, 사용자가 켠 주간 요약은 **사용자가 쓰는 서비스의 이행·요청 정보**라 광고성 정보가 아니에요. 그래서 야간 별도 동의와 2년 확인 의무는 **해당하지 않아요.** (안내서 p.11 기준의 해석이고, 법률 자문은 아니에요.)
- 다만 다음은 광고로 바뀔 수 있어요: 유료 플랜·새 기능 홍보, "oat를 친구에게 추천하세요", 제휴 혜택. 정보성 알림 끝에 한 줄만 붙여도 전체가 광고가 돼요.
- oat가 무료 가족 앱이어도 "영리목적"은 법인 성격이 아니라 정보의 성격으로 판단해요(p.11 주석). 앞으로 홍보 푸시를 보낼 계획이 생기면 별도 광고 동의(매체별), 야간 동의, 2년 확인, "(광고)" 표기, 푸시에서 바로 수신거부 화면 연결(p.44)을 따로 설계해야 해요.
- 앱 안 알림함에 공지·새 기능 소개를 두는 것은 "전송"이 아니라서 이 규제 밖이에요(p.12). 홍보는 푸시 대신 알림함·홈 카드로 돌리는 편이 단순해요.

## 7. oat에 대한 시사점

### 7.1 보낼 이벤트

사례에서 공통으로 보이는 원칙은 "**판단이나 행동이 필요할 때만 푸시**"예요(Copilot의 거래별 알림 없음, YNAB의 배지 분리). oat는 은행 연동이 없어서 결제 승인 알림은 카드사 앱 몫이고, oat의 강점은 가구 협업과 예정 결제예요.

| 우선순위 | 이벤트 | 근거 사례 | 기본값 추천 |
|---|---|---|---|
| 1 | 가구원의 수정·삭제 요청, 요청 결과, 초대 응답 | Splitwise(다른 사람이 추가하면 기본 푸시), 기존 NOTIFICATIONS.md | 켬 |
| 1 | 카드 결제일·청구서 예정(며칠 전) | Monarch 3일 전, Honeydue 최대 1주 전, 현대카드 결제예정금액 | 켬 |
| 2 | 파트너의 새 공용 기록 | Honeydue 파트너 거래 알림, Monarch는 개인별 설정 | **끔** 또는 하루 묶음 |
| 2 | 주간 요약 | Copilot 월요일, Monarch 주간 요약(대시보드+이메일) | 끔으로 시작, 첫 주 이후 제안 |
| 3 | 큰 지출(가구 공용 기준선 초과) | Copilot $500, 신한·현대 기준 금액 | 끔, 켤 때 기준 금액 입력 |
| 3 | 예산 근접·초과 | Honeydue 75%, Copilot·Rocket Money | 예산 기능 생기면 |
| 보내지 않음 | 모든 거래 알림, 홍보 | Copilot이 명시적으로 안 보냄, 6절 법규 | - |

- **개인 장부 내용은 어떤 알림에도 넣지 않아요.** Honeydue는 거래 하나 단위로 숨길 수 있게 했는데, oat는 이미 장부 단위로 가려지니 "개인 장부 기록은 알림 대상 자체가 아님"으로 단순하게 유지하는 게 맞아요(ADR 0025 방향과 일치).
- 리마인더는 Rocket Money처럼 "지난달 결제일 추정"으로 하면 어긋나요. oat는 카드 결제일 설정값이 있으니 확정 날짜로 보내는 게 나아요.

### 7.2 설정 단위

- **종류별 토글 1단**이 표준이에요(Copilot 10종, 토스 기능별). Rocket Money처럼 3묶음으로 뭉치면 "청구서만 받고 싶다"를 못 해요.
- 채널은 지금 푸시 하나라 채널 축은 숨겨도 돼요. 앱 안 알림함은 끌 수 없게 두고, 푸시만 종류별로 끄는 구조가 단순해요(Monarch가 푸시·앱 내·이메일을 따로 두지만 oat 규모엔 과해요).
- **사용자별 설정**, 가구 전역 설정 아님(Monarch와 같음, 기존 설계와 같음).
- Android 이식 때 알림 종류 = 채널로 1:1 대응시키면 OS 설정과 앱 설정이 어긋나지 않아요. 채널은 나중에 동작을 못 바꾸니 iOS 단계에서 종류 목록을 확정해 두세요(5절).
- 청구서 리마인더의 "누구에게"(Honeydue)는 공용 카드라면 의미가 있어요. 1차는 "카드 주인 + 공용이면 가구원 전체"로 고정하고 선택지는 나중에 열어요.

### 7.3 알림함

- **필요해요.** 이유: (1) 서버가 잠깐 멈추거나 APNs가 지연·누락돼도 알림함 원장은 남아요. (2) YNAB처럼 "할 일"(처리할 요청)을 배지로 보여줄 자리가 필요해요. (3) 공지·새 기능 소개를 푸시 대신 알림함에 두면 6.3의 광고 규제를 피해요. (4) Apple 4.5.4는 푸시 없이도 앱이 동작해야 한다고 해요.
- 기존 설계(User Notification이 원장, 푸시는 채널)를 그대로 유지하는 게 맞아요. 푸시는 "알림함 row 생성 후 큐에서 발송"이라 서버 정지 뒤에도 재시도가 쉬워요.
- 탭하면 해당 항목(요청 상세, 결제 예정 카드)으로 바로 가고, 대상이 지워졌거나 권한이 없으면 알림함으로 떨어지게 해요. 다른 앱의 이동 규칙은 공식 자료로 확인 못 했어요.

### 7.4 잠금화면 문구

- 앱이 금액 표시 옵션을 따로 준 공식 사례는 못 찾았어요. 카카오뱅크는 잔액을 **켜야** 보여줘요(블로그). Apple 4.5.4는 민감 정보를 푸시로 보내지 말라고 해요.
- 추천: 기본 문구는 "누가·무엇을" 수준("지수 님이 공용 기록 수정을 요청했어요", "현대카드 결제일이 3일 남았어요")으로 쓰고 **금액·가맹점은 기본으로 넣지 않아요.** 설정에 "알림에 금액 표시"를 하나 두고 기본 끔으로 시작해요. 금액은 알림함과 상세 화면에서 봐요.

### 7.5 조용한 시간

- 정보성 알림이라 21~08시 법적 제한은 없어요(6.3). 해외 앱도 자체 조용한 시간 대신 OS 집중 모드에 맡겨요(Copilot).
- 그래도 가구 협업 알림은 "상대가 밤에 기록을 고쳤다"처럼 밤에 생기기 쉬워요. 추천은 **사용자 설정 없이 서버 규칙 하나**예요: 21~08시(KST, 사용자 기준 시간대)에 생긴 비긴급 알림(파트너 새 기록, 주간 요약)은 알림함에만 넣고 푸시는 08시에 묶어서 보내요. 요청형·결제일 당일 알림은 바로 보내요. 이 기준선을 21~08시로 두면 나중에 광고 푸시를 할 때도 같은 시간 창을 재사용할 수 있어요.
- 리마인더 발송 시각은 "결제일 N일 전 오전 9시"처럼 고정해서 큐 worker가 밤에 몰아 보내지 않게 해요. 서버가 멈췄다 켜졌을 때 이미 지난 리마인더는 날짜가 지났으면 버리고, 당일이면 보내는 규칙이 필요해요(사례 근거 없음, 설계 판단).

## 8. 남은 확인 항목

- 국내 앱(토스·카카오뱅크·현대카드)의 잠금화면 문구, 알림을 누른 뒤 이동, 방해 금지 시간은 실제 앱 설치로만 확인할 수 있어요.
- Monarch·YNAB 도움말 원문은 403/JS 렌더링으로 못 읽었어요. 브라우저로 직접 열면 기본값과 공유 플랜 알림을 확인할 수 있어요.
- Apple HIG의 중단 수준(time-sensitive) 가이드 원문은 못 받았어요. 결제일 당일 알림을 time-sensitive로 보낼지 정할 때 다시 봐야 해요.
