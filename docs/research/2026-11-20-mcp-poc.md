# MCP PoC: 실제 Claude·Hermes 연결, CIMD, 동의 화면, 쓰기 안전장치

조사일: 2026-11-20 · 티켓: [MCP 툴 설계: 툴 목록·권한 범위·쓰기 안전장치·AI 연결 관리](https://github.com/Gn0lee/oat/issues/534) · 결과를 쓴 곳: [MCP](../design/mcp.md), ADR 0023

## 결론

설계한 방식(Better Auth 인가 서버 + **CIMD만** + 허용 목록, 서버가 내는 HTML 로그인·동의 화면, 요청마다 DB 연결 확인, 의도별 툴)으로 **실제 Claude(claude.ai 웹, 개인 계정)와 Hermes Agent(서버)가 붙었어요.** 다섯 가지를 고쳤어요.

1. 동의에 쓴 브라우저 로그인은 동의 직후가 아니라 **코드→토큰 교환 직후**에 지워요. 동의 직후 지우면 토큰 교환이 `session no longer exists`로 실패해요.
2. Better Auth의 동의 기록(`oauthConsent`)을 남기지 않아요. 남기면 다음 연결 때 우리 동의 화면을 건너뛰어서 연결 행(`ai_connections`)과 어긋나요. **동의의 정본은 연결 행 하나**예요.
3. CIMD 도메인 검사(`originBoundFields`)에서 `client_uri`를 빼요. 기본값은 Hermes를 거절해요(예상했던 대로 재현).
4. 조회만 연결에서도 **쓰기 툴을 목록에 두고** `write_not_allowed`와 이유로 거절해요. 목록에서 숨겼더니 Claude가 예전 목록으로 3번 부르고 "일시적인 연결 문제"라고 안내했어요.
5. MCP SDK는 **2026-07-28을 지원하는 버전**을 써요. Claude는 `server/discover`(2026-07-28)를 먼저 보내고, v1 SDK(1.32.2)가 400을 주자 `initialize`로 내려왔어요.

클라이언트의 확인에는 기댈 수 없어요. 삭제 툴에 `destructiveHint`를 붙여도 Claude(Sonnet)는 묻지 않고 지웠어요. 실제 안전장치는 서버의 중복 확인과 감사 기록 기반 되돌리기예요.

## 환경

- 서버(`2026-11-20-mcp-poc/server/`): 인증 PoC 서버를 복사해 확장. Node 26, Hono 4.13, `better-auth`·`@better-auth/{core,mcp,oauth-provider,cimd}` **1.7.26** 정확한 버전, `@modelcontextprotocol/sdk` 1.32.2(무상태 Streamable HTTP, JSON 응답), Docker `postgres:18`.
- 플러그인: `jwt({ disableSettingJwtHeader: true })`, `mcp({ resource, loginPage: "/oauth/login", consentPage: "/oauth/consent", accessTokenExpiresIn: 300 })`, `cimd({ metadataProfile: "mcp-2026-07-28", isMetadataDocumentUrlAllowed: 허용 목록, originBoundFields })`. DCR은 켜지 않아요(메타데이터에 `registration_endpoint` 없음).
- 도메인 테이블은 아주 줄였어요: 가구·멤버(나, 배우자)·장부(공용, 내 개인, 배우자 개인)·지갑·카테고리·기록(다리·줄 없이 한 줄)·`ai_connections`·`audit_log`.
- 툴 4개: `get_context`, `search_records`, `add_spending`(중복 확인), `delete_record`(version, `destructiveHint`).
- 노출: Cloudflare 임시 터널(`cloudflared tunnel --url`, 계정·도메인 없음). 확인이 끝나고 바로 내렸어요.
- 관찰: 모든 요청과 툴 호출을 `poc-log.jsonl`에 남겼어요(커밋하지 않음).
- 실행: `server/`에서 `.env.example`을 `.env`로 채우고 `npm start`, 자체 확인은 `npx tsx --env-file=.env test/flow.ts`(서버를 띄운 뒤).

## 자체 확인 (`test/flow.ts`, 17개 모두 통과)

공개된 Claude Code CIMD 문서(`https://claude.ai/oauth/claude-code-client-metadata`)를 client_id로 써서 브라우저 흐름(HTML 폼)을 따라갔어요. 로컬과 터널 주소 양쪽에서 통과했어요.

- 허용 목록 밖 CIMD(`vscode.dev`) 거절 → `invalid_client`
- 로그인 → 동의 → 코드 → 토큰, 동의 화면에 앱 이름 표시, 응답에 `iss`(RFC 9207)
- 토큰 교환 뒤 브라우저 로그인 없음, 그 뒤에도 갱신 토큰 동작
- 배우자 개인 장부 안 보임, 같은 지갑·날짜·금액 → `possible_duplicate`(저장 안 함), `allow_duplicate`면 저장, version 다르면 삭제 거절
- 조회만으로 바꾸면 다음 요청부터 `write_not_allowed`, 해지하면 만료 전 액세스 토큰도 다음 요청부터 401, 갱신은 `invalid_grant`
- 감사 기록 모든 행에 AI 연결 ID

Node `fetch`는 `sec-fetch-mode: cors`를 붙여서 `/oauth2/authorize`가 302 대신 `{redirect, url}` JSON을 줘요. 브라우저와 curl은 302예요. 테스트만의 차이예요.

## 실제 클라이언트

### Claude (claude.ai 웹, 개인 계정, Sonnet)

| 단계 | 서버에서 본 것 |
|---|---|
| 커넥터 추가 화면 | Claude 서버(`python-httpx`)가 `/mcp` 401 → 보호 리소스 문서 → 인가 서버 문서를 읽고 "지금 로그인"·"Claude의 게시된 ID 사용(CIMD)"을 **자동 감지**. DCR 선택지는 고르지 않음 |
| 등록 | client_id `https://claude.ai/oauth/mcp-oauth-client-metadata`, 리다이렉트 `https://claude.ai/api/mcp/auth_callback`, `token_endpoint_auth_method: none`, `prompt=consent`를 붙여 옴 |
| 로그인·동의 | 맥 Chrome에서 우리 HTML 화면 → 허락 → Claude로 복귀. 토큰 교환 직후 브라우저 로그인 삭제 |
| 프로토콜 | `server/discover`(2026-07-28) → 400 → `initialize`(2025-11-25)로 협상. 대화마다 `initialize`·`tools/list`를 다시 부름(UA `Claude-User`) |
| 조회 | `get_context` + `search_records`(기간 지정). 배우자 개인 기록 없이 3건 |
| 중복 | 앞서 조회한 이마트 84,200원을 **스스로 알아채고** 사용자에게 물은 뒤 `allow_duplicate: true`로 저장. 서버 경고는 쓰이지 않음 |
| 삭제 | 확인 없이 `delete_record` 실행. 툴 설명의 "앱에서 되돌릴 수 있어요"를 사용자에게 전함 |
| 갱신 | 5분 뒤 `refresh_token` 성공. 갱신 때 CIMD 문서를 다시 읽음(`cimd.refreshed`) |
| 조회만(숨김 방식) | `add_spending`을 3번 불러 "Tool not found" → "일시적인 연결 문제"라고 안내 |
| 조회만(거절 방식) | "조회만 허용돼 거부됐어요. oat 앱의 설정 → AI 연결에서 쓰기를 허용해 주세요"라고 정확히 안내하고 입력 내용을 보존 |
| 해지 | 다음 요청 401 → Claude가 재인증 시작 → **우리 동의 화면이 다시 뜸** → 새 연결 행 |

덤: 안내문의 "맞는 카테고리가 없으면 미분류"를 엄격하게 따라 편의점을 '식비' 대신 '미분류'로 골랐어요. 안내문 문구가 행동을 바로 바꿔요. `get_context`가 돌려준 `access`를 대화 중 기억했어요("앞서 조회한 결과에는 쓰기 권한이 있다고 나왔는데") → 권한은 "지금 시점"이라고 설명에 적어야 해요.

### Hermes Agent (서버)

- 첫 시도: `client_uri value "https://hermes-agent.nousresearch.com" must have the same origin as client_id (https://nousresearch.github.io)` → `invalid_client`. 조사에서 예상한 그대로예요.
- `originBoundFields: ["post_logout_redirect_uris"]`로 바꾼 뒤: CIMD 등록(client_id `https://nousresearch.github.io/hermes-agent/docs/oauth/client-metadata.json`, 리다이렉트 `127.0.0.1:27890/callback` 등) → 로그인·동의 → 토큰 → `initialize`(2025-11-25, UA `python-httpx2`).
- 카드 문자만 주고 기록하게 했더니 조회 없이 바로 `add_spending` → 서버 `possible_duplicate` → **사용자에게 같은 결제인지 물음**. 서버 쪽 중복 확인이 실제로 쓰인 경우예요.

### 확인하지 못한 것

- **ChatGPT**: 회사 Enterprise 계정과 회사 맥뿐이라 시험하지 못했어요. ChatGPT는 `private_key_jwt`로 붙는다고 문서에 있어요(우리 메타데이터는 `none`과 `private_key_jwt`를 모두 알림). 구현 때 개인 계정으로 확인해요.
- **ChatGPT 앱의 Codex 클라이언트**(`codex-mcp-client/0.169.1`): 디스커버리 문서를 읽고 `/mcp` 401을 받은 뒤 인가로 넘어가지 않았어요. 회사 맥이라 원인을 가리지 못했어요.
- **회사 맥·회사망**에서는 `*.trycloudflare.com`이 `ERR_SSL_PROTOCOL_ERROR`로 막혔어요(같은 주소가 다른 맥에서는 TLS 1.3 정상). 운영 도메인과는 무관하지만, 회사 기기에서 연결하려는 사용자는 회사 정책에 막힐 수 있어요.
- **폰 Claude 앱**, 폰 브라우저에서의 로그인·동의.
- Claude Team 조직 계정은 커스텀 커넥터를 조직 소유자가 먼저 추가해야 해요(안내 문구 확인).

## 덤으로 알게 된 것

- `/.well-known/oauth-authorization-server/api/auth`와 `/.well-known/oauth-protected-resource/mcp`는 Better Auth 플러그인의 `onRequest`가 처리해요. 루트 `/.well-known/*`을 `auth.handler`로 넘기기만 하면 돼요.
- `/oauth2/authorize`는 세션이 없으면 `loginPage`로 서명된 쿼리를 붙여 보내요. 로그인 폼은 그 쿼리를 `oauth_query`로 `/sign-in/email`에 함께 보내면 Better Auth가 인가를 이어서 동의 화면 주소를 돌려줘요. 동의는 `/oauth2/consent`에 같은 방식으로 보내요. 둘 다 서버에서 대신 불러서 JS 없는 폼으로 만들 수 있었어요.
- 기본 스코프 `openid profile email offline_access`에 `oat`를 더했고, 보호 리소스 문서에는 `oat`만 나가요. 클라이언트는 `oat offline_access`를 요청했어요.
- Better Auth의 갱신 토큰은 `sessionId`를 갖지만, 그 세션을 지워도 갱신은 계속 돼요(앱 로그아웃과 AI 연결이 별개인 근거와 같음).
- 공개 터널을 열자마자 인터넷 스캐너가 `/`를 두드렸어요. 데이터 경로에는 닿지 않았지만, 운영의 `/mcp`·로그인 화면에도 레이트리밋이 필요해요.

## 한계

- 모델은 Claude Sonnet 하나, Hermes 하나의 관찰이에요. 다른 모델은 중복 확인·삭제 확인 행동이 다를 수 있어요. 그래서 설계는 클라이언트 행동에 기대지 않아요.
- 도메인 모델(다리·줄)을 단순화했어요. 툴 입력 모양의 사용성은 구현 때 실제 모델로 다시 봐요.
- 폰·ChatGPT는 위와 같이 미확인이에요.
