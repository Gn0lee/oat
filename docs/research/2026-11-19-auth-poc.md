# 인증 PoC: Expo 세션 전달·소셜 로그인·MCP 토큰 분리

조사일: 2026-11-19 · 티켓: [인증 PoC: Expo 세션 전달·소셜 로그인·MCP 토큰 분리](https://github.com/Gn0lee/oat/issues/525) · 결과를 쓴 곳: [인증](../design/auth.md), ADR 0022

## 결론

[서버 아키텍처](../design/server-architecture.md)에서 정한 인증 방식(Better Auth 고정 버전, `@better-auth/expo` Cookie 헤더 수동 첨부, MCP 토큰 resource 분리)은 **그대로 유지**해요. 확인한 항목은 모두 기대대로 동작했어요. 다만 운영 규칙 세 가지가 새로 생겼어요.

- 앱은 포그라운드마다 세션 확인을 불러야 해요. 부르지 않으면 서버 세션이 살아 있어도 기기 쪽 만료 기록 때문에 헤더가 빠져요(재현함).
- 처음 설치 표시가 없으면 Keychain의 세션을 지워요. 지우지 않으면 앱을 지웠다 다시 깔아도 로그인 상태가 되살아나요(재현함).
- MCP 요청마다 DB에서 연결과 가구원 여부를 확인해요. 회수해도 이미 발급된 MCP 액세스 토큰은 만료(1시간)까지 서명 검증을 통과하기 때문이에요.

실기기는 쓰지 않았어요. 서버끼리 확인할 수 있는 건 Node 스크립트로, iOS 네트워크·Keychain은 시뮬레이터로, 소셜 로그인과 패스키는 문서와 이슈 조사로 대신했어요.

## 환경

- 서버(`server/`): Node 26, Hono 4.13, `better-auth`·`@better-auth/expo`·`@better-auth/mcp`·`@better-auth/oauth-provider`·`@better-auth/core` 모두 **1.7.25** 정확한 버전, Docker `postgres:18`. 플러그인은 `expo()`, `jwt({ disableSettingJwtHeader: true })`, `mcp({ resource: <base>/mcp })`, `openAPI()`, 선택적으로 `bearer({ requireSignature: true })`. `disabledPaths: ["/token"]`.
- 앱(`mobile/`): Expo SDK 58(RN 0.88), CNG + Xcode 27.2 로컬 빌드, iOS 27.2 시뮬레이터, 임시 번들 ID `dev.oatpoc.authpoc`, 스킴 `oat`. 앱은 켜지면 시나리오를 자동으로 돌리고 결과를 서버 `/poc-log`로 보내요.
- 실행: `server/`에서 `npm start`(Postgres는 `postgres://postgres:poc@localhost:55432/auth`), 테스트는 `npx tsx test/<파일>`. `session-expiry.ts`는 `--import ./test/mocks/register.mjs`로 `react-native`·`expo-*`를 가짜 모듈로 바꿔 실제 `@better-auth/expo/client` 코드를 Node에서 돌려요.

## 확인 항목별 결과 (앱 세션 전달 리서치 9.2절)

| # | 항목 | 방법 | 결과 |
|---|---|---|---|
| 1 | iOS 수동 Cookie 헤더 | 시뮬레이터 | **통과.** 서버에 `session_token`이 정확히 1개 도착. `credentials: "omit"`로 받은 `Set-Cookie`는 시스템 쿠키 저장소에 남지 않아서 `include`로 바꿔도 중복 전송 없음 |
| 2 | 카카오·네이버·구글 리다이렉트 복귀 | 조사 | **이번 범위에서 빠짐.** 로그인 수단을 이메일부터 시작하기로 해서 리다이렉트 흐름을 쓸 일이 없어요. 알려진 사항은 아래 "소셜 로그인 조사" |
| 3 | Apple·Google 네이티브 ID 토큰 | 조사 | **구현 때 확인.** 어느 로그인이든 결과는 같은 세션이라 전달 방식 결정과 무관해요. Apple은 유료 개발자 계정이 있어야 시험할 수 있어요 |
| 4 | 오래 방치한 세션 | Node(실제 Expo 클라이언트 코드), 수명 40초로 축소 | **함정 재현, 대응 확인.** 아래 표 |
| 5 | 재설치 후 Keychain | 시뮬레이터 삭제·재설치 | **세션이 되살아남.** 설치 표시 규칙을 넣으니 재설치 후 로그아웃 상태로 시작 |
| 6 | 앱 세션 ↔ MCP 토큰 교차 | Node | **통과.** 8가지 교차 조합 모두 401(bearer 켬·끔 둘 다) |
| 7 | 로그아웃 후 MCP 토큰 | Node | **MCP 연결은 로그아웃과 별개로 살아 있음.** 액세스 토큰은 만료까지 통과, 갱신 토큰으로 새 토큰도 발급(`sid` 없음) |
| 8 | bearer 병용 | Node | **통과.** `requireSignature: true`면 응답 JSON의 서명 없는 `token`은 거부. 다른 사용자의 Cookie와 Bearer가 같이 오면 Bearer가 이김 |
| 9 | OpenAPI 스냅샷 | Node, 세 번 생성 | **결정적.** 세 번 모두 같은 해시, 경로 55개. `/expo-authorization-proxy` 포함, `/token` 제외. bearer 켬·끔과 무관. `servers` URL은 `BASE_URL`을 따라가서 CI에서 고정해야 해요 |

### #4 세부: 세션 수명 40초, 10초마다 우리 API 호출

| 패턴 | 10s | 20s | 30s | 40s | 50s | 60s |
|---|---|---|---|---|---|---|
| A. 우리 API만 | 200 | 200 | 200 | **401** | 401 | 401 |
| B. + 매번 `getSession()` | 200 | 200 | 200 | 200 | 200 | 200 |
| C. 아무것도 안 함 | | | | | 401 | |

A에서 40초 이후 서버 세션은 미들웨어의 `getSession`으로 계속 연장돼 남은 수명이 30초·20초였어요. 그런데 Expo 클라이언트는 `Set-Cookie`의 `max-age`로 계산한 기기 쪽 만료가 지나면 `getCookie()`에서 쿠키를 빼요. 우리 API 응답의 `Set-Cookie`는 Expo 클라이언트가 보지 못하니 기기 쪽 만료가 늘지 않아요. B처럼 Better Auth 클라이언트로 세션 확인을 부르면 응답 `Set-Cookie`로 기기 쪽 만료도 같이 늘어요.

### #5 세부: 설치 표시 규칙

| 순서 | 설치 표시 | Keychain 세션 | `/v1/me` |
|---|---|---|---|
| 규칙 없이 삭제 → 재설치 | (없음) | 남아 있음 | 200 |
| 규칙 켜고 첫 실행 | 새로 만듦, 세션 지움 | 없음 | - |
| 그냥 다시 켬 | 있음 | 있음 | 200 |
| 삭제 → 재설치 | 새로 만듦, 세션 지움 | 없음 | - |

설치 표시는 앱 삭제 때 같이 지워지는 문서 폴더(`expo-file-system`의 `Paths.document`)에 파일로 둬요. Expo 문서도 "같은 번들 ID로 재설치하면 SecureStore 값이 남는다, 다만 보장되지 않으니 기대지 말라"고 적어요. 지우기 전에 남은 쿠키로 `/sign-out`을 한 번 보내면 서버에 버려진 세션도 남지 않아요(이번에 시험하지 않았어요).

### #7 세부: MCP 연결을 끊는 경로

| 동작 | 액세스 토큰(JWT, 1시간) | 갱신 토큰 |
|---|---|---|
| 앱 로그아웃 | 계속 통과 | 계속 새 토큰 발급 |
| `/oauth2/revoke`로 갱신 토큰 회수 | 계속 통과 | `invalid_grant` |

`requireMcpAuth`는 JWKS 서명·issuer·audience·만료만 보고 DB를 보지 않아요. 그래서 회수나 가구 탈퇴를 바로 반영하려면 MCP 요청마다 DB 확인이 필요해요. 액세스 토큰 헤더는 `typ: at+jwt`, `alg: EdDSA`이고 `aud`는 `[<base>/mcp, <base>/api/auth/oauth2/userinfo]`, `azp`가 있어요.

## 덤으로 알게 된 것

- **버전 고정이 새는 곳**: `@better-auth/mcp@1.7.25`가 `@better-auth/oauth-provider`를 `^1.7.25`로 끌어와서, 하루 전 나온 1.7.26이 설치됐고 그 패키지는 `better-auth@^1.7.26`을 요구해 의존성이 어긋났어요. `@better-auth/oauth-provider`와 `@better-auth/core`도 직접 정확한 버전으로 넣고 `overrides`로 묶어야 해요.
- **MCP 클라이언트 등록**: `application_type`이 web인 클라이언트는 `http://localhost` 리다이렉트를 거절해요(오류 문구는 "non-loopback hosts"라서 헷갈려요). 로컬 CLI형 MCP 클라이언트는 `native`로 등록돼야 해요.
- **`/oauth2/authorize`의 응답**: 세션이 있고 동의가 필요하면 302가 아니라 `{ redirect: true, url: "/consent?…&sig=…" }` JSON을 돌려줘요. 동의 화면은 이 쿼리를 그대로 `/oauth2/consent`에 `oauth_query`로 넘겨요.
- **openAPI 스냅샷**: `getMigrations`는 `better-auth/db/migration`에서 가져와요(`better-auth/db`에는 없어요).

## 소셜 로그인 조사 (이번 범위 밖, 나중을 위한 메모)

- **리다이렉트 → 앱 복귀**는 Expo 플러그인의 `/expo-authorization-proxy` + `?cookie=` 딥링크로 동작하고, 같은 구성의 구현 기록이 있어요. iOS에서 서버가 로그인을 거절하면 앱이 오류를 받지 못하고 그냥 끝나는 문제가 있어요([#12348](https://github.com/better-auth/better-auth/issues/12348), "not planned"로 닫힘, 수정 PR [#12377](https://github.com/better-auth/better-auth/pull/12377)·[#12360](https://github.com/better-auth/better-auth/pull/12360)은 열려 있음). 그래서 앱이 "돌아왔는데 세션이 없으면 실패"로 직접 판단해야 해요.
- **카카오 이메일 없음**: 이메일 동의가 없으면 `email_not_found`로 가입이 실패해요. `mapProfileToUser`로 카카오 ID 기반 대체 이메일을 채우는 방법이 공식 문서에 들어갔어요([#12310](https://github.com/better-auth/better-auth/pull/12310), 2026-11-18).
- **카카오 네이티브 ID 토큰**: **1.7.26(2026-11-18)**부터 카카오 네이티브 SDK의 ID 토큰으로 `signIn.social`을 할 수 있어요([#12316](https://github.com/better-auth/better-auth/pull/12316)). 붙일 때는 이 방식을 쓰고, 그러면 리다이렉트가 필요한 건 네이버만 남아요.
- **Supabase Auth 재검토**: 운영 부담은 적지만 OAuth 2.1 서버가 공개 베타(2025-11)이고 CIMD가 없으며(현행 MCP 스펙은 CIMD 권장), 세션 수명 설정은 Pro 플랜부터이고, JWT라 로그아웃이 바로 반영되지 않아서 유지하지 않았어요(ADR 0022).

## 패스키

Better Auth 공식 패스키 플러그인은 웹 기준이고 Expo 지원은 커뮤니티 패키지(`expo-better-auth-passkey`, `@lobehub/expo-better-auth-passkey` 등)뿐이에요. 시험하려면 도메인(Associated Domains `webcredentials`)과 유료 Apple 개발자 계정이 필요해요. 출시 필수에서 빼고 출시 후 검토해요.

## 한계

- 실기기가 아니라 시뮬레이터예요. NSURLSession과 Keychain 동작은 같다고 보지만, 기기 잠금 상태의 Keychain 접근(`keychainAccessible`)은 확인하지 않았어요.
- #4는 수명을 초 단위로 줄였어요. 날짜 단위에서도 계산식이 같다는 가정이에요.
- 원격 MCP를 실제 Claude에 연결해 보지는 않았어요. 서버 쪽 OAuth 흐름(등록 → 동의 → 토큰 → `/mcp`)만 스크립트로 확인했어요. Claude 연결은 MCP 툴 설계 티켓에서 해요.
- 1.7.26은 나온 지 하루라 이번 PoC는 1.7.25로 했어요.
