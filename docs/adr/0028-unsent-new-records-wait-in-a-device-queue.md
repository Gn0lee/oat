# 보내지 못한 새 기록은 폰 대기열에서 자동으로 다시 보내고, 수정·삭제는 온라인에서만 한다

저장할 때 서버에 닿지 못한 **새 기록**은 폰의 대기열에 넣고, 연결되면 자동으로 다시 보낸다. 앱을 껐다 켜도 이어간다. 입력 화면은 바로 닫히고, 기록 탭에 "보내는 중 N건"과 그 기록이 "보내는 중" 표시로 보인다. 서버가 거절하면 "보내지 못한 기록"으로 옮겨 사용자가 고치거나 버린다. 기록을 수정·삭제하는 것은 온라인에서만 된다.

서버는 집의 미니 PC라 잠깐 멈출 수 있고, 지하 매장처럼 신호가 약한 곳에서 적는 일이 흔하다. 그때마다 "다시 시도"를 누르게 하거나 앱을 닫으면 입력이 사라지면 기록을 빠뜨린다. 쓰기마다 중복 방지 키를 붙이므로(ADR 0011, 서버 아키텍처 11번) 같은 새 기록을 여러 번 보내도 한 번만 생긴다. 수정·삭제는 version 낙관적 잠금이라 늦게 보내면 충돌이 나고, 그 충돌은 폰에서 풀 수 없다.

ADR 0011의 "오프라인 입력은 지원하지 않는다. 앱은 보내지 못한 초안만 기기에 남긴다"를 구체화한다. 잔액·통계 계산은 여전히 서버만 하고, 폰은 보내지 못한 새 기록 초안을 들고 있다가 자동으로 다시 보낼 뿐이다. 오프라인 우선 앱이 되는 것은 아니다.

## Considered Options

- **실패하면 확인 화면에 남기고 "다시 시도"**: 가장 단순하다. 하지만 앱을 닫으면 입력이 사라지고, 신호가 약한 곳에서 화면을 붙잡고 있어야 해서 택하지 않았다.
- **완전 오프라인(조회 캐시에서 계산, 수정·삭제도 대기열)**: 잔액·검증 로직이 앱과 서버에 두 벌 생기고(ADR 0011이 버린 두꺼운 클라이언트), 버전 충돌을 폰에서 풀어야 해서 택하지 않았다.

## Consequences

- 보내는 중인 기록은 홈 숫자·잔액에 들어가지 않는다. 그 사이 홈 맨 위 숫자 아래에 "보내는 중 N건 빠짐"을 붙인다.
- 중복 방지 키는 초안을 만들 때 정해 대기열에 함께 저장한다. 다시 보낼 때 같은 키를 쓴다.
- 대기열은 로그인한 사람별이다. 세션이 끝나면 다시 로그인한 뒤 그 사람의 대기열만 보내고, 로그아웃하면 대기열을 지울지 묻는다.
- 구현은 TanStack Query의 멈춘 쓰기 이어하기(`setMutationDefaults` + persist + `resumePausedMutations`)로 한다.
