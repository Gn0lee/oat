# 보내지 못한 새 기록은 폰 대기열에서 자동으로 다시 보내고, 수정·삭제는 온라인에서만 한다

저장할 때 서버에 닿지 못한 **새 기록**(`+`로 만든 지출·수입·이체)은 폰의 대기열에 넣고, 연결되면 자동으로 다시 보낸다. 앱을 껐다 켜도 이어가고 만료 시한은 없다. **새 기록의 id(UUIDv7)는 앱이 정해서 보내고**, 서버는 같은 가구·볼 수 있는 장부에 같은 id와 같은 본문이 있으면 그 기록을 돌려주고, 본문이 다르거나 다른 곳에 있으면 409, 이미 지운 id면 410으로 답한다(지운 기록이 되살아나지 않는다). 입력 화면은 바로 닫히고, 기록 탭에 "보내는 중 N건"과 그 기록이 "보내는 중" 표시로 보인다. 서버가 거절하면 "보내지 못한 기록"으로 옮겨 사용자가 고치거나 버린다. 기록을 수정·삭제하는 것은 온라인에서만 된다.

서버는 집의 미니 PC라 잠깐 멈출 수 있고, 지하 매장처럼 신호가 약한 곳에서 적는 일이 흔하다. 그때마다 "다시 시도"를 누르게 하거나 앱을 닫으면 입력이 사라지면 기록을 빠뜨린다. 쓰기마다 중복 방지 키를 붙이지만(ADR 0011, 서버 아키텍처 11번) 키는 7일만 보관한다. 응답을 잃은 기록을 8일 뒤에 다시 보내면 두 번 생긴다. 앱이 정한 id는 기록이 남아 있는 한 늘 중복을 막는다. 수정·삭제는 version 낙관적 잠금이라 늦게 보내면 충돌이 나고, 그 충돌은 폰에서 풀 수 없다.

ADR 0011의 "오프라인 입력은 지원하지 않는다. 앱은 보내지 못한 초안만 기기에 남긴다"를 구체화한다. 잔액·통계 계산은 여전히 서버만 하고, 폰은 보내지 못한 새 기록 초안을 들고 있다가 자동으로 다시 보낼 뿐이다. 오프라인 우선 앱이 되는 것은 아니다.

## Considered Options

- **실패하면 확인 화면에 남기고 "다시 시도"**: 가장 단순하다. 하지만 앱을 닫으면 입력이 사라지고, 신호가 약한 곳에서 화면을 붙잡고 있어야 해서 택하지 않았다.
- **완전 오프라인(조회 캐시에서 계산, 수정·삭제도 대기열)**: 잔액·검증 로직이 앱과 서버에 두 벌 생기고(ADR 0011이 버린 두꺼운 클라이언트), 버전 충돌을 폰에서 풀어야 해서 택하지 않았다.

## Consequences

- 보내는 중인 기록은 홈 숫자·잔액에 들어가지 않는다. 그 사이 홈 맨 위 숫자·자산 탭 잔액·청구서 위에 "아직 반영 안 된 기록 N건"을 붙인다.
- 기록 id와 중복 방지 키는 초안을 만들 때 정해 대기열에 함께 저장한다. 다시 보낼 때 같은 값을 쓴다. 대기 중인 기록은 고치지 못하고, 빼고 새 초안으로 적는다.
- 예정 확정·매매·돌려받은 돈은 서버 상태(같은 회차, 보유 수량, 한도)에 따라 거절될 수 있어 대기열에 넣지 않는다.
- 영구 거절은 우리 서버의 오류 응답(우리 `code`가 있음)일 때만 인정하고, 그 밖의 응답(Cloudflare의 403·404·5xx 등)과 표에 없는 응답은 다시 보낸다. 최소 앱 버전 미달은 멈춰 두었다가 업데이트 뒤 보낸다. 표는 [모바일 입력 UX 원칙](../design/mobile-input.md) 10.1.
- 대기열은 자동으로 지우지 않는다. 세션이 끝나도(401) 남기고, 계정 삭제 응답일 때만 지운다. 폰 저장소는 사용자 id + 가구 id로 묶는다.
- 앱 id는 `general` 기록에만 받는다. 기기 시계가 틀리면 같은 날 시각 없는 기록의 순서만 달라진다(알려진 한계).
- 대기열과 폰 캐시는 사용자 id + 가구 id로 묶고 iOS 데이터 보호를 쓴다. 다른 사람이 같은 폰에 로그인하면 보이지 않는다. 로그아웃할 때 대기열이 있으면 지워진다고 알리고 취소할 수 있게 한다.
- 대기열은 화면용 쿼리 캐시와 분리한 전용 저장소에 둔다. TanStack Query persist의 기본값(24시간·앱 버전이 바뀌면 버림)과 "멈춘 쓰기만 이어하기"는 서버가 멈춘 경우(502)와 오래 안 연 경우를 덮지 못한다.
- 물리 DB 스키마 2절 4번(ID는 UUIDv7, 서버가 만든다)에 `general` 새 기록 예외를 더한다.
