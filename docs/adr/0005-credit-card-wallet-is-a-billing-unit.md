# 신용카드 지갑은 카드 한 장이 아니라 청구 단위이고, 청구서는 다리 없는 창이다

한국 카드사는 같은 카드사의 카드 여러 장(본인 카드 여러 장, 가족카드)을 결제일 하나, 청구서 하나로 묶어 청구한다. 그래서 "갚을 돈"이라는 잔액은 카드 한 장이 아니라 이 청구 단위에 존재한다. 신용카드 **지갑**은 청구 단위(카드사 + 결제일)로 두고, 실물 카드는 그 지갑을 가리키는 **결제수단**으로 둔다. 체크카드가 통장을 가리키는 결제수단인 것과 같은 구조다. 혜택과 실적처럼 카드 한 장마다 다른 것은 결제수단에 붙인다.

**청구서**는 지갑 하나 × 결제일 하나에 갚을 돈을 보여주는 창이고, 다리를 갖지 않는다. 예상 청구액은 기록에서 계산하고, 확정 청구액은 사용자가 카드사 화면을 보고 입력한다. 확정 청구액과 예상 청구액의 차이(할부수수료·연회비·이자·해외 수수료·혜택 확정·다음 달로 넘어간 기록)는 확정할 때 기록으로 풀고, 남은 차이는 잔액 맞춤으로 남긴다. 그래야 지갑 잔액이 실제로 갚을 돈과 맞는다.

## Considered Options

- **카드 한 장 = 지갑, 청구서가 지갑 여러 개를 묶음**: 카드 화면은 직관적이다. 하지만 잔액(부채)이 카드별로 쪼개지고, 카드대금 한 번이 여러 지갑에 나눠 들어가야 해서 택하지 않았다.
- **청구서를 다리를 가진 기록으로 둠(청구 시 이용분을 청구서 지갑으로 옮김)**: 청구 시점마다 기록이 생겨서 이용 시점 지출 인식과 겹치고, 카드사 청구 로직을 앱이 흉내 내야 해서 택하지 않았다.

## Consequences

- 사용자는 늘 "카드"를 등록한다. 같은 카드사·결제일의 신용카드 지갑이 이미 있으면 함께 청구되는지 묻고, 예라면 결제수단만 추가한다.
- 배우자의 가족카드는 본인 명의 지갑을 가리키는 결제수단이고, 지갑의 "가구원 사용 허용"으로 배우자가 쓸 수 있다.
- 기록은 매입일(모르면 이용일)과 이용기간 규칙으로 청구서에 자동 배정한다. 카드사 청구 로직을 완전히 재현하지 않고, 기록별 "다음 청구서로 넘기기"로 보정한다.
