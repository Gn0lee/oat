# 화면 뼈대와 부품 목록을 닫는다

새 화면은 **뼈대 6종**(요약·목록·리포트/상세·퍼널 질문·확인·시트) 중 하나에 내용을 채우고, **닫힌 부품 목록**([화면 문법](../design/screen-grammar.md) 4절: 숫자 블록·섹션 제목·목록 줄·칸 줄·안내 줄·띠·카드·버튼·칩·스위치·입력칸·세그먼트·달 넘기기·여러 개 고르기 줄·끌기 손잡이·떠 있는 `+`·배지·실패 표시·토스트·상단 바·탭 바·시트·키패드·달력·차트, 그리고 iOS 순정 날짜 고르기 등)만 조립한다. 새 부품이 필요하면 화면에서 바로 만들지 않고 `DESIGN.md`의 `components`에 먼저 더한다. 화면마다 주인공(맨 위의 가장 큰 숫자나 질문)은 하나다.

같이 닫는 문법:
- 버튼은 주 버튼(화면당 하나, 아래 고정)·보조·알약·글자·위험(빨강 글자 + 확인 시트) 5단계.
- 칩은 누를 수 있고(둥근 알약 + 테두리), 배지는 표시만 한다(작은 네모). 배지는 중립·주의(주황 `warning`) 둘이고 실패는 배지가 아닌 빨강 글자 + ⚠ 표시다. 기한 지남에 빨강을 쓰지 않는다.
- 목록 줄은 왼쪽 이름·보조 줄, 오른쪽 금액·보조 값이고 아이콘 자리가 없다. 배지와 개인 장부 🔒은 보조 줄 맨 앞이다.
- 행동은 화면에 보이게 둔다. 밀어서 삭제를 쓰지 않고, 칸을 눌러 고치며, 나머지 행동은 맨 아래 섹션에 모은다. 못 하는 행동은 숨기고, 고칠 수 없는 칸은 이유를 늘 보인다.
- 선택은 색만으로 알리지 않는다: 글자 버튼에 `›`, 선택 칩에 ✓, 선택 탭은 채운 아이콘.

이 티켓은 화면 하나하나의 시안이 아니라 **통일성의 규칙**을 정하는 자리로 범위를 바꿨다. 화면별 세부는 구현에서 이 문법 안에서 정한다. 구현 티켓을 이 부품 단위로 나눌 수 있다.

## Considered Options

- **화면마다 최종 시안을 확정**: 여백·배치 같은 숫자는 DESIGN.md 한 곳만 고치면 바뀌고, 실기기에서 고르는 편이 정확하다. 비싸게 바뀌는 것은 규칙이라 규칙을 정했다.
- **열린 부품 목록**: 구현자마다 비슷한 부품을 새로 만들어 기존 oat처럼 화면마다 모양이 달라진다.
- **줄에 카테고리 아이콘**: 사용자가 카테고리를 만들어서 아이콘 세트를 관리하기 어렵고 금액 열이 좁아진다.
- **밀어서 삭제**: 빠르지만 모르는 사람은 못 찾고, 공용 기록을 실수로 지우기 쉽다.

## Consequences

- `DESIGN.md` 린터에 컴포넌트가 라이트 묶음만 가리켜서 생기는 "참조 안 됨" 경고가 남는다(형식에 모드별 컴포넌트가 없음).
- 간격·모서리·크기 값은 초안이고 구현 때 실기기로 조정한다. 규칙은 그대로다.
