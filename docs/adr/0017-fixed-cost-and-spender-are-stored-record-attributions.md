# 고정비와 쓴 사람은 저장할 때 기본값을 계산해 기록에 저장하고, 사용자가 기록마다 고친다

"고정비 비중"과 "누가 얼마 썼나"는 기록이 어디에 속하는지를 묻는다. 둘 다 다른 데이터에서 계산할 수 있지만, 계산 원천이 나중에 바뀌거나 틀릴 수 있다. 그래서 **기록에 저장하는 귀속**으로 둔다.

- **고정비**(`records.is_fixed`): 저장할 때 정한다. 정기 규칙이 만든 기록이면 켜고, 아니면 지출 줄 중 하나라도 "고정비 기본값" 카테고리면 켠다. 사용자가 기록마다 바꿀 수 있다. 정기 규칙을 지우거나 카테고리 기본값을 바꿔도 과거 기록의 표시는 그대로다.
- **쓴 사람**(`records.spender_member_id`): 보통은 비워 두고 계산한다. 계산은 나간 다리 중 가장 큰 다리의 결제수단 주인이다. 결제수단이 없고 지갑이 "가구원 사용 허용"이면 "함께", 그 밖에는 지갑 주인이다. 배우자가 내 실물 카드를 빌려 썼을 때처럼 계산이 틀리면 사용자가 기록에서 쓴 사람을 고르고, 그 값이 칸에 저장된다.

통계 제외가 기록 단위인 것과 같은 결이다(ADR 0007). 범위는 공용 장부뿐이라서 쓴 사람 통계는 두 가구원이 같은 숫자를 본다.

## Considered Options

- **고정비 = 정기 규칙이 만든 기록**: 칸이 필요 없다. 하지만 규칙 없이 직접 적는 월세가 빠지고, 지금 스키마는 규칙을 지우면 `recurring_rule_id`가 NULL이 되어 지난 달의 고정비가 줄어든다. 규칙을 보관만 하게 바꿔도 직접 적은 기록 문제는 남아서 택하지 않았다.
- **고정비 = 카테고리 표시**: 설정이 한 번이면 된다. 하지만 통신비 안의 휴대폰 구매처럼 한 번만 나간 돈도 고정비가 되고, 표시를 바꾸면 과거 통계 전체가 바뀌어서 택하지 않았다. 카테고리 표시는 기본값으로만 쓴다.
- **쓴 사람 = 입력한 사람**: 한 사람이 몰아서 적는 집에서는 한쪽으로 쏠리고, 기록에 작성자 칸이 따로 필요해서 택하지 않았다. 입력자는 감사 기록(`actor_member_id`)에 이미 있다.
- **쓴 사람 = 늘 지갑 주인**: 칸이 필요 없다. 하지만 공동 생활비 통장에서 계좌이체·자동이체로 나간 돈이 통장 명의자 한 명에게 쏠려서 택하지 않았다.

## Consequences

- `records.is_fixed`(NOT NULL), `records.spender_member_id`(NULL 허용), `categories.is_fixed_default`가 생긴다.
- 정기 규칙의 FK는 지금처럼 `ON DELETE SET NULL`로 둔다. 고정비가 규칙 연결에 기대지 않기 때문이다.
- 기존 데이터를 전환할 때 `is_fixed`는 모두 false다(기존에 정기 표시가 없고, 카테고리 기본값도 켜지 않기로 함). `spender_member_id`는 계산값이 특정 가구원이고 기존 작성자와 다를 때만 채운다. 계산값이 "함께"이면 채우지 않는다. 기존 작성자는 입력한 사람이라서다([기존 데이터 전환](../design/legacy-migration.md) 3절).
- "가구원 사용 허용"이 함께 쓰는 지갑의 표시를 겸한다. 두 뜻이 갈라지면 그때 칸을 나눈다.
- (2026-11-21 [모바일 입력 UX 원칙](../design/mobile-input.md) 8절) 내 카드로 둘이 먹을 장을 본 경우처럼 쓴 사람을 "함께"로 고칠 수 있게 `records.spender_shared`(boolean NOT NULL 기본 false)를 더한다. 켜지면 "함께", `spender_member_id`가 있으면 그 사람, 둘 다 비면 계산이고, 둘이 함께 차지 않게 CHECK를 건다. 고정비는 사용자가 고쳤는지 따로 남기지 않는다.
