# 인증은 셀프호스팅 Better Auth로 유지하고, AI 연결은 앱 세션과 따로 산다

인증 PoC를 하면서 로그인 수단을 초대제 기간 이메일만으로 줄였다. 카카오·네이버 내장 provider는 Better Auth를 고른 이유 중 하나였으니, 매니지드 Supabase Auth를 그대로 쓰는 쪽을 다시 비교했다. 결론은 **Better Auth 유지**다. 이 서비스는 원격 MCP가 핵심 기능이라서, MCP 인가 서버를 우리 서버 안에서 현행 MCP 스펙(2026-07-28, CIMD 권장)대로 낼 수 있어야 한다. 또 세션이 우리 Postgres에 있어서 로그아웃·가구 탈퇴가 바로 반영된다. Supabase Auth의 OAuth 2.1 서버는 2025-11 공개 베타이고 DCR만 지원한다. 앱 토큰과 MCP 토큰이 같은 모양의 JWT라 교차 거부를 직접 짜야 하고, 액세스 JWT는 로그아웃 뒤에도 만료까지 통한다. 세션 수명 설정(우리가 정한 60일 비활동 만료)도 유료 플랜부터다.

**AI 연결(MCP로 AI 클라이언트에 허락한 접근)은 앱 세션과 따로 산다.** 앱에서 로그아웃해도 AI 연결은 끊기지 않는다. 연결 해지, 가구 탈퇴, 계정 삭제 때만 끊는다. PoC에서 MCP 액세스 토큰은 갱신 토큰을 회수한 뒤에도 만료(1시간)까지 서명 검증을 통과했다. 그래서 `/mcp`는 요청마다 DB에서 동의와 가구원 여부를 확인한다. 휴대폰에서 로그아웃한 것을 "Claude도 끊어 줘"로 기대하는 사람이 있을 수 있어서, 이 동작은 이유를 남긴다. GitHub에서 로그아웃해도 연결된 앱이 끊기지 않는 것과 같고, 기기 하나를 정리하려고 AI 연결까지 다시 맺게 하는 비용이 더 크다고 봤다.

## Considered Options

- **Supabase Auth(매니지드)**: 보안 패치를 맡길 수 있고 기존 사용자 2명이 이미 있으며, Bearer JWT라 네이티브 이전에 깔끔하다. 위 MCP·즉시 폐기·플랜 문제로 택하지 않았다.
- **Clerk**: 인증 서비스 비교의 2순위다. 네이티브 세션 수명을 따로 정할 수 있게 됐지만(2026-11), 사용자 데이터가 밖에 있고 가구 수에 따라 비용 구조가 바뀐다. 다시 고르지 않았다.
- **앱 로그아웃 때 AI 연결도 끊기**: 직관적일 수 있다. 하지만 기기 단위 동작과 계정 단위 허락이 섞이고, 여러 기기를 쓰면 한 기기의 로그아웃이 모든 AI 연결을 끊게 된다.
- **MCP 액세스 토큰 수명만 짧게(예: 5분)**: DB 확인 없이 회수 지연을 줄인다. 하지만 지연이 0이 되지 않고, 가구 탈퇴는 어차피 요청마다 멤버십을 보므로 같은 조회에 붙이는 편이 싸다.

## Consequences

- 보안 패치와 업그레이드를 직접 따라간다. `better-auth`와 간접 의존(`@better-auth/oauth-provider`, `@better-auth/core`)까지 정확한 버전으로 고정하고 overrides로 묶는다.
- 앱은 포그라운드마다 세션 확인을 부르고, 새 설치면 Keychain 세션을 지운다([인증](../design/auth.md) 2절).
- AI 연결 목록·해지 화면이 앱에 필요하다(MCP 툴 설계, ADR 0023).
- 이 결정은 서버 아키텍처의 인증 결정(13~17번)을 바꾸지 않고 구체화한다.
